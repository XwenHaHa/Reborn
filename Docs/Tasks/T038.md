## 1. 目标与明确不做

**目标**：把 T037 的同步单次写入升级为**主线程帧驱动的单写入队列**：
普通保存节流合并、关键事务不被插队/覆盖、退出与死亡绕过等待但仍串行；
写入失败可注入且不半写、不双坏、不锁死队列；队列状态可观测。

**明确不做**：
- 不改存档格式、`save_version`、`WorldSnapshot` 键集合与 `pending_settlement_life_id` 语义（T037 口径）。
- 不改 `LifeCycle` 状态机；不改死亡/发现/解锁的既有业务时机。
- 不做多槽、云存档、手动存档 UI、跨进程锁、异步线程。
- 不做按区域账本实例化 NPC（T040）、`last_safe_spot_id`（T042）。
- 不改 T037 挂账项：自然死亡不扣账、T034 昼夜 0.5、T029 两决策。
- 不新增场景/美术；玩家可见反馈只复用 HUD Toast。

## 2. 审计范围与验收判据

| 范围 | 判据 |
|---|---|
| 队列 | 所有生产保存请求经 `request_save()` 入队；同一时刻只有一次写入；重复/并发请求可合并 |
| 关键事务 | 死亡归档、`pending` 清空、发现、解锁、退出不可被合并/丢弃/插队 |
| 节流 | 普通保存默认 1 s；窗口内请求合并为一次写；死亡/退出绕过等待 |
| 串行 | 绕过等待与串行同时成立：`active_writes` 从不超过 1，写入日志 start/end 不交错 |
| 失败注入 | 磁盘写失败 / rename 失败 / `.bak` 复制失败 / 失败后继续：文件状态与玩家文案逐条断言 |
| 可观测 | `queue_length()`、`pending_reasons()`、`stats`、`last_failure_reason`、`last_warning` |
| 兼容 | T030～T037 全绿；T037 的 69 条**不改断言**仍通过 |

## 3. 决策

- **D1（无线程、帧驱动）**：写入是主线程同步文件 I/O（快照 < 数百 KB），数据真源都在主线程节点上；
  引入线程需深拷贝快照并加锁，收益为零且会破坏 `GameState`/`WorldDirector` 的同步语义。
  队列由 `SaveManager._process(delta)` 驱动；仅在有普通请求时开启 `set_process`。
- **D2（请求分类）**：
  - **关键（critical）**：`death`、`settle_shown`、`discovery`、`unlock`、`exit`。**逐条写、绝不合并/丢弃**；
    请求即同步排空（单条串行），可吸收尚未落盘的普通请求（普通请求视为被丢弃，计入 `dropped_normal`）。
  - **普通（normal）**：帧驱动、节流、合并；窗口内多个请求只保留一个待写槽（原因取最后一次并追加日志）。
  - **直接（manual）**：`save_game()` 保留为同步底层 API（测试/工具用），内部同样走 `_perform_write` 串行守卫。
- **D3（合并与 revision）**：同一帧 N 次普通请求 → 1 次实际写、`revision` 仅 +1；
  `revision` 只在**成功写**后递增；失败不占号。合并次数计入 `stats.coalesced`。
- **D4（节流）**：`throttle_seconds` 默认 **1.0**（写进 Parameters）。普通写成功后 1 s 内不再写普通档；
  窗口内请求合并。**关键事务（死亡/退出等）无视窗口立即排空**；`bypass_throttle` 参数对关键请求为默认 true。
- **D5（仍串行）**：`_perform_write` 用 `_writing` 守卫；请求若在写入中到达（理论上仅同线程重入）立即入队，
  当前写结束后再处理。统计 `active_writes` / `max_active_writes`；正常恒为 0/1。
- **D6（原子写加固）**：
  1. 写 `.tmp`（flush/close）；失败 → 删 tmp，主档与 `.bak` 不动。
  2. 主档存在时：复制主档 → `.bak.tmp`；成功则把旧 `.bak` 改名为 `.bak.prev`、`.bak.tmp` 改名为 `.bak`、
     删除 `.bak.prev`。**复制失败不阻断本次写**：旧 `.bak` 原样保留，主档仍更新，返回 `ok` + warning
     「存档已保存（备份更新失败）」。
  3. 主档存在时先改名为 `.old`；`.tmp` 改名为主档。最终改名失败 → **回滚 `.old` 为主档**、删 tmp、
     返回 `write_failed`。成功后再删 `.old`。**主档在任何失败路径都不被截断/删除且可解析**。
  4. 极端窗口（进程在主档改名后、tmp 改名完成前被杀）：主档缺失、`.bak` 仍在 → 读档回退 `.bak`
     （`recovered_backup`，文案「主存档缺失，已从备份恢复」）。
- **D7（失败注入）**：`fault_injection` 仅测试设置（生产恒空）：`tmp_open` / `disk_write` / `bak_copy` / `rename`。
  每个注入点对应一条断言；清除后队列必须继续可用（不重试同一失败，符合 T037 §7）。
- **D8（玩家可见）**：写失败 Toast「存档写入失败」；备份失败 warning Toast「存档已保存（备份更新失败）」；
  读档回退沿用 T037 文案。`last_failure_reason` / `last_failure_message` 记录最近一次失败详情供取证。
- **D9（队列观测）**：`queue_length()`、`pending_reasons()`、`queue_stats()`（含 `queued/coalesced/dropped_normal/
  written/failed/warnings/critical_written/active_writes/max_active_writes/last_failure_reason/threaded=false`）。
- **D10（兼容）**：`MainEntry.save_now()` 语义保持「立即、串行」——内部 `request_save(critical=true)` + 同步排空，
  因此 T037 的死亡两次写、发现/解锁一次写、退出写全部不改变时序；普通队列路径由 SaveManager API 驱动。

## 6. 用例（A～G）

| 段 | 断言 |
|---|---|
| A 队列基础 | 默认 `throttle_seconds=1.0`；同帧 2 次普通请求 → 1 次写、revision +1、`coalesced=1`；写后 `queue_length=0` |
| B 节流 | 普通写后窗口内再请求不写（revision 不变）；窗口到期只写 1 次；`bypass_throttle` 的关键写立即 +1 |
| C 关键事务 | 普通 pending + 关键死亡 → 只写关键、`dropped_normal` +1；关键后再来普通 → 普通排在关键之后；多条关键各自写 |
| D 串行 | `max_active_writes<=1`、写入日志 start/end 交替、`threaded=false` |
| E 失败注入 | `disk_write`/`rename`/`bak_copy` 三路：状态、主档/`.bak`/残文件、玩家文案；失败后清故障再写成功；任一失败后至少一个可解析档 |
| F 读档回退 | 主档删除 + `.bak` 有效 → `recovered_backup` 文案「主存档缺失，已从备份恢复」 |
| G T037 兼容 | 死亡两次写、发现/解锁各一次、退出写、非正式运行 `disabled`（T037 69 条不改仍绿） |

变异表（≥4）：M1 去掉普通请求合并 → A 段红；M2 关键请求不吸收普通 pending → C 段红；
M3 `.bak` 复制失败按致命失败处理（删除旧 `.bak`）→ E 段红；M4 rename 失败不回滚主档 → E 段红；
M5 忽略节流窗口 → B 段红。

## 7. 失败恢复

- 单次写失败：不重试；保留旧主档与 `.bak`，队列状态复位，后续请求继续（`failed` 计数 +1）。
- `.bak` 复制失败：主档写入照常完成，旧备份保留；warning Toast；下一次成功写再刷新 `.bak`。
- 主档缺失（改名窗口崩溃）：读档回退 `.bak`；无有效备份才报 `corrupt`。
- 队列死锁防护：任何路径都在 `_perform_write` 包装层复位 `_writing/active_writes`；统计可查。
