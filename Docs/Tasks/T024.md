# T024 追击、搜索和放弃 —— 任务规格

> 计划出处：`轮生_Reborn_开发计划_v1.0.md` 第 151 行「T024 追击、搜索和放弃 | 4～8h | 前置 T023 |

> 日期口径：2026-10-21（顺序递增虚构日期）。状态：**done（2026-10-21）** —— 断言 134/134 ×3、包内 133/133、全量回归 22 套 2478 条全绿、两张截图已判读；见 `Docs/Evidence/T024.md`。

## 0. 一句话目标

让猫 NPC 在**看不见猎物之后**：先**追到最后已知位置**（`CHASE`），再**搜**（`SEARCH `，`last_known_position` 快照，**不读实时坐标**），
在鼠洞外**最多等 6 s**，**搜索 5 s 超时即放弃**回 `EXPLORE` —— 全部只扩 `CatAI` 的状态机与计时，
**不改感知、不改导航基类语义、不做攻击**（攻击属 T025）。

## 1. 范围

### 做
1. `scripts/ai/cat_ai.gd` 新增 **`CHASE`** 与 **`SEARCH`** 两个状态（枚举本来就有，T019 定契约时预留）：
   - `CHASE`：目标**在攻击距离外持续移动/被追离**或**搜索中重新发现**时的持续追击（按 `chase_repath_interval` 节流重设目的地）；
     到攻击距离 → `in_range` 停住（**不扑击**，与 T023 同口径）。
   - `SEARCH`：失视后在 `search_timeout`（**5 s**）内去 `last_known_position`；到了就停着找；超时 → `EXPLORE` + 记一次放弃。
   - **洞口等待**：若最后已知位置落在鼠洞（组 `hide_spots` 的 `kind=mouse_hole` 标记）`hole_search_radius` 内 → 走去洞口、
     在洞外**最多等 `hole_wait_max`（6 s）**，然后放弃。**不进入洞口、不贴进洞里**。
2. **醒来重发**：T023 里"失视 → `EXPLORE`"按本任务升级为"失视 → `SEARCH`"（T023 规格与实现里已写明"T024 会改成 SEARCH"）。
3. **一场 CHASE 的逃脱账本**（`TechnicalDesign` §6 末）：`encounter_id` 唯一、一场 CHASE 只结算一次、
   **只有猎物存活才算逃脱**（`escape_count` 落到 `LifeRecord` 属 P4，本任务只做 AI 侧账本 + 信号）。
4. 可查看：`CatAI` 新查询（`search_elapsed` / `search_target` / `hole_wait_elapsed` / `search_count` / `give_up_count` /
   `chase_count` / `escape_report_count` / `encounter_id`）+ `ai_report()` 新字段；调试入口 HUD `ai:` 加 `search=`，`MOV|` 加 `search=`/`giveups=`/`chase=`。
5. 断言套件 `tests/run_t024_chase_search.gd`（A～H，目标 ≥ 90 条）。

- **鼠的藏身与掩体规则细节**（草丛只降可见性、鼠洞阻止猫进入的几何/导航验证）→ **T026**（本任务假设"洞口不可达"由 T012 的猫层导航保证）。
- `LifeRecord` 落盘/统计 → P4（T030+）；本任务只保证"账本语义与去重"可断言。
- 真实玩家输入、外部试玩 → 仍 NOT-RUN。

## 4. 状态机（本任务新增/改变的部分）

| From | To | 触发 | reason |
| --- | --- | --- | --- |
| `ALERT` | `SEARCH` | 警戒到期、**看不见**、且之前看得见 | `lost_sight`（**T023 时是 `EXPLORE`，本任务按 §6 升级**） |
| `ALERT` | `APPROACH` | 警戒到期、仍看得见 | `alert_done`（T023 行为不变） |
| `APPROACH` | `CHASE` | 猎物**跑到攻击距离外**（> `attack_range + 0.05`） | `chasing` |
| `SEARCH` | `CHASE` | **重新发现**猎物 | `reacquired` |
| `CHASE` | `CHASE` | 按 `chase_repath_interval` 节流重设目的地；到攻击距离 → 停住 | `chasing` / `in_range` |
| `CHASE` | `SEARCH` | 失视（先 `ALERT` 0.4 s） | `lost_sight` |
| `SEARCH` | `SEARCH` | 走到 `search_target` → 停住等；或走去洞口 → 洞外等 | `moving_to_last_seen` / `arrived` / `hole_wait` |
| `SEARCH` | `EXPLORE` | 搜索满 `search_timeout`(5 s) | `search_timeout`（`give_up_count` +1） |
| `SEARCH` | `EXPLORE` | 洞口等待满 `hole_wait_max`(6 s) | `hole_timeout`（`give_up_count` +1） |
| 任意 | `EXPLORE` | 路径失败累计 → 基类 `WAIT` → 到期 | `wait_done`（沿用 T019 口径） |

逃脱账本：进入一场 `CHASE` 时生成 `encounter_id`（`enc-<n>`）；**离开 CHASE 且猎物仍存活**时结算一次
（`escape_report_count` +1、发 `chase_ended(id, true)`、`encounter_id` 清空）；同一 id **只结算一次**（重复结束不再 +1）；
猎物已死则发 `chase_ended(id, false)` 且**不计逃脱**。

### 硬约束（断言守着）
- **隐藏后不得读取玩家真实坐标导航**：`search_target` 是失视时刻的快照，搜索/等待期间**永不更新**；
  猎物瞬移到别处时，目的地与该点的距离必须 > 0.5 m。
- **不进入洞口**：洞口等待期间 `move_intent` 为零、水平位移 ≈ 0，且与洞口中心的距离 ≥ 洞口半径。
- **不永久卡**：搜索 5 s / 洞口等待 6 s 都有上限；超时回 `EXPLORE`，世界时间继续前进。
- 不写物种名分支；不改 `Perception`；不改 `AnimalAI` 的既有语义（除 T023 已记录的锚点/兜底）。

## 5. 行为决策

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | `CHASE` 与 `APPROACH` 的区别：`APPROACH` = 警戒后**首次**接近；`CHASE` = **猎物跑开后的持续追击**或**搜索中重新发现** | §6 状态链 `APPROACH → CHASE`；两者都"到攻击距离停住"，区别只在触发与重设节流 |
| D2 | 失视 → `SEARCH`（不再直接 `EXPLORE`） | §6 第 226/230 行；T023 规格已预留"T024 会改成 SEARCH" |
| D3 | 搜索目标 = `last_seen_position()` 快照，**只在看见时更新** | §6"隐藏后不得读取玩家真实坐标导航" |
| D4 | `search_timeout` 5 s / `hole_wait_max` 6 s 取 `Parameters` 第 69 行；两个上限**都从进入搜索时开始计时** | 真源 + A03 的"搜索 5 s / 洞口等待 6 s 后放弃" |
| D5 | 洞口判定用**组 `hide_spots` 的 `kind=mouse_hole` 标记**（T020 约定），半径 `hole_search_radius` | 复用既有标记，不新造数据 |
| D6 | 逃脱账本放 AI 侧（信号 + 计数），**不落 `LifeRecord`** | `LifeRecord` 属 P4；本任务只保证语义与去重可断言 |
| D7 | 到攻击距离仍**只停住不攻击** | 攻击属 T025 |
| D8 | 3 个新实现默认值（`chase_repath_interval` 0.25 / `search_arrive_radius` 0.6 / `hole_search_radius` 0.6）放 `CatAI` 的 `@export` | 与 T019/T020/T023 同做法；`Parameters.md` 无对应行 |
| D9 | 测试夹具自建（导航面 / 鼠洞标记 / 身体） | T019～T023 同模型；真实生态属 T027 |
| D10 | **两个上限分开计时**：普通搜索从**进入 `SEARCH`** 起 `search_timeout`(5 s)；洞口场景从**到达洞口**起 `hole_wait_max`(6 s)，另加 `search_overall_max`(12 s，实现默认值) 兜底总长 | 真源给了 5 s / 6 s 两个数；若都从进入搜索计时，几米的赶路就会吃掉等待预算，A03 的"洞口等待 6 s"永远到不了 |

## 6. 验收断言（`tests/run_t024_chase_search.gd`，目标 ≥ 90 项）

### A 接口与参数（≥ 12）
- A1 `search_timeout == 5.0`、`hole_wait_max == 6.0`（`Parameters` 第 69 行）；3 个实现默认值 > 0
- A2 `CatAI` 有 `CHASE`/`SEARCH` 两个状态可用（`state_id()` 能取到）；新查询函数齐备
- A3 `ai_report()` 含 7 个新字段；`chase_started`/`chase_ended` 两个信号在
- A4 **无物种名字面量**（`cat_ai.gd` 源码静态检查；包内标 `STATIC|NOT-APPLICABLE`）

### B 追击（≥ 14）
- B1 8 m 看见 → 先进 `ALERT`（reason `saw_prey`）→ 到期后 `APPROACH`
- B2 猎物从 0.6 m 跑到 3 m（仍可见）→ 进 **`CHASE`**（reason `chasing`）
- B3 `CHASE` 期间距离**收敛回 ≤ 0.65 m**（继续追）
- B4 `CHASE` 期间按 `chase_repath_interval` 节流：1 s 内 `destination_sets` 增量 ≤ 6
- B5 `CHASE` 期间路径点数 ≥ 1（走导航，不是直线瞬移）
- B6 连续换位 3 次（每次 2 m）都能再次收敛
- B7 `CHASE` 到攻击距离 → `reason == in_range` 且停住（1 s 位移 ≤ 0.15 m）
- B8 全程 `pounce_count == 0`、猎物 health 不变（攻击属 T025）

### C 失视 → 搜索（≥ 16）
- C1 遮挡使失视 → `ALERT`(reason `lost_sight`) → 0.4 s 后进 **`SEARCH`**
- C2 `SEARCH` reason `moving_to_last_seen`，目的地 = 失视快照（≤ 0.10 m）
- C3 `search_target()` 与 `perception.last_seen_position()` 一致且**恒定**
- C4 把猎物搬到 3 m 外（仍不可见）→ `search_target` **不变**、目的地**不指新位置**（> 0.5 m）
- C5 走到快照点附近（≤ `search_arrive_radius`）→ reason `arrived`、停住（1 s 位移 ≤ 0.15 m）
- C6 搜索期间 `is_searching()` 为真、`search_elapsed()` 单调增长
- C7 搜索期间再次看见猎物 → 立即进 `CHASE`（reason `reacquired`）

### D 搜索超时放弃（≥ 12）
- D1 搜索满 5 s（±0.6 s）→ 回 `EXPLORE`、reason `search_timeout`
- D2 `give_up_count` +1；`is_searching()` 变假
- D3 超时期间世界时间前进（不冻结）、帧推进正常
- D4 第二次失视 → 重新搜索（`search_count` +1）、**重新计时**（第二次也能撑到 ~5 s）
- D5 放弃后**不立刻重搜同一位置**（回 `EXPLORE` 后不会马上又进 `SEARCH`）
- D6 放弃不改变世界账本（`capture_count`/`capture_food_count` 不变）

### E 洞口等待（≥ 14）
- E1 最后已知位置落在鼠洞标记 0.6 m 内 → `SEARCH` 的目的地是**洞口**（≤ 0.15 m）、reason `hole_wait` 或先 `moving_to_last_seen`
- E2 `hole_target_id()` = 该标记 id；到达后 `hole_wait_elapsed()` 开始增长
- E3 洞口等待期间 `move_intent` 为零、水平位移 ≈ 0（1 s ≤ 0.15 m）
- E4 **不进入洞口**：与洞口中心距离 ≥ 标记半径（0.30 m）
- E5 等待满 6 s（±0.7 s）→ 回 `EXPLORE`、reason `hole_timeout`、`give_up_count` +1
- E6 等待期间猎物重新出现 → 进 `CHASE`（不等满 6 s）
- E7 没有鼠洞标记时走普通搜索（reason 不是 `hole_wait`）

### F 不读隐藏玩家实时坐标（≥ 8）
- F1 搜索期间把猎物瞬移 +3 m → 目的地不动、`last_seen` 不动
- F2 洞口等待期间把猎物瞬移 −4 m → 同样不动（0.0000 m）
- F3 上述两次瞬移后，目的地与猎物**实时**位置距离 > 0.5 m
- F4 搜索期间猫的水平位移只来自"去快照/去洞口"，不与猎物实时位置相关（位移方向夹角 < 60° 朝向快照点）

### G 一场 CHASE 只结算一次（≥ 8）
- G1 进 `CHASE` → `encounter_id()` 非空、`chase_count` +1、`chase_started` 信号 1 次
- G2 猎物存活下结束（失视 → 搜索）→ `escape_report_count` +1、`chase_ended(id, true)` 一次
- G3 同一 encounter **重复结束不再 +1**（幂等）
- G4 猎物已死（health ≤ 0）结束 → `chase_ended(id, false)` 且 `escape_report_count` **不变**
- G5 新一场 CHASE → 新 `encounter_id`（与上一场不同）

### H 集成与可查看（≥ 10）
- H1 真实关卡 `l_courtyard.tscn` + 猫 NPC + 鼠 NPC：猫发现 → 追击（水平位移 > 1.5 m）
- H2 鼠进洞（把最后已知位置放到关卡 `HideSpot_RootHole`）→ 猫搜索 → 洞口等待 → 超时放弃（有界）
- H3 HUD `ai:` 行含 `search=`；`MOV|` 含 `search=` / `giveups=` / `chase=`
- H4 `l_courtyard.tscn` / `main.tscn` 内无 `/debug/` 脚本节点
- H5 全程无脚本错误（套件汇总 + 退出码；日志报错行由 Evidence 的 `Select-String` 扫描核对）

## 9. 开放项（不阻塞 T024）
1. **5 个实现默认值**（`chase_repath_interval` 0.25 / `search_arrive_radius` 0.6 / `hole_search_radius` 0.6 / `search_overall_max` 12.0 / `chase_trigger_move` 0.5）**待负责人并入正式起测值**。

   而是留在 `APPROACH` 继续重设目的地 —— 行为等价（两者都是"追到 0.65 m 停住"），只有 `state`/`reason` 不同；更细的追击链（体力、扑击时机）属 T025。
3. `escape_count` 落到 `LifeRecord` 与 `encounter_id` 的持久化 → P4（T030+）。
4. 猫是否会在洞口等待期间**改去别的洞口**（多洞优先级）→ T026/T027；"洞口真的不可达"的几何/导航验证 → T026。
5. 攻击（预警 0.45 s / 伤害 35 / 恢复 1.2 s）→ T025。
6. **实测结果见 `Docs/Evidence/T024.md`**（134/134 ×3 + 包内 133/133 + 全量回归 22 套 2478 条 + 两帧视觉判读）。
