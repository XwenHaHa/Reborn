## 1. 目标与明确不做

**目标**：把 T036 审计过的长期/当前状态组装成 `WorldSnapshot` 落盘，覆盖**写入 → 校验 → 损坏恢复 → 读档重建**全链；
所有路径有可执行断言，玩家可见的失败有明确文案。

**明确不做**：
- 不做云存档、多存档槽、手动存档 UI（单槽自动存档；UI 只复用既有 HUD Toast）。
- 不建 `last_safe_spot_id`（T042）；v1 格式**预留键**，缺省不写、读到空值忽略。
- 不改 `LifeCycle` 的既有状态语义；只新增**读档专用**入口（D4）。
- 不改死亡不扣账怪癖、T034 昼夜 0.5、T029 两决策（挂账）。
- 不做"按区域账本实例化 NPC"（T040）；读档只恢复账本与玩家，生态仍按 `EcologySpawner` 既有规则铺。
- 不把事件流改成外部文件（仍随快照整体落盘）。
- 不引入新资源/场景/美术；Toast 文案复用 `PlayerHud.show_toast()`。

## 3. 决策

- **D1（职责分层）**：新增 autoload `SaveManager` 只做**快照组装/序列化/校验/原子写**；场景重建（玩家、生态、菜单）在 `MainEntry`。
  `SaveManager` 不引用关卡节点，便于无头测试。
- **D2（路径与格式）**：`user://savegame_v1.json`（主档）、`user://savegame_v1.bak`（上一版）、
  `user://savegame_v1.corrupt-<n>`（隔离的坏档）。JSON 文本；**不含个人路径、令牌、设备名**。
- **D3（快照结构）**：TD §3 的 10 键 + 实现扩展 3 键：
  `events`（事件流，档案区间引用的真源）、`life_counter` / `event_seq`（保证读档后 `LifeId`/`seq` 继续单调）。
  其余扩展键 `saved_reason` 只写不读（诊断），不计入契约。
  `transform` / `start_position` 用可逆纯数据编码：`{"$t":[12 浮点]}` / `{"$v":[x,y,z]}`；`StringName` 写为 String。
- **D4（待结算语义）**：`pending_settlement_life_id` = **"死亡已归档、结算页尚未展示"**。
  - 死结算：先写 `pending=<life_id>` → 呈现结算页 → 写 `pending=""`（两次原子写，见 D6）。
  - 读档：该字段非空且 `life_records` 中能按 ID 找到记录 → 走**既有** `SETTLING → SELECTING`（`request_select()`），
    再 `_present_settle(record)`；呈现后清空并落盘。**不改状态机语义**。
  - 复活当前生命：只新增 `LifeCycle.restore_alive()`（读档专用，只接受 `SETTLING/SELECTING → ALIVE`），
    不经 `spawn_requested`，不新分配 `LifeId`。
- **D5（版本策略）**：`save_version=1`。缺失/非整数 → 按坏档；`>1` 或未知整数 → `version_mismatch`，
  **不隔离、不覆盖**，玩家见"存档版本不兼容（vX），未载入"。只有 v1 有读取器，无迁移。
- **D6（原子写）**：写 `savegame_v1.json.tmp` → `flush/close` → 现存主档先复制为 `.bak` →
  `DirAccess.rename_absolute(tmp, 主档)`（Godot 在 Windows 走覆盖替换）。任一步失败：删除 tmp、保留旧档、
  返回 `write_failed`（玩家见"存档写入失败"）。重复保存 = 内容相同（除 `revision`/`saved_reason`），断言按规范化比较。
- **D7（校验与修复口径）**：
  - **结构错误**（非字典、缺 `save_version`、JSON 解析失败/截断）→ `corrupt`：主档改名隔离；若有可读 `.bak` → 从备份恢复（`recovered_backup`）。
  - **字段缺失**（集合类 `resources/regions/discovered_ids/unlocked_species/life_records/events`）→ 补默认值并记 `repairs`。
  - **值非法**：负/超容量 → 夹紧（region `total∈[0,capacity]`、resource `units∈[0,capacity]`、生存指标 `[0,100]`）；非有限浮点/缺稳定 ID/类型不符的**条目**跳过并记 `repairs`；当前生命 `health<=0` 视为非法 → 拒绝该当前生命（归档替补）。
  - 玩家文案：有修复 → "存档已修复 N 处后载入"；坏档无备份 → "存档损坏，已隔离；未载入"（继续新游戏，**不静默**）。
- **D8（重建顺序）**：校验 → 世界时间 → 区域账本 → 资源点（按稳定 ID 应用/补建）→ 长期层（发现/解锁/档案/事件/计数器/当前生命）
  → 生命（存活：直接恢复；待结算：补弹页）→ Toast/状态刷新。顺序固定并有断言。
- **D9（自动存盘时机）**：死亡结算（2 次写）、地点发现（1 次）、物种解锁（1 次）、退出（`_exit_tree`，1 次）、读档补弹完成（1 次）。
  **仅正式运行**（`get_tree().current_scene == self` 且 `persistence_enabled`）启用；测试/取证工具手动开启。
- **D10（测试隔离）**：测试路径 `user://t037_tests/savegame_v1.json`，结束时整目录删除；不触碰真实 `user://savegame_v1.json`。

## 6. 用例（A～G）

| 段 | 断言 |
|---|---|
| A 格式 | 快照 13 键；`save_version=1`；`revision` 单调；transform/Vector 编码可逆；无个人路径/令牌 |
| B 写入 | 无 `.tmp` 残留；`.bak` 是上一版；重复保存规范化后相同；只读目录 → `write_failed` 且旧档完好 |
| C 校验 | 版本 2→`version_mismatch` 且文件不动；缺集合→修复计数；负数/超容量→夹紧；NaN→跳条目；截断→`corrupt`+隔离；主档坏+备份好→`recovered_backup`；文案逐条 |
| D 重建 | 世界时间、区域账本、资源点（应用与补建）、发现/解锁、档案/事件/计数器、当前生命 transform+四指标、待结算补弹 |
| E 读档生命 | 存活读档：`LifeId` 保持、`event_seq` 连续、HUD 绑定、时间恢复推进；死亡后读档：归档不变、`pending` 空则进入选物种 |
| F 幂等 | 连续两次 `save_game` 不改变逻辑快照；读档后再存档 = 同一规范化内容 |
| G 时机 | 死亡两次写（pending 有→无）；发现写含 `discovered_ids`；解锁写含 `unlocked_species`；`_exit_tree` 写；非正式运行不自动写 |

变异表（至少 3 处）：M1 版本比较去掉 → C 段红；M2 `restore_long_term` 不写 `_life_counter` → E 段红；
M3 原子写不复制 `.bak` → B 段红；M4 死亡不写 pending → G 段红。

## 7. 失败恢复

- 写失败：保留旧主档 + `.bak`，本次返回失败；下一次触发再试（同一失败不重试超过两次）。
- 读失败：坏档隔离（不删除）、有备份则回退；无备份则新游戏 + Toast，日志 `ENTRY|save|corrupt`。
- 读档中途重建异常（配置缺物种/关卡缺节点）：停止应用、保留原文档、转新游戏并 Toast；不得半应用（先校验后应用）。
