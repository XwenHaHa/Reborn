处理链路（每步都有原因，见脚本注释）：
1. 保住 `matrix_world` 再烘（glTF 网格是 Y-up，直接 apply 子级会烘错轴；围栏已踩过）。
2. 用"最高 25% 高度顶点"的 XY 质心估树干轴 → 半径 0.55 m 之外的**面全部删掉**（扫描地面 + 外围）：
   39,122 → 24,239。
3. 删掉细小的独立连通块（528 个壳 → 只留主体）：24,239 → 23,160。
4. 焊接（15,562 → 12,120 顶点）后单轮 Collapse 减面：23,160 → **13,999**。
5. 归一到**高 0.85 m**、原点 = 脚印中心 + 底面 z=0（0.8232 × 0.8220 × 0.8500）。
6. **布尔差集破洞**：0.24（X）× 0.30（Z）× 1.20（Y 贯通）→ 12,555 tris。
7. 清掉布尔带进来的空材质槽（否则切出来的面渲染成纯白）。
8. 自检 9 个点的**射线贯通**：`clearance|points=9|blocked=0`。

## 4. 接入（改生成器，不手改 .tscn）

- 新增 `ROOT_HOLE_ASSET` / `ROOT_HOLE_SIZE` 与 `_mk_root_hole_visual()`（glb 实例，**零碰撞**、**不进** `nav_source_courtyard`）。
- **南北各放一桩**：`RootHoleStumpS` 内端面贴 `z = BARRIER_Z_MIN`、`RootHoleStumpN` 内端面贴 `BARRIER_Z_MAX`，
  两桩的 0.24×0.30 贯通孔与玩法孔**首尾相接**（共 2 × 12,555 ≈ 25,110 tris）。
- 位置、旋转（必须 0°）、缩放(必须 1×) 全部被断言锁死——加旋转/缩放会让资产里的孔径与玩法孔不一致。
- `_verify()` 新增 **16 条**断言（每桩 8 条：存在/是资产/无碰撞/不在导航组/贴地/X 对齐/贴屏障/未旋转未缩放）。

## 5. 实测踩到的两个真缺陷（已修）

1. **整桩被灰盒吃掉**：第一版把桩子放在 `z = 19`（屏障正中）。屏障深 1.0 m、桩深 0.778 m → 桩子整个埋在
   灰盒里面，实机只露出顶部 0.35 m（`Art/Probes/art07_hole_approach.png` 第一版就是"树桩长在墙上"）。
   修法：桩子内端面**贴住屏障面**（南 z=18.111、北 z=19.889），孔与玩法孔首尾相接。
2. **布尔留下空材质槽**：切割面落到没有材质的槽上 → 渲染成纯白。修法：`material_index = 0` + 清多余槽。
