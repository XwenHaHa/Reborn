## 1 目标（可验收的一句话）

世界时间成为唯一的昼夜与恢复基准：`WorldDirector` 提供可断言的昼夜时钟契约（一天 = 1200 s、`WorldTime=0` 为白天起点、昼夜边界明确、连续秒刻度、与真实帧率 1:1）；结算/选物种期间时间与资源恢复**精确冻结**（既有门闩 T030 D7 只复证不重写）；**重生不重置世界时间**（不跳数小时、不重置白天）；固定食物按世界时钟恢复、一次结算多周期并夹紧容量，捕获食物失效跟随世界时间——恢复与捕猎/解锁保持零耦合；T033/T032 的 UI 契约（树序/解锁集语义/Toast 不进 `hud_text`/settle 最上）一条不踩。

## 3 关键决策

- **D1 昼夜时钟契约（先钉契约再动数值）**：刻度 = **连续世界秒**（不引入 tick/整点跳变）；换算 = TD §5 的 1 sim s : 1 real s（`world_time += delta`，门闩时 0）；一天 = `day_length = 1200.0 s`（真源 `Parameters.md:83`）；**昼夜边界对半**：白天 `[0, 600)`、夜晚 `[600, 1200)`，`WorldTime=0` 为白天起点——策划只给了周期与白天起点、未定义边界，**对半是 T034 新增实现默认值，需负责人并入正式起测值**。API 全部是 `world_time` 的**纯函数**（不存平行状态，杜绝两份时钟漂移）：`time_of_day()`（当天内秒，`fmod` 取余）、`day_index()`（0 起）、`is_daytime()`、`phase_name()`（`day`/`night`）。防呆：负 `world_time` 按 0 处理；`day_length ≤ 0` 时视为恒白天（读数全 0）。昼夜**光照**属 T057，本任务不做任何光照变化。
- **D2 门闩既有契约只复证不重写**：`SETTLING`/`SELECTING` 冻结（`LifeCycle._freeze_time`，T030 D7）已存在；本任务用断言固化「门闩期间 `world_time` **精确不变**（真实毫秒等待对照）→ 资源恢复与捕获食物失效都不动」。`set_world_time()` 是**权威时间指令**（存档恢复/取证快进），门闩不阻止它——策划 §10.1 说的是"模拟停止"，手动设时间属读档路径，不违规；测试里不用它冒充"门闩期间时间在走"。
- **D3 重生不重置时间**：正式死亡→重生路径**绝不调用 `reset_for_new_game()`**（它只属"明确的新游戏"）；断言第二世 `start_world_time ≥ 第一世死亡时刻` 且两者间隔在数秒内（「不额外跳过数小时或重置白天」的可断言形式），且出生后 `world_time` 从死亡时刻继续。
- **D4 资源恢复 = 世界时间驱动（复证 + 收口）**：`ResourcePoint.advance_to()` + `auto_advance`（T017）已按世界时间推进；本任务收口三件事并落断言：① **正/反对照**证明恢复吃世界时间而非真实时间——ALIVE 下把 `next_refill_at` 排到 `wt+0.01` 真实等待即恢复；同样夹具在 SELECTING（时间冻结）下真实等待 600 ms **不恢复**；② 权威快进（`set_world_time`）跨多周期**一次结算**并夹紧容量、`next_refill_at` 更新到未来（T017 J 段单元语义在正式场景实例上复证）；③ 捕获食物 `expire_at` 跟随世界时间（快进即失效、门闩真实等待不失效）。恢复速率与捕猎/解锁**零耦合**由既有套件回归（t031/t033）守住，本任务不碰任何解锁/计数代码。
- **D5 存活读数最小可读版**：ALIVE 状态行追加「第 N 天·白天/夜晚」（N = `day_index()+1`，人话从 1 数起；引擎口径 0 起由断言锁死）。策划未强制时钟 UI → **不新增 HUD/菜单元素**。状态行在存活期默认隐藏是既有呈现（`_present_menu` 隐藏、出生后不恢复）——取证帧沿用 t031/t033 的"取证侧强制可见"口径，并在证据里如实记录这一呈现事实，不冒充玩家常驻 UI。
- **D6 T033/T032 契约零改动复证**：UI 树序 `hud→MainMenu→LifeStatus→LifeSettlePanel`、`MainMenu.build` 缺省空=全可玩 / `set_unlocked` 显式空=全锁、Toast 不进 `hud_text()`、`settle` 最上——本任务对这些**只断言不改**（测试 A 段轻量复证 + 全量回归兜底）。
- **D7 headless 能力门（既有）**：真实毫秒等待用 `Time.get_ticks_msec()` 循环（t033 E 段同法），不把帧数当真实时间；点击/光照类不在本任务范围，无新增能力缺口。

## 6 用例（`tests/run_t034_world_clock.gd`）

- **A 时钟契约**：`day_length` 初值 1200；`wt=0` → day 0 / 白天 / `time_of_day=0`；`599.99`→白天、`600`→夜晚、`1199.99`→夜晚且 day 0、`1200`→白天且 day 1、`1800`→夜晚 day 1；负 `world_time` 防呆归 0；纯函数（同输入两次结果一致）；`day_length≤0` 防呆。
- **B 门闩冻结与换算**：ALIVE 下真实帧推进 `world_time` 递增（1:1 sim/real）；死亡后 SELECTING 下真实毫秒等待 600 ms，`world_time` **精确相等**、昼夜读数不翻转、`time_is_advancing()=false`。
- **C 重生不重置时间**：记录第一世死亡时刻 `t_death>0`；第二世 `start_world_time ≥ t_death` 且 `< t_death+10`（不跳数小时）；第二世 ALIVE 后 `world_time ≥ t_death` 且继续递增；`day` 读数未重置回第一世之前。
- **D 资源恢复 = 世界时间驱动**：正式场景内取一个真实食物点，运行时把 `refill_interval` 改 1.0（只改实例，不入库）：① ALIVE 下 `units` 扣 2 → 权威快进 +2.5 s → 等帧后 `units` 一次回到容量、`next_refill_at` 排到未来（多周期一次结算+夹紧）；② 同夹具（`next_refill_at=wt+0.01`、`units<capacity`）在 SELECTING 下真实等待 600 ms **不恢复**（反证：恢复吃世界时间不吃真实时间）；③ ALIVE 正对照：同夹具真实等待 300 ms 即恢复；④ 捕获食物（`expire_at` 型）：ALIVE 快进过期 → 失效清零；SELECTING 下真实等待不过期。
- **E 存活读数**：ALIVE 状态行含「第 1 天」与「白天」；权威快进到 650 s → 刷新后含「夜晚」且仍是「第 1 天」；快进到 1200 s → 「第 2 天·白天」；SELECTING/SETTLING 行不含天读数。
- **F T033/T032 契约复证**：层序 `menu < LifeStatus < settle`；`build` 缺省全可玩 / `set_unlocked` 显式空全锁；Toast 文本不在 `hud_text()`。
- **变异校验（4 处，每处必须红）**：① `is_daytime` 边界 `>=`（600 归白天）→ A/E 红；② `day_index` 改 `int(world_time/day_length + 0.5)`（进位）→ A/C/E 红；③ ALIVE 状态行去掉天读数 → E 红；④ `mark_spawned` 去掉 `_restore_time()` → B/C 红（重生后时间仍冻结）。

## 7 失败恢复

- 若 `run_t014`/`run_t017`/`run_t030` 回归红：本任务对这三处是**纯加法**——先怀疑测试夹具互相污染（实例级改 `refill_interval` 后未复位、快进后的 `world_time` 影响后续段），修夹具不动生产语义。
- 若快进后玩家濒死/死亡：快进总量控制在 ≤1300 s（猫饥渴损耗 0.08+0.06/s ≈ 182 点 → 起测 100 会死）；分段的夹具顺序要保证读数断言发生在死亡前，必要时把快进改小或分段补满指标（只改测试实例）。
- 若 headless 真实毫秒等待断言抖动：只断言 `world_time` 精确相等与 `units` 不变，不等长等待；可读性判断全部交给 `CaptureRun` + vision。
- 若全量批再遇后台句柄丢失：用顺序脚本（`Tools/t033_headless_batch.ps1` 同款）重跑并保留两轮日志，如实记录；不漏套件。
- 同一失败最多两次有依据的修复尝试；无新诊断不重试。
