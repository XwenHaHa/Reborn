## 1. 目标与明确不做

**目标**：把 T037/T038 已有的原子写与单队列能力**验证到损坏/失败/强杀边界**，并补齐两处缺口：
① 主档与 `.bak` 同时损坏时，两份坏档都隔离、给出明确文案、**不写任何新档**；
② 主档缺失且 `.bak` 损坏时，不再静默当作“无存档”。
所有结论都要能回答“玩家看到什么、存档文件变成什么样”。

**明确不做**：
- 不改存档格式、`save_version`、`WorldSnapshot` 键集合、`pending_settlement_life_id` 语义。
- 不改 T038 队列/节流/关键事务语义；不改 `LifeCycle` 状态机与死亡/发现/解锁时机。
- 不做多槽、云存档、手动存档 UI、跨进程锁、异步线程。
- 不做 T041 的“主菜单继续/新游戏确认”完整交互；T039 只做**阻断**（见 D3），T041 再做显式确认入口。
- 不做 `last_safe_spot_id`（T042）、按区域账本实例化 NPC（T040）。
- 不改挂账项：自然死亡不扣账、T034 昼夜 0.5、T029 两决策、过渡态 `active>total`。

## 2. 审计范围与验收判据

| 范围 | 判据 |
|---|---|
| 临时档 | `.tmp` 半截/非法/存在但主档完好：**只认主档**；不污染主档；下次保存成功且清理 `.tmp` |
| 写入失败 | 四类注入（`tmp_open`/`disk_write`/`bak_copy`/`rename`）连续多次失败、失败后退出：主档与 `.bak` 不双坏、无死锁、无半写 |
| 备份恢复 | 主档损坏→隔离→`.bak` 载入→提示；主档缺失→`.bak` 载入；**双坏**→两份隔离+「存档损坏，已隔离；未载入」+不写新档+不静默进新游戏 |
| 真机强杀 | 保存中四个时点被外部 `TerminateProcess`；重启后读档结果、玩家提示、旧档完整性逐条断言 |
| 兼容 | T030～T038 全绿；T037/T038 既有断言**不改语义** |
| 观测 | `last_quarantine` 可列出被隔离文件；`MainEntry.is_load_blocked()` |

## 3. 决策

- **D1（`.tmp` 不是读档来源）**：读档只认主档与 `.bak`。`.tmp` 是写入中间态，可能来自任意时点；
  即使内容完整、`revision` 更新，也**不载入**。下次写入前删除残留 `.tmp`，防止陈旧中间态被误当新档。
- **D2（隔离而非删除）**：任何要判定为损坏的源（主档或 `.bak`）都改名为
  `<原路径>.corrupt-<unix>`；同名已存在时追加 `-1/-2…`。**不删除**，供事后取证/手工救援。
- **D3（双坏阻断）**：主档与 `.bak` 同时不可用 →
  - `SaveManager` 返回 `status=corrupt`，消息精确为 **「存档损坏，已隔离；未载入」**；
  - 两份坏档都隔离；读档过程**零写入**；
  - `MainEntry` 仍呈现菜单并显示该提示，但**拒绝物种选择**（不开始新游戏），且**退出时不自动保存**；
  - 恢复路径：隔离后主路径已空，**重启**会按“无存档”正常开新局；会话内“确认开始新游戏”留给 T041。
- **D4（缺主档分支）**：
  - 主档缺失 + `.bak` 有效 → `recovered_backup`「主存档缺失，已从备份恢复」；
  - 主档缺失 + `.bak` 存在但损坏 → 隔离 `.bak`，返回 `corrupt`（不再静默 `none`）；
  - 主档缺失 + 无 `.bak` → `none`（合法新局）。
- **D5（连续失败不升级）**：写入失败**不重试**（T037 §7）。同一故障连续多次只累计 `failed`，主档与 `.bak`
  保持上一次可解析状态；失败后进程退出仍不写坏档、不锁死队列。
- **D6（可控延迟钩子，仅测试）**：`write_delay_phase ∈ {before_tmp, tmp_mid, rename_gap, bak_rotate}` +
  `write_delay_ms`，在对应时点 `print("T039|phase|…|begin")` 后阻塞主线程。生产默认空/0。
  这是**为取证扩窗的可控延迟，不是生产行为**；证据中必须写明。
- **D7（真机强杀口径）**：用 `Tools/CaptureRun.ps1`（隐藏桌面、GUI exe）启动真实游戏进程，
  监视器读到标记后 `TerminateProcess`。它近似“进程被杀、文件句柄未 flush/fsync”这一层；
  **不能**覆盖：真正的掉电/硬复位、OS 写缓存未落盘、磁盘控制器缓存、扇区级损坏、硬件级撕裂写。
  证据中一律写“进程强杀”，不用“断电”二字冒充。
- **D8（兼容）**：T037/T038 的断言与存档格式零改动；`last_safe_spot_id` 仍属 T042。
- **D9（观测）**：`last_quarantine`（本次读档隔离了哪些文件）、`last_status`、`last_message`；
  `MainEntry.is_load_blocked()`。
- **D10（玩家可见）**：复用菜单「上一世」文字位与 HUD Toast；不新建 UI。

## 6. 用例（A～F）

| 段 | 断言 |
|---|---|
| A `.tmp` 残留 | 半截 `.tmp` + 好主档 → `ok` 且 revision/内容来自主档；`.tmp` 不参与读档；下次保存成功、`.tmp` 清理；完整但更“新”的 `.tmp` 仍不载入；仅 `.tmp` 无主档/备份 → `none`，下一次写从新档开始并清掉陈旧 `.tmp` |
| B 写入失败 | 四类注入各连续 2 次：状态 `write_failed`/`ok+warning`、主档与 `.bak` 各自可解析、无 `.old`/`.tmp` 残留；`tmp_open`/`disk_write` 不删旧档；失败后清故障继续成功；注入失败时退出（`_exit_tree` 再写一次也失败）后两份旧档仍可解析、队列无死锁 |
| C 双坏 | 主档坏 + `.bak` 好 → `recovered_backup`、主档被隔离且坏内容保留、`.bak` 不动；主档坏 + 无备份 → `corrupt`、主档隔离；主档缺失 + `.bak` 坏 → `corrupt`、`.bak` 隔离；双坏 → `corrupt`、**两份都隔离**、消息精确、隔离后原路径不存在、读档零写入 |
| D 阻断 | 预置双坏后实例化 `MainEntry`（正式持久化）：`is_load_blocked()` 为真、快照为空、选物种被拒且仍停在 `SELECTING`；不产生新主档；释放入口时退出保存不执行（无新档）；重启后（隔离已移走）`none` + 可正常开局 |
| E 连续失败/退出 | 同一注入连续 3 次：`failed` 累计、revision 不动、每次后 `main` 与 `bak` 都可解析；退出保存失败同样不改坏档；`active_writes=0`、`queue_length=0` |
| F 兼容 | `throttle_seconds=1.0`、`threaded=false`、T038 队列 API 仍在；`last_safe_spot_id` 不写入（现有格式不变） |

变异表（≥3）：M1 双坏不隔离 `.bak` → C 段红；M2 主档缺失 + `.bak` 坏仍返回 `none` → C 段红；
M3 双坏时 `MainEntry` 仍允许选择/退出仍保存 → D 段红；M4 读档把 `.tmp` 当候选来源 → A 段红。

## 7. 失败恢复

- 单次写失败：不重试，保留旧主档/`.bak`，队列复位；后续请求继续。
- 备份复制失败：主档照常更新，旧 `.bak` 保留，warning 提示。连续失败仍不升级为致命。
- 读档隔离失败（只读/占用）：不删除文件，保留原路径并记录 `quarantine_failed`。
- 双坏阻断：不写新档；重启后按“无存档”开新局；原坏档留在 `.corrupt-*` 供取证。
- 真机强杀：重启只允许载入主档或有效 `.bak`；`.tmp`/`.old`/`.bak.tmp` 残留一律不载入，下次保存清理。
