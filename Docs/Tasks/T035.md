# T035 区域 NPC 数量账本（种群数量与恢复）

> 状态：in-progress（2026-11-03 开工）。
> 依据：总计划 `:169`「区域 NPC 数量账本——活动数量与区域总数定义一致，捕获只扣一次，恢复不超过容量，读档可据数量重建」；`Docs/TestCases.md` W01；`Docs/TechnicalDesign.md` §1/§3/§7/§8；`Docs/Parameters.md` 第 77 行（T035 真源）。
> 前置：T014 done（统一世界时间）、T021 done（捕获幂等上报）、T027 done（测试生态布置）、T034 done（昼夜与恢复时钟契约）。HEAD 起点 `1b162ba`。

## 1. 目标

给 `WorldDirector` 加**区域种群账本**：每个关卡区域 × 物种一条 `RegionRecord`（`total_count / capacity / next_recover_at / recover_interval`，TD §3 数据契约）。种群恢复**只吃世界时间**（复用 T034 时钟契约：`world_time` 单一时间源、门闩冻结、`set_world_time` 权威快进），捕获从账本**扣一次**，恢复**夹紧容量**，账本为**纯数据**可快照/重建（"读档可据数量重建"）。

**明确不做**（边界）：
- 不按总数**实例化/重建** NPC 身体（落点 + 安全距离重建是 T040 职责；本轮活动身体仍由 T027 生态布置器按其既有计数铺）。
- 不加种群 UI（策划 §3.2「区域数量延续」是账本事；U01 无种群显示要求）。
- 不实现真实读档（T037+）；本轮只保证账本可 round-trip。
- 不改 `NIGHT_START_RATIO=0.5` / `day_length=1200`（未正式并入起测值，负责人口径：不顺手改）。
- T029 两条挂账（鼠洞不是安全区 / 冲针会把 AI 冲出平台）不顺手"修好"；见 §9。

## 3. 决策

- **D1 账本真源与位置**：`WorldDirector`（TD §1 已排定"NPC 生成与区域账本"；TD §8"禁止两份同时权威"——T036 若迁移 GameState 所有权时**搬走**而不是复制）。记录键 `"region_id|species_id"`，值 = `RegionRecord` 形状 Dictionary，**纯数据、无 Node 引用** → 可进存档。
- **D2 参数数据驱动（不写物种名）**：`SpeciesConfig` 新增 `Population` 组：`region_capacity: int`、`region_initial: int`、`region_recover_interval: float`（**0 = 不自动恢复**）。鼠 4/2/240、猫 1/1/0，只写 `.tres`。`validate_config()` 补校验：capacity ≥ 0；initial ∈ [0, capacity]；interval ≥ 0 且有限。数值真源 `Parameters.md` 第 77 行，**按初值执行，本轮零调参**。
- **D3 区域清单来自关卡**：`init_region_population(configs)` 扫 `level_regions` 组（`Region_*` Node3D + `region_id` meta），账本 = 关卡区域 × 物种配置的笛卡尔积。区域矩形从场景**只读推导**（标记位置 ± 子 `Volume/Shape` BoxShape3D 的半尺寸，水平 XZ），缓存后供 `region_id_at(pos)` 反查。初始总计：鼠 8 / 猫 4（4 区 × 每区 initial）——**以关卡 4 区域为前提**，区域数变化则总量跟随，不是硬编码总数。无 `level_regions` 的夹具关卡：账本空、`region_id_at` 返回 `&""`、登记/恢复全为安全 no-op、**不崩**。
- **D4 恢复只吃世界时间**：镜像 `ResourcePoint.advance_to` 语义（T017/T034 已验收）：**多周期一次结算**、**夹紧容量**、**满容量清零 `next_recover_at`**（有空额时下次 advance 重排 `t + interval`）。驱动 = `WorldDirector._process` 在 `world_time += delta` 后调 `region_population_advance_to(world_time)`——`time_advancing=false` 时 `_process` 早退 → **门闩天然冻结**（同 T034 D2，不另造时钟）。`set_world_time` 权威快进后由**下一次 advance** 结算经过的周期（Parameters 第 81 行口径，休息结算 T058 复用）。猫 interval=0 → **原型不自动增长**（快进任意时长不恢复）。**零耦合**：恢复不查解锁集、不查捕猎账本、不知道 UI。
- **D5 捕获只扣一次**：`report_capture` 在**幂等门内**（首次真实结算、`captured_target_ids` 去重）扣受害者区域的 `total_count - 1`（下限 0）并移出活动登记；受害者须**在活动登记中**（T027 布置器铺的正式 NPC）；**未登记个体**（测试夹具/临时身体）只走全局捕获账本，区域账**不动**（t021/t022/t026/t031/t033 既有夹具零影响）。重复上报 `false` → 不重复扣。`capture_reported` 信号签名**零改动**（加参会破坏既有连接）；区域语义经账本查询暴露，信号面待有消费者（T036+）再议。
- **D6 活动个体登记 = 表现层**：TD §3 明文「`total_count` 包含已实例化与未实例化个体；实例化/销毁表现不改变它」。活动登记只用于两件事：①不变式 **每区每物种 `active ≤ total`**；②捕获扣账时反查受害者区域。活动计数口径 = 登记且实例有效且未死（survival 死亡）且未被捕获。**死亡/销毁表现不动总数**（TD 口径；自然死亡的个体在下次重建时"复活"是已知怪癖，记录给负责人，不擅自加扣账规则——W01 只钉「捕获减 1 一次」）。目标玩家不计入（玩家不登记）。
- **D7 快照与重建**：`region_population_snapshot() -> Array[Dictionary]`（RegionRecord 形状，即 TD §3 `WorldSnapshot.regions` 的元素形状）；`restore_region_population(snapshot) -> Dictionary`（修复报告）：未知区域/未知物种 → **跳过并记录**；负数 → 钳 0；超容量 → 钳容量；非有限 → 回初始。**读档可据数量重建** = 账本纯数据可 round-trip 且恢复后继续正常运转（能接着排期/结算/扣账）；真实重建身体是 T040。
- **D8 新游戏 / 重生**：`reset_for_new_game()` 清空账本（记录 + 活动登记 + 区域矩形缓存 + initialized=false），只有明确新游戏确认才可调（TD §7）。`MainEntry._ready` 建关卡后 init **一次**；正式死亡 → 重生**不重置、不再 init**（与 T034 D3 时间语义同构；断言锁）。
- **D9 门闩语义与 T034 对齐**：SELECTING/SETTLING 期间恢复冻结（真实等待不恢复）；ALIVE 正对照真实等待即恢复（同 t034 D 段正/反夹具口径）。
- **D10 包体**：`.tres` + 生产脚本进包 → 本轮**重导出两预设**（Reborn / RebornSelfTest）并做包内断言（t035 全套 + 抽查 t034），不沿用 T034 的免导出口径（本轮有数据资源变化）。

## 6. 用例（对应 `run_t035_region_population.gd`）

- **A 初始化契约**：4 区域齐；鼠每区 total=2/cap=4/interval=240；猫每区 total=1/cap=1/interval=0；总计鼠 8 / 猫 4；`initialized=true`；SpeciesConfig 校验两实例空。
- **B 区域反查与活动登记**：`region_id_at` 对四区代表点各得正确 `region_id`、区外点得 `&""`；spawner 铺的鼠逐只登记（登记区域 = 反查结果）；`Σactive(Mouse) == 反查非空的铺出数`；`Σactive(Cat) == 0`（目标玩家不计入）；每区每物种 `active ≤ total`。
- **C 捕获只扣一次**：真实捕获一只登记鼠 → 其区 total −1、active −1；同 `target_id` 重复 `report_capture` → `false`、账不动；未登记夹具个体上报 → 全局 `capture_count` +1、区域账不动；扣账后 `total` 下限 0（人工负账快照不产生负数）。
- **D 恢复只吃世界时间**：捕获造空额后权威快进 240 s → +1、`next_recover_at` 排到未来；一次 advance 快进 1000 s → **多周期一次结算** +3 且**夹紧容量 4**、满容量清零 `next_recover_at`；SELECTING 门闩下 `next=t+0.01` 真实等 600 ms → **不恢复**；ALIVE 正对照真实等 → 恢复；猫区 interval=0 → 快进 2000 s 不增长；恢复与解锁集/捕猎计数零耦合（恢复期间 `capture_count` 不变、解锁集不变）。
- **E 快照与重建**：快照形状逐字段对照；造 deficit → 快照 → 再变账 → `restore_region_population(旧快照)` → totals 回到快照值；坏快照防呆：未知区域/物种跳过、负数钳 0、超容量钳容量、非有限回初始；restore 后能继续正常排期结算（不冻结）。
- **F 重生不重置种群**：扣账后死亡 → 重生（第二世）→ totals 保持扣后值、`initialized` 不翻、鼠总账不回 8。
- **G 新游戏重置**：`reset_for_new_game()` → 账本清空（records/active/rects/initialized）；再 `init` → 回初始 8/4。
- **H 既有契约复证**：T033 UI 树序 / 解锁集语义；T034 状态行天读数 + 时钟不进 `hud_text`；`capture_reported` 发信次数 == `capture_count`（扣账不加发信）。

**变异校验（各处先红后复原）**：
1. 恢循环去掉 `total < capacity` 守卫 → total 超容量（D 红）。
2. 扣账移出幂等门（每次 `report_capture` 都扣）→ 重复上报再扣（C 红）。
3. `region_id_at` 恒返回第一个区域 → B 红（分布断言）。
4. `region_initial` 误用 `region_capacity`（初始=容量）→ A/F 红（total=4≠2）。
