## 1. 目标

1. **能用**：一只鼠 NPC 从出生点**自己走去**最近的可用食物点，到达后用**和玩家同一套**交互接口进食（`Parameters.md` 第 75 行：1.5 s、1 Unit → Hunger 35），吃完回到探索。
2. **警戒可切换**：外部注入威胁（`alert_for(position, reason)`，T020 接真实视觉/听觉）→ 进 `ALERT`，
   **最长 0.3 s**；期间**停止移动与进食**且**无收益**；警戒时间到且无新威胁 → 回到 `FORAGE`/`EXPLORE`。
3. **状态与原因可查看**：`state` + `state_reason` + `state_elapsed` + 目标/路径诊断，进调试入口 HUD（`ai:` 行）与 `MOV|`。
4. **MoveTo 失败不永久阻塞**：1 s 内无法推进 → 回退重选；**最多 3 次**后进入**短暂等待**（`WAIT`）并记录诊断；
   等待结束仍能回到 `EXPLORE` 重新找目标。
5. **不每帧请求路径**：只在"换目标 / 换状态 / 上一次路径失效"时重新设置 `target_position`（用 `target_reached` / `navigation_finished` 驱动）。
6. **沿用已有规则**：饥饿/体力照 `Parameters.md` 消耗（T014/T015）；进食走 `ResourcePoint`（T017）；导航层来自地图 metadata（T012）——
   **不新增一套 NPC 专用存活逻辑**。

## 4. 决策（D1~D8）

- **D1 AI 是组件**：`AnimalAI extends Node` 挂在身体下（与 T016 的 `InteractionDetector` 同一模式）；
  身体只执行 `move_intent` / `want_*`，**不把状态机写进身体**。
- **D2 时间用世界时间**：所有计时（`state_elapsed`、Alert 0.3 s、失败窗口 1 s、等待时长）用 `body.world_time_now()` 的差，
  **不累加 `delta`**（与 T014 一致：暂停不推进）。
- **D3 导航层从地图反查**：遍历树里的 `NavigationRegion3D`，按 `metadata/species == config.species_id` 取 `navigation_layers`
  （与 `debug_entry.nav_layer_for()` 同源；**不硬编码物种名**）。取不到时回退到 `1` 并在 `ai_report()` 里标 `nav_layer_source=fallback`。
- **D4 NPC 与玩家共用交互规则**：NPC 到达后调 `InteractionDetector.press_interact()`，由 T016/T017 的机制计时与结算
  （策划第 335 行）。AI **不自己扣 units、不自己加 hunger**。
- **D5 MoveTo 失败判据**：`retry_window = 1.0 s`（`Parameters.md` 第 71 行）内，位置推进 < `min_progress = 0.05 m`
  且未 `is_navigation_finished()` → 记一次失败。**不每帧请求路径**（只在换目标/换状态/路径失效时设 `target_position`）。
- **D6 重选与等待**：失败后回退（重新选目标）最多 **3 次**；第 4 次进 `State.WAIT`，持续 `move_fail_wait = 1.0 s`，
  `state_reason = &"path_failed"`；等待结束回 `EXPLORE`（**不永久阻塞**）。诊断写入 `ai_report()` 的 `path_failures` / `replans` / `last_path_status`。
- **D7 警戒语义**：`alert_for()` 进 `ALERT`，时长 `min(0.3, ...)` 由 `alert_max_time = 0.3 s` 承载；进入时
  `interaction.release_interact(&"alert")`（**无收益**，T017 语义）+ `move_intent = 0`；**不逃跑**（逃跑与躲藏属 T020）。
- **D8 状态值**：`State` 前 9 个值与 `TechnicalDesign.md` §1 `AIState` **顺序一致**，末尾追加 `WAIT`（第 10 个，
  对应 Parameters 的"短暂等待"）；`state` 与 `state_reason` 都是 `StringName`，便于 HUD/日志/断言。

## 6. 断言（`tests/run_t019_mouse_ai.gd`，目标 ≈90 条）

- **A 状态机接口**：`State` 前 9 个值与契约一致（逐个断言 `EXPLORE=0 … ATTACK=8`）且 `WAIT=9`；
  `state_id()` / `state_reason()` 初值可读；`change_state()` 发 `state_changed` 且记录原因；`ai_report()` 字段齐全。
- **B 目标选择**：三个食物点（近的可食 / 近的不可食 `/ 空 / 远）→ 选**最近的可食且有 Unit 的**；
  不可食（猫的肉）与空（`units=0`）被跳过；全都不行 → `state = EXPLORE`、`reason = &"no_food_known"`。
- **C 导航**：`nav_layer()` 从地图 metadata 反查到**鼠层**（非硬编码）；`_set_destination()` 后路径点 > 1；
  **同一目标下不重复设 `target_position`**（计数 `destination_sets` 不随时间增长）。
- **D 移动与到达**：NPC 在真实物理帧下朝目标位移（位置变化 > 0.5 m，速度 ≤ 配置行走速度）；
  进入 `interaction_range` 后进 `FORAGE`（`reason = &"arrived"`）。
- **E 进食（共用 T017 规则）**：到达后自动开始交互 → 1.5 s 后提交：目标 `units` 3→2、NPC hunger +35（夹紧）、
  `state` 回 `EXPLORE`、`reason = &"ate"`、`ate_count() == 1`；**AI 自己不扣 units**（提交前后由 `ResourcePoint` 判定）。
- **F 警戒**：`alert_for()` → `state = ALERT`、`reason` 可读、`has_alert()` 为真；期间 `move_intent == 0`
  且进行中的交互被取消（`cancel_call_count()` +1、**units 不变、hunger 不变**）；**0.3 s 后**自动回落
  （`state_elapsed` 与 0.3 s 的关系实测）；威胁重复注入 → 仍保持 `ALERT` 但**不无限延长**（以最后一次注入 + 0.3 s 为界）。
- **G 失败处理**：目标不可达（导航层上封死）→ `path_failures ≥ 1`、`replans ≤ 3`、进入 `WAIT`（`reason = &"path_failed"`）、
  `last_path_status` 可读；`WAIT` 结束后回 `EXPLORE`（**不永久阻塞**）；整段过程 NPC 仍在物理世界里（没被卡死）。
- **H 集成**：真实 `animal_body.tscn` + `resource_point.tscn` + `l_courtyard` 的导航区域；
  调试入口 HUD 出现 `ai:` 行、`MOV|` 出现 `ai_state=`；正式场景仍 0 调试节点；全量回归不退化。

## 8. 失败回退

- 若导航代理在测试世界拿不到导航面（headless 下烘焙/同步时机）：改用**显式 `NavigationRegion3D` + 运行期 bake**，
  或退一步只断言"状态机与目标选择"（并把移动断言标 NOT-RUN）——**不伪造位移**。
- 若 NPC 与玩家共用交互导致互相抢目标：给 AI 的检测器加 `probe_extra_range`/优先级以外的**显式目标**（`_set_explicit_target()`），
  但仍走 `query_/commit_interaction`；在证据里写明。
- 任一失败最多两次有依据的修复，之后按 `AGENTS.md` 记 blocked。
