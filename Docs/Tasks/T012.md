## 1. 目标

给 T011 的生态灰盒 `scenes/maps/l_courtyard.tscn` 加**分物种的导航数据**，并用**真实 `AnimalBody` + `NavigationAgent3D`** 回答三个问题：

1. **猫和鼠各自的导航代理配置能不能"合法通行"**：鼠能沿导航路径穿过 0.24 × 0.30 树根洞与溪边 0.24 缝；
   猫在**庭院/草地等常规地面**能正常寻路走到目标。
2. **猫的导航图在鼠洞处必须断开**（`猫不能进入鼠洞`）：同一对"洞两侧"的目标点，猫**没有**穿洞路径；
   若存在路径，只能是绕行远路（长度显著大于洞的直线距离），且**路径点不得落在洞口通道内**。
3. **猫跨 0.50 树根屏障必须靠跳跃**：导航图不含跳跃边，因此屏障顶面是**孤岛**或与地面不连通 ——
   **如实记录**为"NPC 猫跨屏障需要 `NavigationLink3D` 跳跃链接或走远路"，本任务**不擅自加跳跃链接**（属 AI/关卡决策）。

范围外（**本任务不做**）：AI 决策/状态机（T019+）、`NavigationLink3D` 跳跃链接、避障与拥挤调度、动态障碍、
动画/寻路表现、任意瞬移或"贴脸传送"。

## 4. 决策（先写清，再实现）

- **D1 两个导航区（分物种）+ **同一张地图的不同 layer****：Godot 的 `agent_radius` / `agent_height` 是**烘焙参数**，
  一张图无法同时满足"0.32 宽的猫过不去、0.12 宽的鼠过得去"的 0.24 洞，因此烘**两张图**：
  `NavRegion_Mouse`（用鼠的尺寸，**layer 1**）与 `NavRegion_Cat`（用猫的尺寸，**layer 2**），
  查询/代理各用自己那一层。
  > **实测修订（2026-10-13）**：原本设想的"每个物种一张**自建地图**"在 Godot 4.7 上不可用 ——
  > 第二张自建地图的查询**恒为空**（等 600 帧仍 0 路径点），而"**共用一张地图 + 分层**"正常。
  > 故改为共用地图（`project.godot` 里把默认地图格设为 0.03，与导航面一致）。
- **D2 参数从物种配置派生，不另写一份常量**：
  `agent_radius = capsule_radius + 0.01`、`agent_height = capsule_height() + 0.02`、`agent_max_climb = max_step_height`、
  `agent_max_slope = 45°`（关卡没有斜坡，取保守值）。断言把这三项与 `*.tres` 对照（改物种尺寸就会红）。
- **D3 只烘静态碰撞**：`geometry_parsed_geometry_type = STATIC_COLLIDERS`（关卡里所有实体都是
  `StaticBody3D` + `BoxShape3D`；glb 只带视觉，见 T005 约定）。`geometry_collision_mask = 1`（world_static）。
  烘焙源用 **`geometry_source_geometry_mode = GROUPS_WITH_CHILDREN` + 分组 `nav_source_courtyard`**
  （实测：`ROOT_NODE_CHILDREN` 只认**区域自己的子节点**，会让"两张图烘同一套几何"变不出图）。
  区域/掩体/危险区是 `layer=0` 的**数据体量**，不会污染导航几何。
- **D4 烘焙产物是资源，不是运行时状态**：烘出的 `NavigationMesh` 存 `resources/nav/l_courtyard_{cat,mouse}.tres`，
  再作为 `NavigationRegion3D.navigation_mesh` 引用进关卡。这样导航数据可 diff、可复现、可回归。
- **D5 「入树烘焙」是刻意破例，写清原因**：烘焙必须让几何在世界里可见（`NavigationRegion3D` 子树），
  所以 `tool_bake_courtyard_nav.gd` **会**把场景实例化进树 —— 但它**只读几何、只写 `.tres`**，
  **不保存场景**，因此不会把运行时状态写回 `.tscn`；写场景的是 `tool_add_nav_to_courtyard.gd`（**不入树**，同 T009/T011 规矩）。
- **D6 禁止瞬移伪装**：断言必须包含**真实 `AnimalBody` 沿路径走过去**（位置逐帧推进、`is_on_floor`、0 重叠），
  只验证 `map_get_path()` 有返回值**不算通过**。
- **D7 跳跃约束如实记录，不擅自解决**：导航图不含跳跃边 → 猫跨 0.50 屏障在导航层**不可达**（顶面孤岛），
  这是**已知事实**，写入证据与 UNVERIFIED/待确认表：NPC 猫跨屏障要么走远路（绕庭院），要么后续加 `NavigationLink3D`。

## 5. 导航参数（从物种配置派生）

| 参数 | 猫 | 鼠 | 依据 |
|---|---|---|---|
| `agent_radius` | 0.16 + 0.01 = **0.17** | 0.06 + 0.01 = **0.07** | 胶囊半径 + 1 cm 安全边距 |
| `agent_height` | 0.48 + 0.02 = **0.50** | 0.18 + 0.02 = **0.20** | 胶囊总高 + 2 cm |
| `agent_max_climb` | **0.12** | **0.03** | `max_step_height` |
| `agent_max_slope` | 45° | 45° | 关卡无斜坡，保守值 |
| `cell_size` / `cell_height` | **0.03 / 0.03** | **0.03 / 0.03** | **实测口径**：0.03 时 0.24 的洞能留在导航面上（鼠路径直穿、长度 = 直线）；≥0.05 时洞被吃掉、路径改绕行 |
| `region_min_size` | **0.02** | **0.02** | 实测：`rmin` 相对 cell 过小（如 cell 0.05 + rmin 0.05）会让查询**恒空**；0.03/0.02 正常 |

> 0.24 宽的洞对鼠（直径 0.12 + 2×0.01 边距 = 0.14）**可通行**；对猫（直径 0.32 + 0.02 = 0.34）**不可通行** ✓。
> 0.24 的溪缝同理。这两条正是要验证的核心判据。

**C 猫图（约 15 条）**：
- 庭院内两点（(−4, 24) → (−7, 22)）**有路径**且长度 ≈ 直距（证明猫图本身可用）；

## 8. 失败回退

- 若**鼠穿不过洞**：先检查 `cell_size` 是否太粗（0.24 洞只有 ~5 格）与 `agent_radius` 边距；
  允许调**烘焙参数**（cell/边距），**不许**把洞改宽（0.24×0.30 是 T010/T011 已验收的几何）。
- 若**猫能穿洞**：说明猫图把洞烘通了 → 检查猫图 `agent_radius` 是否被误写成鼠值、或 `cell_size` 过粗；
  **不许**用运行时"猫进洞就传送出来"的补丁（TechnicalDesign §5 明确禁止）。
- 若**猫图整体为空/大量断连**：检查 `geometry_collision_mask` 是否漏了 layer 1，或栅栏/屏障把地图切成太多孤岛；
  先打印多边形数与面积，再决定是参数问题还是关卡问题（后者报告负责人，不擅自改关卡）。
- 若**代理走到一半卡住**：记录逐帧位置与 `NavigationAgent3D` 的下一个路径点，区分"路径穿过实际过不去的地方"（烘焙问题）
  与"控制器贴墙"（T013 的范围）；**不许把超时放宽到掩盖卡死**。
- **本任务不新增跳跃链接**（D7）：猫跨屏障不可达是**记录项**，不是待修 bug。
