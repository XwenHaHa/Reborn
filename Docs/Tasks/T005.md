## 1. 目标

证明**资产链可用**，而不是"生成了一个文件"：

> 在 Blender 里显式建模的 **1 m** 物体，经 `.glb` 导出、Godot 导入后，引擎读回的真实尺寸仍是 **1.0 m**（不是 0.01，也不是 100），
> 轴向按 Blender `+Z`-up → glTF/Godot `+Y`-up 自动转换，且该物体在**运行中可作为碰撞体**被角色踩上去。

对应 `Docs/TestCases.md` **E02**、Bootstrap T005。

## 5. 所用参数版本

- Blender **3.3.1**（Python 3.10.2）；Godot **4.7.2.stable.official.ed1daf0bf**。
- 探针几何（本次**显式建模**，不用出厂 Cube —— 出厂 Cube 实测 2.000000 m）：
  - `ProbeCube`：边长 **1.000 m** 立方体，原点居中。
  - `Marker_Front` / `Marker_Top` / `Marker_Right`：0.1 m 小立方体，分别放在 Blender `(0,-2,0)` / `(0,0,+2)` / `(+2,0,0)`，用于**实测轴向转换**。
  - 四个对象各自独立材质（便于视觉检查区分方向），**不用自发光**（自发光会冲掉明暗差，见 Visual-Verification §3.2）。
- **轴向映射（实测已定，原假设已被实测改正）**：`(x, y, z)_Blender → (x, z, −y)_Godot`，即
  Blender `-Y`(前) → Godot **`+Z`**（不是 `-Z`）；Blender `+Z`(上) → Godot `+Y`；Blender `+X` → Godot `+X`。
  后果与角色资产约定已写入 `Docs/BlenderPipeline.md`（**角色在 Blender 里应面朝 `+Y`**）。
- 猫胶囊（碰撞回归用）：`radius=0.16, height=0.48`（÷100 后）。

## 6. 接口 / 状态转换

1. `blender.exe --background --factory-startup --python Tools/Blender/t005_static_probe.py`
   → stdout 输出 `PROBE|...` 机器可读事实；退出码 0 = 成功。
2. Godot `--headless --import` → 生成 `.import` 与 `.godot/imported/` 缓存（缓存已 gitignore）。
3. `--headless --path ... --script res://tests/run_t005_asset.gd --quit-after N` → 退出码 0 = 断言全过。
4. 视觉：**不能 headless**，用 `tests/tool_capture_render.gd`（需真实渲染器）导出 PNG，再交 `vision.js`。

## 7. 逐步实现

1. 用已知答案探针图复验 vision 工具可信性（防"工具坏了却用它下结论"）。
2. 写 Blender 脚本：查场景 → 建 4 个对象 + 材质 → 打印对象清单与实测尺寸/世界包围盒 → 存 `.blend` → **重开该 `.blend` 再查一次名称与尺寸**（Bootstrap 要求）→ 导出 `.glb`（记录实际导出设置）→ 打印文件 SHA256。
3. 把 `.glb` 放到 `Game/Reborn/assets/tests/`，运行 `--headless --import`，读回**真实** `.import` 设置并写入证据（不凭记忆写导入设置）。
4. 用 `tests/tool_dump_scene_tree.gd` dump 导入后的节点结构（决定 `.tscn` 该如何引用）。
5. 写 `tests/run_t005_asset.gd` 断言（全部**读真实引擎数据**）：
   - 导入场景可加载；存在 `MeshInstance3D`，其 `mesh.get_aabb().size` 三轴 ≈ 1.000 m（容差 0.01）；
   - 四个对象名保留；标记物在 Godot 空间的位置符合轴向映射（容差 0.01）；
   - 网格有材质且反照率接近脚本设定值（材质随 glb 往返）；
   - **运行中碰撞**：脚本内建地面 + 用**导入网格的 AABB** 生成 `BoxShape3D` 的 `StaticBody3D`，猫胶囊分别落到"平地"和"1 m 立方体顶面"，两次落点高度差 ≈ **1.00 m**（容差 0.02）。
6. 把 `ProbeAsset` 接入 `l_movement_lab.tscn`（放在标尺旁 `x=2.4, z=-2.5`，**避开 T002/T007 的运动路径**），用 `BoxShape3D(1,1,1)` 做简单碰撞。
7. 回归：`run_t002`、`run_t007_input`、`probe_step_height` 全跑，必须与改动前一致。
8. 渲染捕获 + vision 检查：立方体是否存在、是否与黄色 1 m 标尺**等长**、是否有明暗面、前/上/右标记颜色位置是否与轴向结论一致。

## 9. 失败回退

- Blender 侧失败（API 不存在/参数名不符）：**保存诊断**（完整 stderr + 实际可用参数签名），最多两次有依据的修复；仍失败则把 T005 记 **blocked** 并写明缺失能力。
- Godot 导入失败：保留 `.import` 与引擎 stderr，尝试显式导入设置，仍失败则如实记为 blocked，**不得用"手工改场景"绕过**资产链验证。
- 视觉工具失败：视觉项记 **awaiting-review**，不得编造画面判断。
- 任何失败都不改产品规则、不改引擎路线。
