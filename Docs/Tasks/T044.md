# T044 建立资产规格与清单

## 1. 目标与不做

**目标**（开发计划 :212）：把 P6 正式资产生产需要的六件事一次定清 —— **尺寸、朝向、材质数、预算、文件命名、来源**，并且**预算必须由本机实测得出，不套用固定面数**（`modeling4.md` §六 的原表明确写着"未经实机性能测试验证"）。

**不做**：
- 不做任何正式模型/贴图/动画（属 T045～T052，且需要负责人对模型来源的授权）。
- 不改玩法数值、不改关卡几何、不改存档与 UI。
- 不把 `references/**` 里的参考文件复制进 `Game/Reborn/`（Reference Lock 硬规则）。
- 不因为"面数达标"就宣称资产可用（评分门槛属 T045 起）。

## 3. 决策

- **D1 预算用增量实测**：新增 `tests/tool_t044_budget_probe.gd`，在真实关卡按固定机位叠加 N 个**真实资产实例**（猫/鼠骨骼网格、巨石/草丛静态网格），测每帧耗时与 primitive/draw call，用"每件增量成本"反推上限。测 `1280×720`（项目基线）与 `1920×1080`（余量档）。
- **D2 预算分三层**：① 单件上限（tris / 材质槽 / draw call）；② **场景总增量**（P6 新增资产合计 ≤ 一定 ms 或 draw call，先到者为准）；③ 分辨率档位（720p 是验收基线，1080p 是余量，成本比实测给出）。
- **D3 面数不再是唯一硬约束**：若实测显示几何成本远低于填充/draw call 成本，则明确写"面数上限给足余量、真正的约束是 draw call 与屏幕覆盖率"，避免下游为面数牺牲结构（洞净空、耳/吻轮廓）。
- **D4 清单只做加法**：`reference_manifest.json` 保留既有 5 条不变，新增条目带 `origin`（`procedural` / `derived_from:<source>` / `third_party`），`state` 继续用既有枚举（现役未批准 = `modeling`）。
- **D5 来源三分工**：`reference_manifest.json` = 逐资产来源与候选；`Docs/THIRD_PARTY_ASSETS.md` = 仓库内第三方登记与署名义务；`Builds/P0-Win64/THIRD_PARTY_NOTICES.md`（构建产物）= 随包许可清单（T043 已落地）。

## 5. 验收

1. 探针可重复运行，输出机器型号 + 每档 `ms_avg/ms_p50/ms_p95/prim_peak/draw_peak`；`exit=0`、`BUDGET|done`。
2. `Docs/ART_ASSET_SPEC.md` §2 每个数字都能追到本次实测的某一档，**没有任何"感觉"数字**；原表若保留须标注为历史。
3. 单件上限 + 场景总增量 + 分辨率档位三层都写清，且给下游可判定的阈值（不是"尽量低"）。
4. 清单覆盖**当前包内全部资产**：manifest 条目数 ≥ 包内资产类目数，且每条有 `origin`／许可／在役文件路径。
5. 命名、朝向、尺度、材质槽、碰撞归属四条契约各有**一处权威表述**（不散落在多个文档里互相打架）。

## 6. 失败恢复

- 探针测不出差异（噪声大于增量）：提高采样帧数或换更大 N；仍测不出就如实写"该量级下不可分辨"，不编造斜率。
- 探针窗口抢焦点/污染桌面：`--position 2400,1200` 放屏幕外，不使用合成键鼠输入。
- JSON 改写破坏格式：先 `git checkout` 再按原缩进（`indent=1`）重写，`python -c "json.load"` 校验。
- 预算与既有断言冲突（如胶囊尺寸/洞净空）：**以断言为准**，预算只约束面数/材质，不约束碰撞与净空。
