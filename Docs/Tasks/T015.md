# T015：消耗、警告与基础伤害

状态：**in-progress（本文件为开工规格，2026-10-15）**。总计划定义：`轮生_Reborn_开发计划_v1.0.md` §5
「消耗、警告与基础伤害 | 4～8h | 前置 T014, T009, T010 | 奔跑/扑击有代价，体力耗尽保留行走；饥渴警告后才持续伤害；危险跌落测试」。
验收结果见 `Docs/Evidence/T015.md`。

## 1. 目标（逐条对 `Docs/Parameters.md` 第 65 行）

1. **奔跑有代价**：冲刺时按 `SprintStaminaPerSecond`（猫 15 / 鼠 35）消耗体力，消耗用**实际经过时间**（世界时间差，T014 统一入口）。
2. **体力门控（双门控）**：`Sprint 只有 Stamina≥5 可开始`；已经开始后可以继续跑到**耗尽**，然后**自动转行走**。
3. **体力耗尽仍保留基础移动**：耗尽不会停下、不会掉速度，只是不能冲刺（`TestCases.md` S02「拒绝高强度动作但可行走」）。
4. **饥渴警告**：`Hunger/Thirst ≤ 25` 发警告（暴露布尔量与事件，供 T018 HUD 用），**警告本身不扣血**。
5. **持续伤害**：任一归零后各扣 `Health 1/s`；两项均零则 `2/s`；**Health 不自动恢复**。
6. **跌落伤害**：落地前垂直速度绝对值 ≤ **700 cm/s（= 7 m/s）无伤**；超过按 `(speed_cm/s − 700) × 0.1` 伤害，**上限 100**。
   （换算到米：`damage = (|v_y| − 7.0) × 10`，与配置字段一一对应。）

范围外（**本任务不做**）：扑击的体力成本 25 与恢复（**T021**，其行内已写明）、NPC 攻击伤害 35（T025）、
食物/饮水交互（T017）、正式 HUD 的低值警告显示（T018）、死亡结算流程（T030）、**跳跃代价**（`Parameters.md` 没有给数值 → 见 §9 待确认）。

## 4. 决策

- **D1 体力门控做成"开始 / 继续"两个条件**（`Parameters.md` 第 65 行的两句话都满足）：
  开始冲刺要求 `stamina ≥ sprint_min_stamina`（5）；已经开始后只要求 `stamina > 0`。状态是 `AnimalBody._sprint_active`。
- **D2 消耗用世界时间差**：冲刺扣体力在 `_physics_process` 里用 `survival.tick_to(world_time)` 的**返回值**（= 本次世界时间差），
  不读 physics `delta`（与 T014 决策 D1 一致；`Parameters.md` 第 65 行「运动消耗使用实际经过时间」）。
- **D3 扣血复用 `apply_damage()`**：危机扣血走 T014 已有的伤害通道（写 `last_damage_reason`、归零只发一次 `died`），
  不在本任务新开一条生命修改路径。
- **D4 原因字符串固定三个**：`&"starvation"`（只有饥饿归零）/ `&"dehydration"`（只有水分归零）/
  `&"exhaustion"`（两项都归零）；便于 T030 的生命档案与诊断。
- **D5 警告是"查询 + 事件"，不是伤害**：`is_low_hunger()/is_low_thirst()` 只读；
  变化时发 `warning_changed(kind: StringName, active: bool)`（T018 直接接）。
- **D6 跌落只看落地前垂直速度**：腾空期间记录 `max(|velocity.y|)`，**落地那一帧**结算一次，然后清零；
  水平速度与高度差不参与判据（与 `Parameters.md` 的"落地前垂直速度"逐字一致）。
- **D7 不做跳跃代价**：`Parameters.md` 只给了冲刺与扑击的成本；跳跃代价没有依据 → 记入 §9 待确认，**不擅自加数值**。

## 6. 断言（`tests/run_t015_costs.gd`，目标 ≈80 条）

**A 参数落地**：六个新字段在两份 `.tres` 里都是 5 / 25 / 1 / 1 / 7.0 / 10.0；`validate_config()` 为空；
把字段改成非法值（0、负数）时校验**能报错**；`Parameters.md` 第 65 行的三个换算自查（700 cm/s = 7 m/s、×0.1/（cm/s） = ×10/（m/s）、上限 100）。

**B 冲刺消耗（真实循环）**：猫/鼠各按住冲刺 1 s 世界时间：
- 体力下降 ≈ `SprintStaminaPerSecond × 实际经过时间`（±一次结算间隔）；
- **不冲刺时体力不降**（同长度循环，体力只增不减）；
- 冲刺期间**不恢复**（`_time_since_spend` 被持续清零）。

**C 双门控**：
- 体力 = 4（<5）且按住冲刺 → `is_sprinting() == false`，速度 = `walk_speed`（**不是 0，也不停止移动**）；
- 体力 = 6 且按住冲刺 → `is_sprinting() == true`，速度 = `sprint_speed`；
- 从 ≥5 开始冲刺后把体力打到 0 → `is_sprinting()` 变 false、速度回到 `walk_speed`，**位移仍在增加**（保留基础移动）。

**D 耗尽不被卡死**：体力 0 时按住冲刺 + 前进 1 s，位移 ≈ `walk_speed × 时间`（±10%），且仍在地面上。

**E 恢复**：体力打到 20 → 松开冲刺 → `RegenDelay` 内不变 → 之后按 `StaminaRegenPerSecond` 恢复、封顶 `max_stamina`。

**F 警告**：`hunger=25.1` 无警告；`hunger=25.0`（边界，`≤` 成立）与 `24.9` 有警告；`thirst` 同理；两者**相互独立**；
警告状态**不影响生命**（跑 5 s 世界时间后 health 仍是 100）；`warning_changed` 事件在跨越阈值时各发一次。

**G 危机扣血**：`hunger=0, thirst=100` → 跑 10 s 世界时间 → health ≈ 90（扣 10，`TestCases.md` S02 口径）；
`thirst=0` 同理；两项都 0 → 扣 20；扣血期间 `last_damage_reason` 分别是 `starvation/dehydration/exhaustion`；
health 归零 → `died` **恰好一次**且此后不再扣血；`health=50` 且两项都不为 0 → 跑 10 s **不变**（不自动恢复也不掉）。

**H 跌落伤害**：自建高台（**代码生成几何**，不依赖关卡）：
- 落高 0.5 m（落地速度 ≈3.1 m/s < 7）→ **无伤**；
- 落高 3 m（≈7.67 m/s）→ 伤害 ≈ `(7.67−7.0)×10 = 6.7`（±0.5，按实测速度算期望值并打印）；
- 落高很大（≈20 m，速度 > 20 m/s）→ 伤害**封顶**（= `max_health`），且不会出现负血；
- 伤害原因 = `&"fall"`；**平地走动不产生跌落伤害**（0.5 m 平台上下不扣血的那条已覆盖）。

**I 集成/回归**：`AnimalBody` 上"按住冲刺 1 s → 体力下降 + 速度是 sprint"；调试 HUD 的 survival 行仍在；
`l_courtyard.tscn`/`main.tscn` 仍不含调试节点；T002→T014 全量回归绿（**特别注意 T007/T009/T010/T011 的冲刺用例**：
它们都在 1 s 量级，体力 100→85/65，不会触发门控）。

## 8. 失败回退

- 若按世界时间扣体力导致 T009/T010/T011 的冲刺车道失败：先量"该车道实际冲刺时长"，再核对是不是**门控太严**
  （例如误把"继续"也要求 ≥5）；**不允许**为了让旧用例过就删掉门控。
- 若跌落伤害把 T011 的"跳越 0.50 屏障"判成受伤：先确认 0.5 m 落地的实测速度（应 ≈3.1 m/s < 7），
  再查是不是把**水平速度**也算进去了（D6 只算垂直）。
- 若危机扣血让 T014 的断言失败：T014 的断言不允许任何伤害源（`apply_damage` 只由测试调用）；
  若冲突，说明是否把阈值判错的"零"当成了"≤0 即扣"（T015 才允许扣）。
