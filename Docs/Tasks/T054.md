# T054 导入与替换回归

## 1. 目标与不做

**目标**（开发计划 :222）：两种动物与环境资产换新之后做一次**替换回归** —— 动画接线、碰撞、数值契约仍成立，**P1/P2/P3 的路线与战斗仍通过**。

引擎口径澄清：总计划原文写"导入 UE / 动画蓝图"，但本项目**已定 Godot（UE5 路线废止）**，所以本任务的对应物是：
- "动画蓝图" → `AnimalBody` 的片段表与切换口径（`_bind_visual_animation()` + `_update_visual_animation()`）；
- "碰撞校验" → 胶囊半径/高度与 `SpeciesConfig` 一致、视觉节点零碰撞、GLB 内建碰撞为零。

**不做**：
- 不改任何资产/数值（本任务是回归，不是调参）。
- 不做包内复验（T043 打包链）与真人试玩（U01）。
- 不处理 T047/T051 的形变挂账。

## 2. 决策

- **D1 资产层与运行时层分开断言**：glTF 导入的片段**一律 `LOOP_NONE`**；`Idle/Walk/Run` 的循环是 `AnimalBody._bind_visual_animation()` 在运行时改的，一次性片段（`AttackCue` / `Eat`）保持 `LOOP_NONE`。第一版在资产层断言 `LOOP_LINEAR`，产生 6 条**假红**——那不是在验证契约，是在验证自己的误解。
- **D2 视觉换新不得动碰撞**：断言 `capsule_radius/height == SpeciesConfig`，且**隐藏胶囊代理网格**尺寸不变（T009/T013 的 `mesh == capsule` 契约）；视觉子树里必须 0 个 `CollisionShape3D`。
- **D3 贴图缺失要能红灯**：材质解析断言（材质为 null，或 albedo 纹理为空且基色为纯黑）——T049 期间就发生过一次"贴图被误删、导入产物静默引用不存在的 PNG"，靠套件才暴露。
- **D4 数值契约写死在本套件里**：换资产时最容易被顺手改的就是 `attack_telegraph` / `sprint_speed`，这里把 Parameters 的值钉成断言（0.45 / 1.2 / 35 / 0.65 / 1.8 / 4.5 与 1.1 / 3.0）。

## 4. 验收

1. 猫 4 段、鼠 4 段片段齐备；资产层全 `LOOP_NONE`；运行时 `Idle/Walk/Run`=`LOOP_LINEAR`、`AttackCue`/`Eat`=`LOOP_NONE`。
2. 胶囊 0.16/0.48 与 0.06/0.18；代理网格同尺寸；视觉子树 0 碰撞。
3. `assets/characters` 下全部 `.glb` 可加载且带 `.import`；两个视觉场景可实例化、材质可解析。
4. 数值契约不漂移。
5. **P1/P2/P3 路线与战斗套件全绿**（t011/t012/t013×2/t020～t027/t029）。
6. 全量 headless 0 失败、0 INVALID、`visible_hits=0`。

## 5. 失败恢复

- **循环模式红灯**：先分清是资产层还是运行时层——资产层应为 `LOOP_NONE`，运行时才改成 `LOOP_LINEAR`；不要直接改 GLB 的 loop 标记（导出器不保留，且会掩盖绑定逻辑）。
- **胶囊尺寸红灯**：查 `SpeciesConfig` 是否被改，或 `AnimalBody._rebuild_collision()` 是否被绕过；**不要**改断言迁就。
- **贴图/材质红灯**：查导入器是否把内嵌贴图提取成了外部 PNG（`sm_cat_006_*_005.png` 就是这种），文件被删会静默失败。
- **路线/战斗套件红灯**：按失败套件名回到对应任务文档（T011/T012/T020…）的失败恢复节；不要在本任务里改玩法数值。
