# T041 主菜单、继续与新游戏确认

## 1. 目标与不做

**目标**：把 T039 留下的「双坏阻断态」与 T037 的读档结果接进主菜单，让玩家在进入世界前明确选择「继续」或「新游戏」；所有会覆盖旧档的操作都要二次确认，且默认焦点在「取消」。

必须覆盖的玩家可见路径：

| # | 场景 | 玩家看到什么 | 点了之后发生什么 |
|---|---|---|---|
| A | 有存档（正常） | 主菜单同时有「继续」与「新游戏」；无读档提示 | 「继续」按 T037 顺序恢复世界与当前生命；「新游戏」先弹确认，确认后清档并进物种选择 |
| B | 无存档 | 只有「新游戏」，没有「继续」（不显示；禁用方案不采用） | 点「新游戏」直接进物种选择；不会落入空载入路径 |
| C | 存档双坏阻断态（T039 只做了阻断） | 只显示「存档损坏，已隔离；未载入」与「确认开始新游戏」 | 点「确认开始新游戏」才清 `_load_blocked`、允许选物种；未确认前不能退出保存、不能静默开新档 |
| D | 主档损坏、已从备份恢复 | 先显示「主存档损坏，已从备份恢复」，菜单正常 | 「继续」正常恢复；**不**同时弹「新游戏确认」 |
| E | 版本不兼容 | 显示「存档版本不兼容（vN），未载入」；旧档仍在 | 「继续」不可用；「新游戏」需确认；确认后才清旧档；不强制隔离 |
| F | 破坏性操作一般化 | 任何会覆盖旧档的新游戏入口都先弹确认，默认焦点「取消」 | 取消 = 什么都不改；确认 = 清档并开新局 |

**不做**：不改轮回/结算语义（T032/T037）；不改解锁规则（T031/T033）；不改存档格式与校验（T037）；不改 12 m 收敛（T040b）；不做设置页持久化；不做多槽位、云存档、自动备份轮转。

## 2. 必须复证的既有契约

1. **UI 树序** `Hud → MainMenu → LifeStatus → LifeSettlePanel`（T033，结算页最上）。
   T041 新增的 `NewGameConfirm` 必须插在 `MainMenu` 之上、`LifeSettlePanel` 之下：
   `Hud < MainMenu < LifeStatus < NewGameConfirm < LifeSettlePanel`，并写断言。
2. **解锁集语义**：`MainMenu.build(unlocked_ids:=[])` 空数组 = 全部可玩；`MainMenu.set_unlocked([])` = 全锁。不得改。
3. **菜单可见时状态行隐藏**：`_present_menu()` 里 `status_label.visible = false` 的口径不得改。
4. **T039 阻断语义**：`_load_blocked` 期间 `select_species()` 拒绝、`save_now()` 返回 `blocked`、退出不写新档。

## 3. 决策

- **D1 启动不再自动恢复存活生命**。有可恢复存档时停在菜单，由「继续」触发 `_restore_life_from_snapshot()`；世界数据（时间/区域账本/资源/长期层）仍在菜单建立前按 T037 D8 应用，保证菜单解锁集正确。无存档/无当前生命/无待结算时仍直接进物种选择。
- **D2 「继续」可用条件**：读档状态为 `ok`/`recovered_backup`，且快照有 `current_life`（校验后非空）或非空 `pending_settlement_life_id`。否则按钮不显示；`continue_game()` 返回 false，绝不落进空载入。
- **D3 双坏阻断页**：`MainMenu` 进入 blocked view，隐藏继续/新游戏/物种/设置/退出，只留「存档损坏，已隔离；未载入」与「确认开始新游戏」。按钮标签本身即确认；点击后 `MainEntry._start_new_game()` 清 `_load_blocked` 并进入物种页。
- **D4 新游戏确认**：`NewGameConfirm` 为普通 `Control`（不引入 `CanvasLayer`），全屏遮罩拦截鼠标，`取消` 先创建且 `grab_focus()`。按 Esc 取消；按 Enter 触发焦点按钮（默认取消）。确认回调才执行 `SaveManager.clear_slot()` + `GameState.reset_for_new_game()`。
- **D5 何时需要确认**：存在可覆盖槽（主档、备份或已载入快照）或版本不兼容旧档时。无存档时无需确认（没有旧档可覆盖）。
- **D6 版本不兼容不隔离**：只提示并禁用继续；旧主档原样保留，玩家可人工处理。与双坏的差异用 `_load_blocked=false`、菜单正常页、主档仍存在三条断言钉住。
- **D7 备份恢复提示与确认互斥**：启动只显示恢复提示；确认弹层只在玩家主动点「新游戏」后打开。
- **D8 清档范围**：只删主档/备份/写入中间文件（`.tmp`、`.old`、`.bak.tmp`）；`.corrupt-*` 隔离档保留（证据与人工恢复）。
- **D9 新开局数据**：`clear_slot()` → `GameState.reset_for_new_game()` → `_init_region_population()` → `_setup_long_term()`；清空生态 NPC 与展示模型计数，刷新菜单解锁集，进入物种页。

## 4. 数据与事件

- 无新存档字段；沿用 T037 的 14 键。
- 新增运行时只读状态：`MainMenu._resume_available`、`_blocked_view`、`_blocked_message`、`_session_notice`。
- 日志（证据用）：
  - `ENTRY|continue|ok=...|state=...|life=...`
  - `ENTRY|new_game|blocked_cleared=...|save_cleared=...`
  - `ENTRY|new_game_confirm|open|cancel_focus=...`
- 信号：`MainMenu.resume_requested`、`MainMenu.new_game_requested`；`NewGameConfirm.confirmed`、`NewGameConfirm.cancelled`。

## 6. 用例（`tests/run_t041_main_menu_flow.gd`）

- **A 有存档**：菜单可见、继续+新游戏并存、确认层关闭、状态行隐藏、状态 `selecting` 且无玩家；继续 → `alive`、LifeId 恢复、世界时间恢复；新游戏 → 确认层打开、焦点「取消」、取消后档仍在；确认后档清空、`selecting`、档案 0、继续隐藏。
- **B 无存档**：继续不可见、`continue_game()` false、无玩家；新游戏不弹确认直接进物种页。
- **C 双坏**：`_load_blocked=true`、blocked view、提示逐字、继续不可用、`select_species` 拒绝、`save_now` = blocked、主档不存在；确认新游戏后 `_load_blocked=false`、可 `select_species` 并进入 `alive`。
- **D 备份恢复**：状态 `recovered_backup`、提示逐字、继续可用、确认层关闭、继续 → `alive`。
- **E 版本不兼容**：状态 `version_mismatch`、提示含 `（vN）`、主档仍存在、无 `_load_blocked`、blocked view 关闭、继续不可用；新游戏弹确认，取消后旧档仍在，确认后清档。
- **F 契约**：树序断言；`build([])` 全解锁、`set_unlocked([])` 全锁；确认默认焦点「取消」。

## 7. 失败恢复

- 确认层打开后任何路径都要保证 `menu.set_input_locked(false)`；`NewGameConfirm.close()` 幂等。
- `_start_new_game()` 若 `SaveManager.clear_slot()` 或 `GameState.reset_for_new_game()` 缺失，只记录错误并保持菜单可用，不半清档后静默开局。
- 阻断态下退出/保存仍走 T039 门；不得因 T041 改动回退。
