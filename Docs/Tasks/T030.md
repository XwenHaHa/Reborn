# T030 生命周期状态与事件记录

- 归属阶段：P4 轮回（实现前置：P3 已收口）
- 硬依赖：T022（临时重开语义）、T027（生态与生命体命名）、T018（HUD）
- 预估：4–8 h
- 计划来源：`轮生_Reborn_开发计划_v1.0.md:164`
- 设计来源：`Docs/TechnicalDesign.md` §1（文件职责表）、§7（生命周期与事务）；`轮生_Reborn_游戏策划案_v1.1.md` §9.2–9.5、§10

## 1 目标（可验收的一句话）

正式入口存在一条**唯一权威**的生命周期链：存活 → 结算 → 选物种 → 出生 → 存活；每一世有稳定的 `LifeId`、**恰好一次**的死亡结算、可查询的结束原因与事件记录；结算与选物种期间世界时间停止、玩家输入失效、不留下尸体、不改变长期数据。

## 3 关键决策

- **D1 记录与实例分离**：`LifeCycle` 只做状态与编排，不创建角色；角色由 `MainEntry` 在 `spawn_requested` 后创建并回呼 `mark_spawned()`。这样状态机可在无渲染、无关卡的环境里单测。
- **D2 唯一权威**：生命档案、事件、解锁物种只存 `GameState`（TD §1）。`LifeCycle` 不复制存储，只调用。
- **D3 `LifeId` 格式** `L%04d`，单调递增、永不复用；只有显式新游戏（`reset_for_new_game()`）才归零。持久化属 T037。
- **D4 `test_mode`**：`GameState.test_mode=false` 时只允许已解锁物种；`true` 时两种都可选（策划 §9.2 的开发便利）。默认解锁集由 `MainEntry` 显式写入（正式：猫未解锁→先鼠；测试：全解锁）。
- **D5 死亡冻结输入**：结算时置 `player_controlled=false`、清空移动/冲刺/跳跃/交互/扑击意向、取消交互；不生成尸体、不产生食物、不减少 NPC 计数。
- **D6 事件记录**：条目 `{seq, life_id, kind, world_time, data}`，`seq` 全局单调；`MAX_EVENTS=1024` 封顶（超出丢最旧）。档案引用 `event_first/event_last`。
- **D7 时间冻结**：`SETTLING`/`SELECTING` 期间 `WorldDirector.time_advancing=false`，回到 `ALIVE` 恢复；世界时间与档案都**不**清零。
- **D8 正式场景最小化**：`main.tscn` 只含一个 `Node3D` + 脚本；关卡/HUD/生命周期/提示文本全部运行期构建，保证既有的"无调试节点、无 CanvasLayer、无调试字样"断言继续成立。

## 4 状态机与迁移表

`State = { ALIVE=0, SETTLING=1, SELECTING=2, SPAWNING=3 }`，初值 `SETTLING`（"结算"一个尚不存在的生命，语义为空操作）。

| 当前 | 调用 | 目标 | 副作用 |
| --- | --- | --- | --- |
| SETTLING | `request_select()` | SELECTING | 时间冻结保持；无档案 |
| SELECTING | `begin_spawn(species)` | SPAWNING | 校验物种（存在配置 + 已解锁或 `test_mode`），发 `spawn_requested` |
| SPAWNING | `mark_spawned(body, pos)` | ALIVE | `GameState.begin_life()` 生成 `LifeId` 与档案；时间恢复；输入恢复 |
| ALIVE | `end_life(reason, detail)` | SETTLING | `GameState.end_life()` 落一次档案；冻结输入与时间；释放身体 |
| 其它 | 任意 | — | 拒绝：`push_warning()` + `transition_rejected` + 事件 `transition_reject` |

拒绝必须**不改变状态、不写档案、不写 `LifeId`**。

## 5 数据字段

生命档案（策划 §9.5 的字段全覆盖）：

```
life_id, species_id, start_world_time, end_world_time, duration,
end_reason, damage_reason, start_position,
captures, escapes, food_gained, water_gained, discoveries([String]),
event_first, event_last, snapshot{health,hunger,thirst,stamina}
```

## 6 用例（`tests/run_t030_lifecycle.gd`）

A 契约：脚本/类存在；枚举值；`GameState` autoload 可解析；`MAX_EVENTS`；`LifeId` 格式。
B 状态机：迁移表正面路径；四类非法迁移被拒且状态不变；拒绝记录可查。
C 物种门：未解锁拒绝；`unlock_species()` 后允许；`test_mode` 放行；未知物种（无配置）拒绝。
D 死亡只结算一次：连续 `end_life()` ×3 + 反复 `apply_damage` → 档案 1 条、`life_ended` 1 次、`LifeId` 不再变。
E 档案字段：`duration = end - start`；`end_reason` / `damage_reason` 正确；`snapshot` 含四项。
F 事件：`seq` 单调、`events_for(life_id)` 只含本世、跨世事件保留、`MAX_EVENTS` 封顶。
G 长期数据：新一世不重置世界时间、归档不清空、解锁集保留。
H 正式入口集成：`main.tscn` 无调试节点/无 CanvasLayer/无调试字样；进入后 `ALIVE`；杀死玩家 → `SETTLING` 且恰好 1 条档案；选物种 → 新 `LifeId` 且不同、世界时间未归零；玩家死亡后输入意向被清空。
I 无尸体与生态计数：结算前后 `npc_count()` 不变，玩家节点不在树中，场景内无新增尸体/食物节点。

## 7 失败恢复

- 若 `--import` 后 `GameState` 未注册：检查 `project.godot` `[autoload]` 段落顺序（`WorldDirector` 在前）。
- 若既有 26 套回归因 `main.tscn` 改写失败：先跑 `run_t013/t018/t026` 定位，按断言修正运行期构建（不改断言）。
- 若测试出现 `MainEntry` 重复 `_ready` 或节点重名：沿用 T022 的"先改名再 `queue_free()`"手法。
- 同一失败最多两次有依据的修复尝试；无新诊断不重试。
