# T043 存档测试矩阵与打包

## 1. 目标与不做

**目标**：把 T037～T042 的存档行为收束成一张**可重复运行的矩阵**（场景 × 触发时机 × 期望结果 × 断言来源），补齐矩阵暴露的缺口，并给 P5 阶段门一次真正的发行包验收：两预设导出、发行包不弹控制台、`user://` 落点、包内无测试/文档/取证脚本、许可清单可随包交代。

| # | 场景 | 期望 |
|---|---|---|
| A | 落盘时机 | 死亡归档、发现、解锁、退出各写一次；暂停零写入；主动结束 `player_quit` 走死亡链路 |
| B | 损坏与恢复 | 主档坏 / 主档缺 / 双坏 / 版本不兼容 / 缺字段与非法值修复；`revision` 单调 |
| C | 强杀窗口 | tmp 前/中、换入时、写 `.bak` 时四个时点都不产生“半档” |
| D | 往返完整性 | 世界时间、区域、资源、档案/事件、发现/解锁、计数器、当前生命逐字段回读 |
| E | 跨世连续性 | 死亡→重生不重置世界时间；发现去重；解锁永久；`life_counter` 递增 |
| F | 边界 | 空档首启；连续多世；`SETTLING/SELECTING` 期间请求保存；`active>total` + 12 m 不退场 |

**不做**：不改存档 14 键格式、不改 `save_version`、不改 `revision`/`pending`/队列语义；不新增安全点字段；不发布、不推送。

## 2. 必须复证的既有契约

1. `SaveManager` 仍是唯写入方：`tmp → .bak → 主档换名`，成功才 `revision+1`；失败不得半写。
2. 关键写（死亡/结算清空/发现/解锁/退出）立即同步；普通写帧驱动节流；单写守卫 `max_active_writes<=1`。
3. `pending_settlement_life_id` 只指向档案里存在的生命；与 `current_life` 互斥。
4. 双坏隔离 `.corrupt-*` 不删除；版本不兼容旧档保留；阻断期间退出不写新档。
5. T042 暂停层不改存档、不写盘；暂停期间队列随树暂停停摆。
6. 包内发布预设排除 `tests/*`；SelfTest 保留 `tests/*` 供包内断言。

## 3. 决策

- **D1 矩阵以现有套件为断言来源**。不重写 T037/T038/T039/T040/T040b/T041/T042，只新增 `run_t043_save_matrix.gd` 补缺口（资源 `next_refill_at/expire_at`、区域 `next_recover_at` 往返、`revision` 严格递增链、跨世世界时间连续、`SETTLING/SELECTING` 期保存）。
- **D2 发布预设关闭控制台包装**：`preset.0` 的 `debug/export_console_wrapper` 由 `2` 改 `0`，发行版只产出 GUI exe；`preset.1` 保留 `2` 以便包内断言捕获 stdout。
- **D3 包内泄露用 PCK 清单审计**：新增 `Tools/t043_pck_audit.py` 解析 `.pck` 目录项，断言发行包不含 `tests/`、`references/`、`Docs/`、`.uid`、`tool_capture_*`、`tool_make_*`。二进制不入 git。
- **D4 许可清单随包**：新增 `Tools/t043_package.ps1`，导出两预设、计算 SHA256、调 PCK 审计、并把 `Docs/THIRD_PARTY_ASSETS.md` 的来源/许可/SHA256 摘录写入 `Builds/P0-Win64/THIRD_PARTY_NOTICES.md`。
- **D5 发行包两帧视觉**：用隐藏桌面启动发行 `Reborn.exe`，截「首启菜单」「进入存活后 HUD」两帧；同时枚举窗口，断言无控制台窗口（`ConsoleWindowClass` 不出现）。
- **D6 `user://` 落点记录路径形态**：用 SelfTest 包内脚本打印 `OS.get_user_data_dir()`，把用户名替换成 `<user>` 后写证据；不记录个人路径。

## 6. 用例（`tests/run_t043_save_matrix.gd`）

- **A 往返补齐**：资源 `next_refill_at/expire_at/important` 写出后重载逐字相等；区域 `total_count/next_recover_at` 回读相等（`capacity/recover_interval` 按 T035 D7 仍由配置持有，不往返）。
- **B 修订链**：连续 `manual → death → discovery → unlock → exit` 保存，文件 `revision` 严格每次 +1；加载后不回退。
- **C 跨世**：记录 `world_time/discovered/unlocked/life_counter`，死亡→重生后世界时间不归零、发现无重复、解锁仍在、`life_counter` 递增。
- **D 阶段期保存**：`SETTLING`（结算页呈现）与 `SELECTING` 期间 `save_now` 均 `ok`、`revision` 增加、不产生 `current_life` 脏数据、不崩。
- **E 空档首启**：无主档无备份时 `load_game=none`、`can_continue=false`、菜单不显示继续（引用 T041 B 段）。
- **F 过渡态**：`active>total` 时 12 m 内不退场、`pending_excess>0`、走远后收敛（引用 T040b D 段）。

## 7. 失败恢复

- 导出失败：保留上一版产物，不删除旧包；记录 `EXIT` 与 stderr，不放宽断言。
- PCK 审计失败：列出泄露路径，先修导出过滤再重导；不得用“文件很小”作为通过理由。
- 发行包启动失败：保留窗口枚举与进程退出日志；不以 SelfTest 包通过替代发行包。
- 测试失败：先判断是实现缺口还是夹具缺陷；实现缺口只做最小修复，不改格式。
