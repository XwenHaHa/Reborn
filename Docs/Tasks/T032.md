# T032 生命档案与结算页

- 归属阶段：P4 轮回（T030/T031 已 done）
- 硬依赖：T030（`GameState` 档案/事件 + `LifeCycle` 状态机）、T031（长期发现 + `discovery` 事件 + 正式入口）
- 预估：4–8 h
- 计划来源：`轮生_Reborn_开发计划_v1.0.md:166`「本世时长、发现、捕获/逃脱和真实结束原因；重复伤害不重复生成档案」
- 设计来源：`轮生_Reborn_游戏策划案_v1.1.md` §9.3（生命值归零 → 冻结输入 → 生成**一次**档案 → 结算与物种选择；重复伤害不生成多份档案）、§9.4（生命档案字段：物种、存活时长、发现地点、食物获取、成功捕猎或逃脱、重要事件、结束原因；死亡原因 = 最后伤害来源 + 相关生存状态，**只给系统确实记录的事实**）、§327（必需页面含「死亡结算」）；`Docs/TechnicalDesign.md` §7（SETTLING → SELECTING 只在结算记录已形成后发生；结算/选物种不推进时间）

## 1 目标（可验收的一句话）

玩家死亡后，入口在选物种画面**上方**弹出一页「生命结算」覆盖层：把 `GameState` 刚归档的结算记录按策划 §9.4 字段**照实**呈现（物种、存活时长、发现地点、食物/水获取、捕猎/逃脱、重要事件、结束原因与死亡时生存状态）；确认（Enter / Esc / 点击 / 继续）后关闭、露出选物种画面；重复伤害**只呈现一次**；**不新建任何平行数据结构**（直接读 `life_settled` 档案 + `GameState.events_for()` + snapshot）。

## 3 关键决策

- **D1 覆盖层方案（时序零改动）**：`_on_life_settled` 保持既有流程（`_enter_select()` 照旧），随后把结算面板**盖在已呈现的选物种画面上方**。`run_t030_lifecycle.gd` H19（死后 6 帧 = selecting）、H26（随即 `select_species()` 可用）的契约不动；状态机、`request_select` 时序全部不变。
- **D2 零平行数据结构**：结算页数据 = `life_settled(record)` 的档案字典（`life_id/species_id/duration/end_reason/damage_reason/captures/escapes/food_gained/water_gained/discoveries/snapshot`）+ `GameState.events_for(life_id)`（重要事件计数）+ 物种显示名（`SpeciesConfig.display_title()`，由入口组装）。**不新增 `GameState` 字段、不新增事件 kind、不在面板里另存一份记录**。实测字段全部够用，无就地扩展。
- **D3 只记录事实（策划 §9.4）**：结束原因显示 `end_reason`（`died` → 「死亡」），死亡原因显示 `damage_reason` 原文，生存状态显示 snapshot 的 health/hunger/thirst/stamina **数值**；不编造故事、不推测未记录的死因细节。
- **D4 重复伤害只呈现一次**：`LifeCycle.end_life` 只结算一次（T030 契约），面板随之只 `present` 一次；断言 `present_count() == 1` 且 `archive_count() == 1`（连打三次致死伤害）。
- **D5 纯 `Control`、加在 `menu` 之后**：`run_t030` H8 断言正式场景无 `CanvasLayer` → 面板是普通 `Control`，由入口在 `add_child(menu)` **之后** `add_child`（同一 canvas 后加入者绘制在上）→ 结算页天然盖住菜单（含 MVP 块），**不需要也不去动 ART09 的 z 序遗留**。
- **D6 捕猎计数只作展示**：`captures/escapes` 是档案字段，展示与解锁零连接（T031 已断言固化，不重接线）。
- **D7 输入保护与消隐**：面板可见时消费**全部**按键（`_unhandled_key_input` 中 `set_input_as_handled`），防止按键穿到背后的菜单；确认（`ui_accept` / `ui_cancel` / 点击 scrim / 「继续」按钮）→ dismiss；出生（`spawn_requested`）自动隐藏。既有套件里靠**引擎输入**驱动的（`run_art05_input`）与取证工具在死亡后需显式关闭面板再继续原流程。

## 4 数据 / 事件

```
LifeSettlePanel（纯 UI，无状态持久化）
  present(record: Dictionary, context: Dictionary) -> void
    # record = life_settled 的结算档案（真源 GameState.life_records 末条）
    # context = { "species_titles": {species_id: 显示名},
    #            "event_kinds": {事件 kind: 条数} }   ← 由 MainEntry 从 GameState 组装
  dismiss() -> void
  present_count() -> int          # 断言 D4 用
  is_presenting() -> bool
  summary_text() -> String        # 断言/取证用：面板正文一行拼接

MainEntry（接线）
  var settle_panel: LifeSettlePanel      # 运行期构建，add 在 menu 之后
  func dismiss_settle() -> void          # 测试/取证工具用
  _on_life_settled: 末尾 _present_settle(record)
  _on_spawn_requested: dismiss_settle()
  # 无新事件、无新 GameState 字段、无新存档数据
```

事件：不新增 kind。运行证据只加一行 `print("ENTRY|settle|...")`（不入档案）。

## 6 用例（`tests/run_t032_settle_page.gd`）

- **A 契约**：`LifeSettlePanel` 脚本可加载且 `class_name` 注册；运行期实例 `main.tscn` 后 `entry.settle_panel != null`；面板是 `Control` 且树序在 `MainMenu` **之后**（同父后加入 → 绘制在上）；`_count_class(main, "CanvasLayer") == 0` 仍成立。
- **B 呈现内容**（headless 实例 + test_mode）：出生 → 推进世界时间 → 致死 → 面板可见；`summary_text()` 含 life_id、物种显示名、存活时长、结束原因（died→死亡）、damage_reason、snapshot 四项数值、captures/escapes、food/water、发现地点 ID；面板数据 == `GameState.last_record()`（同一字典内容，无平行副本漂移）；事件计数 context == `events_for(life_id)` 的按 kind 统计。
- **C 确认消隐**：`ui_cancel`（Esc）→ 面板隐藏、菜单仍可见、状态仍是 selecting、世界时间仍冻结；再次死亡（第二世）→ 面板重新可见且内容换成新一世；`ui_accept`（Enter）同样可消隐。
- **D 重复伤害只呈现一次**：连打三次致死伤害 → `present_count() == 1`、`archive_count() == 1`、面板文本不变。
- **E 出生自动隐藏 + 输入保护**：面板可见时 `life_select_1` 按键**不**触发选物种（被面板消费）；dismiss 后再按可正常出生；面板可见期间直接调 `select_species()` 仍可出生（API 不被 UI 拦），出生后面板自动隐藏。
- **F 既有契约**：`run_t030` H 段全绿（时序未变）；`run_t031` 全绿（解锁门不受影响）；档案字段无增删。

## 7 失败恢复

- 若 `run_t030`/`run_t031` 回归失败：先查是否面板可见期间挡了它们的断言路径（状态文字在面板后面但仍存在）；取证工具/输入套件按 §2 表显式 `dismiss_settle()`，**不改生命周期断言语义**。
- 若面板按键消费导致既有非 headless 输入套件挂：只在该套件死亡流程后加显式关闭，不在面板里加"跳过"开关。
- 若 headless 下文本/可见性断言异常（无渲染）：只断节点 `visible`、`text` 属性，不做像素判断；像素判断全部交给 `CaptureRun` + vision.js。
- 同一失败最多两次有依据的修复尝试；无新诊断不重试。
