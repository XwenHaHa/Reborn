## §2 判定口径（四类，写进证据表头）

- **一致**：字段名、类型、单位、语义、可空性全部相同（或只是 `String` ↔ `StringName` 的同值表示，且比较处已 `String()` 归一）。
- **缺失**：契约要求、实现完全没有；且**没有**等价替代物。必须写「最小补丁方案 + 归属任务」。
- **多出**：实现有、契约没有。必须写「来源任务」，并判断是否该补进 TD（本轮只登记，不改 TD 的字段清单）。
- **语义偏移**：字段存在但名字/类型/结构/单位/时序不同；必须写「等价替代是什么、能否无损还原」。

**验收判据**：每个「缺失 / 语义偏移」必须有结论——要么本轮补上并配断言，要么写明替代物 + 归属任务 + 风险。不允许出现「大概是」「应该」这类无结论条目。

## §3 决策

- **D1（范围）**：T036 = 审计 + 契约锁测试 + **一处契约补丁** + **一处审计发现的缺陷修复**（各配断言）；不引入任何存档 I/O。
- **D2（唯一补丁）**：`CurrentLife` 的 `survival` 与 `transform` 在**存活期间**必须可得。现状：`snapshot` 只在死亡时由 `LifeCycle.survival_snapshot()` 写入；位置只存出生点 `start_position`，**没有当前位置**。→ 新增 `GameState.sync_current_life(survival, transform)`，由 `MainEntry._on_survival_changed`（既有 0.2 s 节流回调）驱动。理由：T037 读档要还原「当前生命状态与位置」，没有等价替代；改动是纯写档案，不改玩法、不改消耗、不掉帧（复用既有回调）。
- **D3（命名）**：`snapshot` 保留（等价于契约的 `survival`），**不**再复制一份 `survival` 键（TD §1「禁止两份同时权威的数据」）。证据表记为语义偏移（键名）。
- **D4（`LifeEvent` 结构）**：保留 `{seq, life_id, kind, world_time, data}`；契约的 `event_id/type/source_id/reason/amount` 记为语义偏移，替代物为 `seq/kind/data{...}`。不重构事件结构（会牵动 T030/T031/T032 全部断言）。
- **D5（`source_id`）**：捕获事件的捕食者由 `life_id` 唯一确定，`data` 里已有 `target`；**不**为对称而补 `source`，避免同一事实两份。
- **D6（`WorldSnapshot`）**：整容器缺失（含 `save_version/revision/pending_settlement_life_id`）。按负责人边界**不在本轮建**，最小补丁方案 = T037 的 `SaveManager` 组装（写进证据表与 TD 注释）。
- **D7（`last_safe_spot_id`）**：契约有、实现无（安全点系统属 T042）。记为缺失 + 归属，不伪造。
- **D8（`life_state`）**：状态机在 `LifeCycle`（`ALIVE/SETTLING/SELECTING/SPAWNING`），不入档案。记为语义偏移（替代物 = `life_cycle.state`，T037 组装时现取）。
- **D9（可执行化）**：所有「一致」项写进 `run_t036_contract.gd` 的 A 段（键集合 + 类型 + 单位），一旦有人改字段名/类型会红。
- **D10（跨世回归）**：只验证**数据一致性**（ID 单调唯一、档案不可变、事件引用完整、跨世保留项不被清、重生不重置世界时间与种群），不重复 T030/T033/T035 已覆盖的行为断言。

## §6 用例与变异

**A 契约形状（锁「一致」项）**
- A1 `SurvivalState.to_dictionary()` 恰 5 键且类型正确（4 float + 1 StringName）。
- A2 `RegionRecord` 元素恰 6 键（String/String/int/int/float/float），容量与间隔来自配置。
- A3 `ResourceRecord` 恰 10 键（含 `Transform3D`、`expire_at`）。
- A4 事件条目恰 5 键（int / String / String / float / Dictionary）。
- A5 `SpeciesConfig` 契约字段齐（25 项逐一点名存在）。
- A6 `LifeRecord` 归档键齐（17 键）。
- A7 `CurrentLife` 契约字段可得（`life_id/species_id/start_world_time/snapshot/transform/discoveries/event_first/event_last`）。

**B 稳定 ID**
- B1 `LifeId` 格式 `L%04d`；B2 三世间递增且不复用；B3 区域键 `region|species` 集跨重生不变；
- B4 资源 `interaction_id` 非空且全局唯一；B5 地点发现 ID 去重且列表稳定。

## §7 失败恢复

- 首跑红不崩：所有新 API 走 `call()/get()` + 段首守卫，未实现时该段只出一条红。
- 断言与现状冲突时**先查是谁的定义漂移**：若实现更合理（如 `food_gained` 是「累计增益」而非「次数」），记语义偏移并保留实现，不反向改实现去凑契约字面。
- 批量套件缺失/异常必须逐条记录，不静默跳过。
- 补丁若引起既有套件红：优先回退补丁并记录，不以改断言的方式掩盖。
