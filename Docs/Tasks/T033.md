## 1 目标（可验收的一句话）

正式模式下，物种选择界面按解锁状态呈现所有已实现物种：未解锁物种显示为**锁定卡**（可见、压暗、「尚未解锁」、点击/数字键有明确文字反馈，不改变选中）；**发现→解锁**发生时菜单即时刷新、HUD 弹出可读提示；ART09 遗留的「MVP 说明块遮挡状态文字」修复——状态文字与菜单同帧可见时**逐字可读**，且 `LifeSettlePanel` 仍绘制在最上（T032 A9 不回归）；入口与菜单**零物种名特判**（解锁信息全部来自 `SpeciesConfig`/`GameState`）。

## 3 关键决策

- **D1 层序修复（ART09 遗留）**：`_ready` 构建顺序从 `hud → status → menu → settle` 改为 `hud → menu → status → settle`——`LifeStatus`（状态文字）绘制在 `MainMenu` 之上（遮挡根因 = menu 后加入画在其上），`LifeSettlePanel` 仍最后加入、绘制在最上（T032 A9「settle index > menu index」继续成立）。**同时**把 `MvpNote` 下移（`offset_top` 34 → 84）：状态文字两行（y≈12–64）与 MVP 块（原 y≈34 起、宽 300px 压到画面中线）不再相交，两层文字互不压字。
- **D2 锁定呈现（数据驱动）**：`MainMenu.build(configs, settings, unlocked_ids := [])`——**空数组 = 全部可玩**（回退兼容：不传解锁信息的调用方与既有 UI 套件/取证工具语义不变）；`set_unlocked(ids)` 为**显式**调用（空 = 全锁）。锁定卡与可玩卡**同构**（`Card_<id>` / `Thumb_<id>` / `Tagline` / `Note` 齐全——`run_art09_menu_contract` 的卡契约不破），差异 = 整卡压暗（modulate）+ Tagline「尚未解锁」+ Note 解锁提示 + 点击反馈；真实显示名保留（玩家知道有什么可解锁，与 MVP 说明「猫 / 鼠」一致，不保密）。
- **D3 选择门只在 UI 呈现层收紧**：出生权威门仍是 `LifeCycle.begin_spawn`（T031 契约 `REJECT_LOCKED_SPECIES`）。`menu.select_species(id)` 对锁定物种返回 `false` 并给出文字反馈（底部 hint 行 + `last_lock_feedback()` 供断言），选中不改变；数字键对锁定物种同样只反馈。**入口零改动**：`selectable_slots()` / `_setup_long_term` 已数据驱动（无物种名），不写任何 `"Cat"`/`"Mouse"` 特判。
- **D4 解锁即时刷新**：`MainEntry` 连接 `GameState.species_unlocked` → `menu.set_unlocked(当前解锁集)` + Toast + `_refresh_status()`。发现提示走 `GameState.place_discovered`（比 DiscoveryTracker 信号更全：测试/工具直接调 `gs.record_place_discovery()` 也生效）。**T031 约束不重写**：死亡不取消解锁、捕猎计数与解锁零耦合由 `run_t031_discovery` 回归 + 本套件 F 段复证。
- **D5 Toast 最小可读版**：`PlayerHud` 新增顶部居中金色 Label（16px + 黑描边），`show_toast(text, duration := 4.0)` 后由 `_process` 按毫秒截止时间隐藏；无动画、无声音、无弹窗（策划未强制，不做大奖演出）。解锁文案 =「新物种已解锁：<`SpeciesConfig.display_title()`>」；发现文案 =「发现新地点：<稳定 ID>」（地点无配置化显示名，照实显示稳定 ID，不编名字）。`hud_text()` 契约不动（Toast 不混入 T018 断言口径）。
- **D6 重生整备断言（开发计划原文收口）**：`LifeCycle._release_body()` 已实现改名+释放；本任务在两世之后断言：关卡内 `Player` 直属节点恰好 1 个、无 `*_retired` 残留节点、`DiscoveryTracker.player` 指向新身体——"无旧 Pawn 或计时器残留"以可断言形式固化。
- **D7 headless 能力门（既有）**：鼠标点击类验证（锁定卡点击反馈）headless 无 GUI 命中，放非 headless 套件或以 `gui_input` 闭包等价断言；如实记录，不造假。

## 4 数据 / 事件

```
MainMenu（新增 API；既有信号/方法签名不变，select_species 返回值 void → bool）
  build(configs, initial_settings, unlocked_ids: Array = []) -> void   # 空 unlocked_ids = 全可玩（回退兼容）
  set_unlocked(ids: Array) -> void          # 显式覆盖；空 = 全锁
  is_locked(species_id) -> bool
  locked_list() -> Array[StringName]        # 排序
  last_lock_feedback() -> String           # 最近一次锁定反馈（断言用）
  select_species(id) -> bool                # 锁定：反馈并返回 false，选中不变

PlayerHud（Toast）
  show_toast(text: String, duration := 4.0) -> void
  toast_text() -> String
  toast_visible() -> bool                   # _process 超时自动隐藏

MainEntry（接线）
  _ready: _build_menu() → _build_status() → _build_settle_panel()   # D1 层序
  _build_menu: menu.build(_configs, current_settings(), _unlocked_ids())
  _wire_gamestate_signals(): gs.species_unlocked → _on_species_unlocked
                             gs.place_discovered   → _on_place_discovered_toast
  _on_species_unlocked(id): menu.set_unlocked(...) + hud.show_toast("新物种已解锁：<显示名>") + _refresh_status()
  _on_place_discovered_toast(pid): hud.show_toast("发现新地点：<pid>")
  # 无新 GameState 字段、无新事件 kind、无新存档数据
```

事件：不新增 kind。运行证据加 `print("ENTRY|unlock|...")`（不入档案）。

## 6 用例（`tests/run_t033_formal_species.gd`）

- **A 契约**：`MainMenu`/`PlayerHud` 新 API 齐备；层序 `menu.index < LifeStatus.index < settle.index`；`_count_class(main,"CanvasLayer")==0`；1280×720 下 `MvpNote` 与状态 Label 的全局矩形**不相交**。
- **B 正式锁定呈现**（`test_mode=false`）：`locked_list()` == 恰好「`initially_unlocked=false` 的物种」（数据推导，不写物种名）；锁定卡 `Card_<id>` 存在且 `Tagline == 尚未解锁`；默认选中 = 第一个已解锁物种；`menu.select_species(锁定)` → false、选中不变、`last_lock_feedback()` 含该物种显示名与「尚未解锁」；`entry.select_species(锁定)` 仍被 lifecycle 拒绝（rejections 记录）。
- **C 解锁链与刷新**（真实路径）：正式模式出生初始物种 → 挪到鼠洞发现半径 → 扫描触发 `record_place_discovery` → Toast 可见且含「已解锁」与显示名；`menu.locked_list()` 清空；`menu.select_species(原锁定物种)` → true；死亡后 `locked_list()` 仍为空（死亡不取消解锁）。
- **D z 序与遮挡几何**：A3 层序断言 + `MvpNote` 矩形与状态文字矩形不相交（两层同帧可见时互不压字；逐字可读性由 vision 判读兜底）。
- **E Toast 契约**：`show_toast("X")` → `toast_visible()` 且文本逐字相等；短时长后自动隐藏；空文本直接隐藏；`hud_text()` 不含 Toast（T018 契约不破）。
- **F 重生整备与 T031 约束**：两世后关卡内 `Player` 恰好 1 个、无 `*_retired` 节点残留、`discovery.player` 指向当前身体；解锁发生时 `captures == 0`（捕猎与解锁零耦合复证）。
- **变异校验（4 处，每处必须红）**：①`select_species` 去掉锁定门 → B 红；②`_on_species_unlocked` 不刷菜单 → C 红；③`_ready` 层序改回 status 在 menu 前 → A/D 红；④Toast 去掉超时隐藏 → E 红。

## 7 失败恢复

- 若 `run_art09_*` 套件因锁定门红：先分清「布局契约」还是「解锁门语义」——布局/取景类套件开 `test_mode` 或显式 `set_unlocked`，**不放宽锁定门本身**。
- 若 T031/T032 回归红：优先怀疑层序改动（D1）——`LifeSettlePanel` 必须仍最后加入；不动 `LifeCycle` 与 `GameState` 的任何语义。
- 若 headless 下 Toast 时序断言抖动：只断言 `visible`/`text` 属性与毫秒截止逻辑，把像素/可读性判断全部交给 `CaptureRun` + vision.js。
- 同一失败最多两次有依据的修复尝试；无新诊断不重试。
