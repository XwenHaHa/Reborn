# T058 安全休息与快进

> **状态：in-progress（2026-11-11）** —— 目标路径、数据、步骤、用例、失败恢复先落文档，再动代码（AGENTS.md 执行循环第 4 条）。

## 1. 目标与不做

**目标**（开发计划 :250）：**安全休息与快进** —— 追逐中拒绝、资源不足提前提示；**时间、生存消耗、资源与种群恢复一致**。

真源：

- `Docs/Parameters.md:81`：**「休息：推进 60 sim seconds，Health 恢复 10；Hunger/Thirst 照常扣，预计休息后任一 ≤0 或正在警戒/追逐则拒绝。资源/种群结算所有经过的恢复周期并夹紧容量，NextRefillAt 更新到未来，不能只恢复一次造成时间错误。」**
- 策划 v1.1 :297：休息可快进固定时长，**受限于安全地点和剩余资源**，不能在追逐或警戒中使用。
- 策划 v1.1 :299：休息期间生存消耗和资源恢复按快进时长结算；**资源不足提前拒绝并提示原因，不让玩家在不可操作的快进中无预警死亡**。
- 策划 v1.1 :129/:132：休息是**交互**（与进食/饮水同属交互目标，冲突按视线+距离解决）。
- 策划 v1.1 :305：自动存档节点包含**安全休息完成**。

开工前状态：项目里**没有休息、没有时间快进入口**（`WorldDirector.set_world_time` 只有测试/读档在用）；
`SurvivalController.restore_health()` 的头注写着"安全休息用"，但**没有任何调用方**。

**不做**：

- 不做睡眠动画/躺姿、不做休息中的相机或过场（表现层留 P6）。
- 不做"安全点系统"（`last_safe_spot_id` 仍按 T042 挂账：需要先定义安全点判定）。本任务的"安全地点"用**最小可判定口径**：休息只在**休息点交互**上发生（第 2 节的 `RestPoint`），没有交互点的地方不能休息。
- 不改 `world_time` 的推进口径（仍是 T043a 的 `GameClock` 单一时钟）、不改存档格式/`save_version`/`revision` 语义。
- 不给"休息回复体力"或"休息回满生命"这类新数值（`Parameters.md` 只允许 +10）。

## 2. 决策

- **D1 休息 = 一次原子事务，不是逐步动画。** 60 sim seconds 是**权威时间跳变**（与读档 `set_world_time` 同一口径），
  所以"快进后资源只结算一次"这类时间错误在本设计里不可能出现：`ResourcePoint.advance_to()` 与
  `WorldDirector.region_population_advance_to()` 本来就是"多周期一次结算 + 夹紧容量 + `next_*_at` 前移"（T017/T035 契约）。
- **D2 拒绝判定与预测用同一套数学。** 预测"休息后 Hunger/Thirst"直接用物种配置的 `hunger_loss_per_sec / thirst_loss_per_sec × 60`，
  **不真的推进时间**再回滚（回滚会污染 `last_world_time` 与账本）。
- **D3 危险判定复用既有语义，不新增 AI 状态。** 只看 `AnimalBody.ai.state_id()` 是否属于 `{alert, approach, chase, search, attack}`
  且距离 ≤ `DANGER_RADIUS`；玩家自己必须处于 `ACT.IDLE`（扑击/攻击/交互/恢复期都不许休息）。
- **D4 休息点走交互系统。** 新 `RestPoint extends Interactable`，`_action_id() = &"rest"`、`interaction_duration = 1.0 s`
  （进食 1.5 / 饮水 2.0 之间留档，避免一按同时进食与休息——策划 :132）。
- **D5 位置用运行时挂载，不改关卡几何。** 关卡只有标记、交互体一律运行期建立（与 T017/T034 的资源点同一做法），
  因此**不重生成 `l_courtyard.tscn`、不重烤导航**，T011/T012 结构断言零影响。
- **D6 结算顺序固定**：先推进世界时间 → 生存按时间结算（含危机伤害）→ `restore_health(+10)` → 资源点与种群结算到新时间 → 存档。
  "先扣后加"保证 `+10` 不会被自伤抵消成负数、也不会在 `hunger≤0` 时用回血掩盖饥饿。
- **D7 完成即触发自动存档**（策划 :305），走既有 `save_now(&"rest")`（T037/T038 的队列与原子写不动）。

## 4. 用例（验收）

1. **正常休息**：世界时间 **+60.000 s**（逐位）、`Health +10`（夹紧 `max_health`）、Hunger/Thirst 各按 `rate×60` 下降。
2. **一致性**：同一夹具下"自然推进 60 s 世界时间"与"休息快进 60 s"的生存/资源/种群结果**逐项相同**
   （证明快进没有走另一套账）。
3. **追逐/警戒中拒绝**：NPC 处于 `chase`/`alert` 等状态且 ≤ 危险半径 → `reason=in_danger`，
   世界时间、生存四项、资源点 units、种群 `total` **全部零变化**。
4. **资源不足提前提示**：预测休息后 Hunger 或 Thirst ≤ 0 → `reason=insufficient_resources`，
   并且 `predicted` 里给出具体预测值（HUD 用它提示），**同样零变化**。
5. **资源与种群按经过周期结算**：容量夹紧、`next_refill_at` / `next_recover_at` 前移到未来（不是"只恢复一次"）。
6. **暂停/门闩**：`time_advancing=false`（暂停）时拒绝（`reason=not_advancing`），零变化。
7. **幂等**：同一 `transaction_id` 重复提交只结算一次（基类 `_transactions` 契约）；
   `interaction_id` 稳定可存档。
8. **相位跟随**：休息跨越昼夜边界后，`DayNightDirector` 下一帧采样 = 新时间的纯函数值（无状态恢复口径）。
9. 全量 headless 0 失败、`invalid=0`、`visible_hits=0`。

## 5. 失败恢复

- **`Identifier not found: RestDirector`**：`--script` 下不要直接写 autoload 单例名，用 `get_node_or_null("/root/RestDirector")`（T056 教训）。
- **休息后生存数值"没扣"**：多半是 `SurvivalController.last_world_time` 还没对齐（首次 `tick_to` 只对齐）——夹具要先跑一帧物理。
- **资源点 double-settle**：`advance_to()` 自带 `_last_world_time` 门，重复调用是 no-op；若见到双倍恢复，先查是不是夹具自己又调了一次。
- **世界时间跳变把 NPC 卡住**：本任务只推时间、不推 AI 帧；NPC 行为在下一物理帧继续，**不要**在休息里循环 `await`。
- **画面取证**：一律走 `Tools/CaptureRun.ps1`（隐藏桌面 + GUI exe），**不要**直接 `& godot_console.exe`——它会在负责人桌面弹窗。
