## 3. 数据契约（新增/扩展）

### 3.1 `DebugEntry`（`scripts/debug/debug_entry.gd`）
```gdscript
const ACTION_RESTART := "debug_restart"          # project.godot: F6 = 4194337
signal round_restarted(index: int)               # 重开完成（新一局就绪）
var restart_count := 0                           # 重开次数（测试读）
func restart_round(reason: StringName = &"manual") -> int   # 返回重开后的 restart_count
```
`restart_round()` 语义（顺序固定）：
1. `_release_player()`：释放旧玩家与旧 `main_agent`（`queue_free`）。
2. 旧关卡实例整体释放（`level.queue_free()`）→ 关卡子树里的旧身体、资源点、捕获食物一并消失。
3. `WorldDirector.reset_for_new_game()`：`world_time` 归零、捕获账本/捕获食物/`captured_target_ids` 清空。
4. `_build_level()` 重建关卡实例（导航随之重建）。
5. 按 `current_species`（空则 `start_species`/配置池第一个）重新 `switch_species()`。
6. `restart_count += 1`、`round_restarted.emit(restart_count)`、HUD 刷新；`print("DBG|restart_round|...")`。
`_unhandled_input()` 增加 `debug_restart` 分支（无其他行为变更）。
HUD：`hud_text()` 在 `is_dead()` 时追加一行提示（如 `提示：F6 重开`），非死亡态不显示。
**重开后的失效实例防线（本轮实测缺陷，见 Evidence §6）**：`InteractionDetector.current_target()` 对**已释放目标**先清空再返回 `null`；
`_resource_for_display()` / `_resource_units()` 用 `is_instance_valid()` 跳过失效实例 —— 否则重开后每次 HUD 刷新都会打脚本错误。

### 3.2 `project.godot`
新增输入动作 `debug_restart` → `InputEventKey` keycode **4194337（F6）**（与既有 F1～F5 调试键并列）。

### 3.3 测试侧契约（不改产品代码）
- 循环主干在真实关卡上**自建身体**（与 T019/T020/T021 的 H 段同模型）：关卡只提供几何与标记。
- 食物/水按 `supply_points` 标记实例化 `scenes/world/resource_point.tscn`（关卡内**没有**现成 `ResourcePoint` 实例）。
- 猫捕猎对象：按 `spawn_points["Mouse"]` 生成的鼠身体，`ai_enabled = false`（AI 会抢 `move_intent`）。

## 4. 行为决策

| # | 决策 | 理由 |

| D1 | 循环主干走真实关卡，不新建专用场景 | 阶段门要求"猫可连续尝试捕猎"，必须在真关卡几何/标记上成立 |

## 5. 验收断言（`tests/run_t022_loop.gd`）——**实测 168 项全 PASS**（A 45 / B 27 / C 11 / D 15 / E 40 / F 27）

### A 循环主干（真实关卡，≥ 18 项）
- A1 关卡 `l_courtyard.tscn` 加载成功且根为 `Node3D`
- A2 `spawn_points`：含 `Cat` 与 `Mouse`，且都在关卡子树内
- A3 猫/鼠在出生点落地（`is_on_floor()`）
- A4 `supply_points`：猫食物 / 鼠食物 / 水源标记存在，水源为无限水（`infinite`）
- A5 按标记实例化的 `ResourcePoint` 进入 `resource_points` 组、且有可用单位
- A6 探索：猫移动后水平位移 > 0，且感知能发现猎物（距离/可见口径）
- A7 扑击启动返回 `true`，且立刻扣一次体力（差值）
- A8 捕获结算：`cat.captures == 1`、猎物 `captured == true`、`capture_count` 与 `capture_food_count` 各 +1
- A9 捕获食物已生成且与猎物位置重合（≤ 0.60 m）
- A10 进食捕获食物后 `hunger` 上升（差值 > 0），单位 1 → 0
- A11 饮水后 `thirst` 上升（差值 > 0），水源单位不减（无限）
- A12 再次探索：可再次移动（位移 > 0）且再次 `request_pounce()` 成功（循环闭合）
- A13 `WorldDirector.world_time` 全程单调不减且终点 > 起点
- A14 全程无 `push_error` 级脚本错误（用退出码 + 断言汇总判定）

### B 连按与重复请求（≥ 8 项）
- B1 连续 10 帧 `request_pounce()`：只启动一次、`pounce_count` 只 +1
- B2 扑击中继续连按：被拒 `busy`/`pouncing`，不重复扣体力
- B3 恢复期内连按：被拒 `recovering`
- B4 连按跳跃：不产生额外纵向位移（扑击期间禁跳）
- B5 交互连按：只结算一次（`consumed_count` +1 而非 +N）
- B6 重复上报同一猎物：`try_capture()` 第二次返回 `false` 且账本不再增长（T021 幂等口径）

### C 体力耗尽（≥ 6 项）
- C1 `stamina` 置 0 后 `request_pounce()` 被拒，原因为 `stamina`
- C2 被拒时猫不产生水平位移（不传送、不滑行）
- C3 被拒时不进入恢复态（`is_recovering() == false`）
- C4 被拒时 `pounce_count` 不变
- C5 体力归零后冲刺不加速（速度 ≤ 步行上限）
- C6 体力恢复到 ≥ 代价后可再次扑击（差值断言）

### D 寻路失败回退（≥ 6 项）
- D1 目标不可达（无导航面/出界）时 AI 不永久停留在寻路状态
- D2 1 s 世界时间内回退出直接移动（必须有一次水平位移或明确的 `blocked` 原因）
- D3 连续 3 次失败后放弃重选，不再产生新的路径查询
- D4 回退期间不报错、不冻结帧（帧推进正常）
- D5 目标重新可达后恢复导航（新路径点数 > 0）
- D6 回退不改变世界账本（`capture_count` 不变）

### E 死亡与临时重开（≥ 12 项）
- E1 致死后 `died` 信号只发一次（信号计数 == 1）
- E2 `is_dead()` 为真、动作态为 `dead`
- E3 死后 `request_pounce()` 被拒
- E4 死后交互被拒（`try_interact()` 返回 `success == false`、`reason == "dead"`），且 `action_state_name() == "dead"`
- E5 `restart_round()` 返回递增的 `restart_count`
- E6 重开后 `world_time` 归零（≤ 0.5）
- E7 重开后 `capture_count` / `capture_food_count` 归零、`captured_target_ids` 为空
- E8 旧玩家/旧关卡实例已释放（`is_instance_valid()` 为假）
- E9 新一局玩家存在、非死亡、落地、物种不变
- E10 新一局可再次完整循环（再次捕猎成功：`captures == 1`）
- E11 无残留：`spawn_points` 数量不翻倍、无重复 `Player` 节点、组内无陈旧身体
- E12 重开可重复执行 ≥ 2 次且结果一致
- E13 **已释放目标不泄漏**（本轮缺陷回归）：重开后 `current_target()` 为 `null`、`resource_line()` 为 `resource: <none>`、`hud_text()` 含该行

### F 入口与打包契约（≥ 8 项）

- F2 `project.godot` 中 `debug_restart` 存在且键码为 4194337（F6）

- F4 `restart_round()` 在非死亡态也可调用且不破坏状态（调试工具语义）
- F5 `main.tscn` / `l_courtyard.tscn` 内无 `/debug/` 脚本节点（T013 口径）

- F7 死亡态 HUD 文本含重开提示；非死亡态不含

## 8. 回退与失败恢复

- **重开实现不稳定**（重建关卡时导航未烘/出生点重复/两关卡瞬时并存）：回退为"原地重置"——保留关卡实例，只清玩家、资源点、捕获食物与账本，再重建玩家；断言集合不变，Evidence 记录改口径的理由与实测差异。
- **真实关卡上无法稳定制造不可达**（导航覆盖全区域）：D 段改用测试夹具"有地板但导航为空"的区域（T019 口径），并在 Evidence 注明"夹具不可达，非真关卡"，不改断言意图。
- **多帧无头环境下世界时间推进过慢**：沿用 `_run_seconds()` 真实时钟兜底（T021 已实测）。
- 同一失败最多两次有依据修复；无新诊断不上第三次。
- 任何弃用断言/放宽规格的动作都必须在 Evidence §7 显式记录，禁止静默放宽。
