## 1. 目标

把"两个物种差在哪"**集中到一处数据**，并给出一个**由配置驱动**的最小身体，使 T009（猫移动）/T010（鼠移动）只写一套代码、靠配置区分：

> 1) `SpeciesConfig` 资源类 + `cat.tres` / `mouse.tres` 两个实例，字段值与 `Parameters.md` 逐项一致（厘米→米）；
> 2) 最小身体 `AnimalBody`：胶囊尺寸、相机偏移、FOV、碰撞层、**台阶上限**全部**从配置读**；
> 3) 配置里的 `max_step_height` 真的接到已实测的 `StepClimb` 组件上，并且**用物理实测**证明
>    猫能上 12 cm / 上不了 20 cm、鼠能上 3 cm / 上不了 12 cm；
> 4) **不散落物种名称判断**：身体与台阶组件源码里不出现物种名字面量分支（可静态检查）。

## 6. 逐步实现与断言（`tests/run_t008_species.gd`）

1. 两个 `.tres` 能加载为 `SpeciesConfig`；`species_id` 为 `"Cat"` / `"Mouse"`（与设计拼写一致、非空、互不相同）。
2. **逐字段**与 §4 表核对（含 `Array[int]` 食物类型与三个能力布尔）；`validate()` 返回空。
3. `AnimalBody` 实例化 + 赋配置后：碰撞形状是 `CapsuleShape3D`，`radius`/`2×half_height` 等于配置；
   相机本地 z = `camera_offset_z`、`fov` = 配置；`collision_layer = 2 (animal)`、`mask = 1 (world_static)`；
   `climb.max_step_height` == `config.max_step_height`。
4. **物理实测（配置驱动）**：每个物种各两个用例，用 `AnimalBody` + 其配置驱动的 `StepClimb`：
   - `step = config.max_step_height` → **能上**（水平到达目标 x 且抬升 ≈ 台阶高）
   - `step = 0.20`（猫）/ `0.12`（鼠）→ **上不去**（不得到达台阶顶）
   同时记录猫/鼠胶囊与台阶尺寸，证明"尺度差异真的成立"。
5. **静态检查（不散落物种判断）**：读取 `animal_body.gd` 与 `step_climb.gd` 源码，
   断言其中**不出现** `"Cat"` / `"Mouse"` 字面量与 `species_id ==` 这类分支。
6. 断言失败即退出码 1；stdout 用 `ASSERT|id|expected|actual|PASS/FAIL`。

## 7. 失败回退

- 手写 `.tres` 若字段名/类型不被引擎接受：保留引擎报错，改为**引擎侧工具生成**（与 lab 场景修补同法），并记录原因。
- 若某个物理用例不稳定：**不许放宽容差蒙过去**，先记录实测分布（沿用探针的 `sweep_tolerance` 思路）。
- 不改产品参数；`Parameters.md` 与配置不一致时以 `Parameters.md` 为准并记 Decisions。
