# T060 目标机器性能检查

> **状态：done（2026-11-11）** —— 真实场景（非空关卡）两分辨率实测 + **只修了一个最大瓶颈**（昼夜光照限频）+ 同机位复测；11 条契约守卫 ×3、全量 65 套 4,933 条 0 失败。未验证项见 `Docs/Evidence/T060.md` §7。

## 1. 目标与不做

**目标**（开发计划 :252）：**目标机器性能检查** —— 记录**帧时间、内存、AI/植被负载**；**修一个最大瓶颈并复测**；**报告配置与场景**。
开发计划 :257 另有一条口径：「T060 的目标先由 T001 设为本机临时基线，确认发布目标硬件后另行测试。**不能以空地图 FPS 代表真实场景性能**」。

本机基线（T001 采集，见 Handoff「关键环境事实」）：i7-11800H / 31.75 GB / **T600 Laptop 4 GB** / Win10 19045。

**现状**：

- 有 `tests/tool_perf_probe.gd`（ART03-③/④ 遗留）：**只测空关卡**（`l_courtyard.tscn` + 一个相机），
  没有玩家、没有 NPC、没有 HUD、没有生态 → 正是 §257 说的"空地图 FPS"，**不能当 T060 的结论**。
- 有 T044 的资产预算（每件猫/巨石/草丛的增量），但那是"叠加资产"的合成量，不是真实一局的整帧成本。
- 有 ART09 展板关的 5.6 ms，但那是**展板关**（不同关卡、无 AI）。

**不做**：

- 不做性能优化专项（只修**一个**最大瓶颈，其余记录成表）。
- 不改画质档位/分辨率策略（那是产品决策，需要负责人拍板）。
- 不上多线程渲染/物理参数调优（会改手感与确定性契约）。
- 不做发布目标硬件测试（本机是临时基线，见 :257）。

## 2. 决策

- **D1 测真实场景**：用 `scenes/core/main.tscn`（正式入口）+ `select_species()` 出生，
  即"关卡 + 玩家 + 生态 NPC + HUD + 昼夜 + 环境音"都在跑，而不是空关卡。
- **D2 同一机位、只换变量**：固定相机（玩家第三人称视角在出生点朝庭院中心），逐变体测：
  `all`（全开）/ `no_ai`（NPC 的 `ai_enabled=false` + 身体停物理）/ `no_vegetation`（隐藏草丛/背景草簇）/
  `no_daynight`（`DayNightDirector.enabled=false`）。**差值就是该子系统的真实开销**。
- **D3 测量口径沿用既有的、可复现的那一套**（`tool_perf_probe.gd`）：关 vsync、`Engine.max_fps=0`、
  预热 60 帧后采样 240 帧，用 `frame_post_draw` 的墙钟差算帧时间，同时读
  `Performance.RENDER_TOTAL_{PRIMITIVES,DRAW_CALLS,OBJECTS}_IN_FRAME` 与 `MEMORY_STATIC`。
- **D4 内存**记 `Performance.MEMORY_STATIC`（引擎侧静态内存）+ `OS.get_static_memory_usage()` + 峰值，
  不把 OS 总占用当"游戏内存"（那包含编辑器/系统噪声）。
- **D5 判据是"相对"不是"绝对"**：本机是临时基线，所以验收判据写**预算 vs 实测**（60 fps → 16.67 ms/帧；
  T044 的"场景总增量 ≤ +2.0 ms@1080p"）与**变体差值**，不写"这游戏在 T600 上一定 60 fps"。
- **D6 只修一个瓶颈**，且必须：① 有测量证明它是大的；② 修法不改变玩法/画面契约；③ 修后有复测对比。

## 4. 用例（验收）

1. **探针能跑出可用数据**：两个分辨率各有 `frame_ms avg/p50/p95/max`、`fps`、`primitives`、`draw_calls`、`memory`。
2. **负载归因成立**：`no_ai` / `no_vegetation` / `no_daynight` 与 `all` 的差值被记录（同机位、同帧数、可重复）。
3. **瓶颈判定有依据**：从数据里指出"最大的那一项"（渲染 vs AI vs 植被 vs 昼夜），不是凭感觉。
4. **修一个瓶颈**：修后复测，给出修前/修后同机位对比；其它项**不动**并写明。
5. **报告配置与场景**：硬件、分辨率、关卡、NPC 数、开关状态、采样帧数全部记录。
6. 全量 headless 0 失败、`invalid=0`、零窗口（性能探针本身非 headless，但必须 `visible_hits=0`）。

## 5. 失败恢复

- **`Engine.max_fps=0` 在无头下没有意义**：本任务探针**必须非 headless**（dummy 渲染器测不到 GPU 时间）。
- **首次采样的第一帧特别长**（着色器编译）：所以预热 60 帧，且报告里写清预热帧数。
- **`frame_post_draw` 采样会漏掉逻辑线程**：墙钟差里其实包含逻辑 + 渲染，这是有意的（玩家感知的是整帧）。
- **变体之间要清理干净**：`no_vegetation` 只改 `visible`，不能 `queue_free`（会改变物理/GC 形态）；`no_ai` 恢复时把
  `ai_enabled` 与 `set_physics_process(true)` 一起复位。
- **测到的数会抖**：`p95` 与 `max` 都要报，不能只报平均；两分辨率都要有。
