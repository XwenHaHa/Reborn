# T031 地点发现与老鼠解锁

- 归属阶段：P4 轮回（T030 已 done）
- 硬依赖：T030（`GameState` 档案/事件/解锁集 + `LifeCycle` 状态机 + 正式入口）
- 预估：2–4 h
- 计划来源：`轮生_Reborn_开发计划_v1.0.md:165`「指定鼠洞稳定 ID；发现事件更新长期记录，不按刷捕猎解锁」
- 设计来源：`轮生_Reborn_游戏策划案_v1.1.md` §9.2（猫默认可选；作为猫首次发现指定鼠洞入口后老鼠永久解锁；不要求捕食数量；解锁后死亡不取消；开发测试模式与正式体验明确区分）；`Docs/TechnicalDesign.md` §1（`GameState` 唯一权威）、§7（初始化普通新游戏：**猫解锁**）

## 1 目标（可验收的一句话）

正式模式下：**只有猫可选**；玩家作为猫**走到指定鼠洞入口的发现半径内** → 记一条**长期**发现记录（跨世保留、去重）、事件 `discovery`、并**永久解锁老鼠**（死亡/新世不取消）；**捕获计数不参与解锁**；开发测试模式（`test_mode=true`）仍直接放行两个物种，且与正式模式行为明确区分。

## 3 关键决策

- **D1 稳定 ID**：指定鼠洞 = 庭院树根屏障的**唯一**鼠洞（`HOLE_CENTER_X 26.5`，z∈[18.5,19.5]），稳定 ID `"root_hole_courtyard_01"`。**进存档后不得再改**（T036 契约里的"长期发现"键）。ID 写在关卡标记的 `discovery_id` meta 里，消费方不复制常量。
- **D2 发现判据 = 水平距离**：玩家到发现点标记的**水平**距离 ≤ 半径（200 cm = 2.0 m，标记 meta `radius`，兜底常量同值）即视为发现。不加视锥/遮挡：策划 §9.2 只说"发现入口"，原型以确定性优先；是否加"看见才算"待负责人定（记入 Parameters 待定项）。
- **D3 发现记录分两层**：`GameState.discovered_places`（**长期**，跨世保留、按 ID 去重、`reset_for_new_game` 才清）+ 既有 `current_life.discoveries`（本世档案，策划 §9.5）+ 事件 `discovery`（既有的长期事件流）。**去重以长期层为准**：同一地点一世内/跨世重复触发都不再记。
- **D4 解锁规则数据驱动**：`SpeciesConfig` 新增 `initially_unlocked`（猫 true / 鼠 false）与 `unlock_discovery`（鼠 = 洞 ID）。`MainEntry` 启动时把配置汇成 `GameState.discovery_unlock_rules`（地点 ID → 物种 ID）并写初始解锁集。`GameState.record_place_discovery()` 首次记录时查规则并 `unlock_species()`。**代码与入口不出现物种名**（沿用 T019 `ai_script` 模式）。
- **D5 "作为猫"由门控结构性保证，不写特判**：正式模式初始只有猫可选 → 能第一个走到洞口的必然是猫；鼠在解锁前根本无法出生，所以**不需要**"发现者必须是猫"的额外分支（测试里用断言固化这个不变量：解锁前鼠 `begin_spawn` 被拒 `locked_species`）。测试模式下鼠先发现也只是空解锁（测试模式本就放行）。
- **D6 不按刷捕猎解锁**：解锁**只**挂在发现事件上；捕获计数（`add_to_life("captures")`）与解锁无任何连接（测试断言固化）。
- **D7 `test_mode` 默认翻 false**（T030 遗留收口）：`MainEntry.test_mode` 默认值 `true → false`；正式模式 `selectable_slots()` 只列已解锁物种（T030 已实现的分支）。受影响的既有套件（t030 H 段、art05 输入、两个取证工具）**显式**打开测试模式——它们测的是生命周期/输入/取证，不是解锁门。
- **D8 菜单内"锁定物种"的视觉/提示不在本任务**：ART09 物种页仍显示两张可玩卡；正式模式点鼠的「开始游戏」会被 `LifeCycle` 拒（`locked_species`，`push_warning` + 拒绝记录），状态栏文字不变。锁定态卡片美术/提示属 T033（正式物种选择与重生），不在 T031 撕美术。

## 4 数据 / 事件

```
SpeciesConfig（新增，Progression 组）
  initially_unlocked: bool = false        # 正式新游戏初始解锁（策划 §9.2：猫默认可选）
  unlock_discovery: StringName = &""      # 解锁本物种的地点稳定 ID；空 = 无发现解锁条件

GameState（新增）
  discovered_places: Dictionary           # 键 = 地点稳定 ID（String），值 = 首次发现的世界时间
  discovery_unlock_rules: Dictionary     # 键 = 地点稳定 ID，值 = StringName(species_id)；入口写入
  set_discovery_unlock_rules(rules)
  record_place_discovery(place_id, world_time=-1) -> bool   # 首次 true；去重；触发规则解锁
  is_place_discovered(place_id) -> bool
  discovered_place_list() -> Array[String]
  signal place_discovered(place_id)
  # reset_for_new_game()：清 discovered_places（进度数据）；保留 discovery_unlock_rules（接线数据，入口会重写）

关卡标记（tool_make_courtyard.gd 生成）
  Marker3D "Discovery_RootHole" ∈ discovery_points
    meta discovery_id = "root_hole_courtyard_01"（**稳定 ID**）
    meta radius = 2.0
    pos = (26.5, 0.10, 19.0)（洞中心；两侧入口都在半径内）

事件（沿用 T030 既有 kind）
  kind=discovery  data={label: <地点ID>}
  kind=species_unlock data={species: <物种ID>}   # unlock_species() 既有行为
```

## 6 用例（`tests/run_t031_discovery.gd`）

- **A 契约**：两 `.tres` 的 Progression 字段值正确；`validate_config()` 双双为空；`GameState` 有新 API；`main.tscn` 实例 `test_mode == false`；关卡场景有 `Discovery_RootHole`（组/ID/半径/位置正确、零碰撞）。
- **B 发现判定**（tracker 单测，运行期造标记）：半径外 0 次；进半径发现一次；出/进不重复；已发现地点（长期层）不再扫；无 `discovery_id` 的标记被忽略；半径边界 ≤ 判定。
- **C 长期记录**：首次 `true` + 事件 `discovery`（data.label = ID）；重复 `false` 不加事件；`end_life` 后新一世仍视为已发现；`reset_for_new_game` 清空；无进行中生命时也能记长期层（life_id 空串）。
- **D 解锁规则**：正式态下发现洞 ID → 目标物种解锁 + `species_unlock` 事件；解锁跨 `end_life` 保留（**死亡不取消**）；`add_to_life("captures", 5)` **不**解锁；无规则地点不解锁任何物种；规则与 `test_mode` 无关。
- **E 正式入口集成**（headless 实例 `main.tscn`）：正式模式 `selectable_slots()` 只含初始解锁物种；选另一物种被拒（`locked_species`）；出生初始物种 → 把玩家挪到洞口半径内、推进若干物理帧 → 目标物种出现在 `selectable_slots()`；结束本世后解锁仍保留；`test_mode=true` 时两物种都可选。

## 7 失败恢复

- 若重新生成的 `l_courtyard.tscn` 出现**预期外** diff：说明生成器与已提交场景存在漂移——停下核对（先 `git stash` 场景再逐步对齐），**不得**顺手提交无关几何变更。
- 若 T030/T008 回归因 `test_mode` 默认翻转失败：按 §2 表给对应套件显式开测试模式，**不改生命周期断言语义**。
- 若 `GameState` 未注册（包内）：检查 `project.godot` `[autoload]`；包内 `.tres.remap` 的坑 T030 §6 已修，`unlock_discovery` 是 `StringName` 不经文件枚举，不受影响。
- 同一失败最多两次有依据的修复尝试；无新诊断不重试。
