# T042 暂停与主动结束确认

## 1. 目标与不做

**目标**：给存活期补上正式的暂停层与「结束本次生命」确认闭环。Esc 打开暂停菜单；暂停是真冻结（世界时间、资源恢复、区域种群恢复、AI/物理、玩家输入全部停摆，状态逐字段保持）；结束必须二次确认且默认焦点「取消」；确认后走 `LifeCycle.end_life` 正常死亡路径（归档、`damage_reason=player_quit`、T037 pending 存盘、T032 结算页），不得直接重生、跳结算或清档；暂停本身不写盘。

| # | 场景 | 玩家看到什么 | 点了之后发生什么 |
|---|---|---|---|
| A | 存活期按 Esc | 全屏暂停层：「游戏已暂停」，「继续游戏」「结束本次生命」，提示「Esc 继续游戏」 | 世界立即冻结；焦点在「继续游戏」；再按 Esc 或点「继续游戏」逐字段恢复 |
| B | 暂停中观察世界 | 画面静止；老鼠/猫不移动，饥饿不减，资源点不刷新，区域种群不恢复 | 暂停 5 s 后 `world_time`、资源 `next_refill_at`、区域 `next_recover_at` 一字不变 |
| C | 点「结束本次生命」 | 二次确认层：标题「结束本次生命？」、正文说明会正常结算并写档案、默认焦点「取消」 | 取消 → 回暂停菜单仍存活；确认 → 正常死亡并弹结算页 |
| D | 确认结束 | 结算页显示「死亡（player_quit）」；主菜单在下面 | 档案 +1、事件 `life_end`、T037 pending 存盘；**不**直接重生、**不**清档；重生仍需玩家在结算后选物种 |
| E | 暂停期间 | 不产生任何额外存档 | 主档字节与 revision 不变；退出程序的存档仍按既有出口径 |
| F | Esc 冲突 | 结算页 / 确认层 / 暂停层同时可能存在 | 优先级固定：结算页 > 确认层 > 暂停；低层不得抢先 |

**不做**：不改存档格式（仍 14 键）、不改结算/轮回与重生语义（T032/T037）、不改解锁规则（T031/T033）、不改 12 m 收敛（T040b）、不新增“安全点”概念与 `last_safe_spot_id` 字段、不做设置页、不做多槽位。

## 2. 必须复证的既有契约

1. **UI 树序**：`Hud < PauseMenu < EndLifeConfirm < MainMenu < LifeStatus < NewGameConfirm < LifeSettlePanel`。新增暂停层插在 `Hud` 与 `MainMenu` 之间；理由：暂停层只在存活期可达，此时菜单/状态/确认/结算全部隐藏，贴 HUD 之上即可覆盖画面，同时让 T033/T041 既有链 `MainMenu < LifeStatus < NewGameConfirm < LifeSettlePanel` 一字不动。结算页仍最上。
2. **T033 解锁集语义**：`MainMenu.build(unlocked_ids:=[])` 空数组 = 全部可玩；`set_unlocked([])` = 全锁。不得改。
3. **菜单可见时状态行隐藏**：`_present_menu()` 中 `status_label.visible = false` 的口径不得改。
4. **T041 确认层默认取消**：`NewGameConfirm` 默认焦点「取消」、Esc 取消；T042 的 `EndLifeConfirm` 沿用同口径，不改 `NewGameConfirm`。
5. **T039 阻断语义**：`_load_blocked` 期间 `select_species()` 拒绝、`save_now()` 返回 `blocked`、退出不写新档。
6. **T014/T034 D2 冻结口径**：`time_advancing=false` 与 `SceneTree.paused=true` 两条路径都能让 `world_time` 精确不前进（T014/T020 已实测）。

## 3. 决策

- **D1 暂停入口只在 `ALIVE`**。`open_pause()` 仅在 `LifeCycle` 为 `ALIVE`、且 `LifeSettlePanel` 未呈现、`NewGameConfirm`/`EndLifeConfirm` 未打开时成立；其它状态返回 false。
- **D2 双保险冻结**：`open_pause()` 同时置 `WorldDirector.time_advancing=false` 与 `get_tree().paused=true`。树暂停停掉所有 PAUSABLE/INHERIT 的 `_process/_physics_process/_input`（时钟、资源、区域种群、AI、物理、玩家输入）；`time_advancing=false` 保证即使某节点被设 ALWAYS，世界时间也不前进。不引入逐帧快照/回滚，状态天然保持。
- **D3 暂停层 `PROCESS_MODE_ALWAYS`**。`PauseMenu` 与 `EndLifeConfirm` 必须能在树暂停时收键与点击；其子节点继承 ALWAYS。
- **D4 Esc 优先级**：`MainEntry.handle_escape()` 固定顺序——结算页呈现 → false（交给结算页消隐）；`NewGameConfirm` 打开 → false（交给确认层取消）；`EndLifeConfirm` 打开 → 取消确认并保持暂停；已暂停 → 恢复；`ALIVE` → 暂停；其它 → false。`_unhandled_input` 与测试共用该路径。
- **D5 主动结束 = 正常死亡**。确认后先解除树暂停，写 `pending_settlement_life_id`，调用 `lifecycle.end_life(&"died", {"damage_reason": "player_quit"})`，再 `save_now(&"death")`；随后既有 `_on_life_settled → _enter_select → _present_settle` 接管。禁止调用 `_start_new_game()`、禁止直接 `select_species()`、禁止 `clear_slot()`。
- **D6 暂停不写盘**。`open_pause/resume_game/request_end_life/cancel_end_life` 不调用 `save_now`；暂停期间存档队列随树暂停停摆。`_exit_tree` 若仍暂停先解除树暂停，再按既有退出出口径存档。
- **D7 鼠标所有权上移**。删除 `AnimalBody` 对 `pause` 键的鼠标切换分支；暂停打开时 `MOUSE_MODE_VISIBLE`，恢复存活时 `MOUSE_MODE_CAPTURED`，结束生命后由菜单呈现路径设为可见。
- **D8 结束确认层独立**。新建 `EndLifeConfirm`，不复用 `NewGameConfirm`，避免改动 T041 的文案与契约。

## 4. 数据与事件

- 无新存档字段；沿用 T037 的 14 键。`damage_reason=player_quit` 写入既有 `CurrentLife` 档案与 `life_end` 事件数据。
- 新增运行时只读状态：`MainEntry._paused`、`PauseMenu._open`、`EndLifeConfirm._open`。
- 日志（证据用）：
  - `ENTRY|pause|open|world_time=...|advancing=false`
  - `ENTRY|pause|resume|world_time=...|advancing=true`

- 信号：`PauseMenu.resume_requested`、`PauseMenu.end_life_requested`；`EndLifeConfirm.confirmed`、`EndLifeConfirm.cancelled`。

## 6. 用例（`tests/run_t042_pause_flow.gd`）

- **A 暂停入口**：存活期 `open_pause()` 成功；暂停层可见、标题/按钮逐字、焦点「继续游戏」；树暂停、`time_advancing=false`；`selecting/settling/spawning` 下调用返回 false。
- **B 冻结逐项**：真实等待 5 s 后 `world_time`、资源 `units/next_refill_at`、区域 `next_recover_at`、NPC 位置/朝向、玩家 transform/velocity、饥饿/口渴/体力/生命、footstep 计数全部精确不变；按住移动/疾跑键也不位移。
- **C 恢复还原**：暂停前后基线字段一致；`resume_game()` 后暂停层隐藏、树恢复、`time_advancing=true`；世界时间继续走、消耗继续、玩家能移动、控制权未丢。
- **D Esc 优先级**：结算页呈现 → `handle_escape()` false 且不暂停；`NewGameConfirm` 打开 → false 且不暂停；`EndLifeConfirm` 打开 → Esc 只取消确认、仍暂停；暂停中 Esc → 恢复；`InputEventAction("pause")` 经 `_unhandled_input` 能打开暂停。
- **E 结束确认**：`request_end_life()` 仅在暂停+存活成立；确认层可见、默认焦点「取消」；取消后确认层隐藏、仍暂停、仍存活、档案 0、暂停不写盘。
- **F 正常死亡路径**：确认后档案 1 条且 `damage_reason=player_quit`、`end_reason=died`；`life_end` 为最后事件；`settle_count` +1；结算页逐字含「死亡（player_quit）」；`player=null`、状态 `selecting`；存档仍存在且含该档案、`saved_reason=settle_shown`、`pending` 已清；不出现新生命。
- **G 契约**：树序 `Hud<PauseMenu<EndLifeConfirm<MainMenu<LifeStatus<NewGameConfirm<LifeSettlePanel`；既有 `menu<status<confirm<settle` 不变；`build([])` 全解锁 / `set_unlocked([])` 全锁；菜单可见时状态行隐藏。

## 7. 失败恢复

- 测试或异常路径务必解除暂停：`resume_game()` 失败时再补一次 `get_tree().paused=false`，并恢复 `time_advancing=true`（存活时）。
- `EndLifeConfirm` 打开后任何路径都要保证 `pause_menu` 仍在、确认层关闭幂等；取消不清档、不归档。
- 确认后若 `end_life` 被拒（非 `ALIVE`），不进入结算、不写盘，回到暂停菜单并记录错误。
- `_exit_tree` 若仍暂停：先 `get_tree().paused=false` 再走既有退出存档，避免带着全局暂停销毁场景。

## 9. 挂账

- 版本不兼容存档「保留旧档等以后版本」的出口：负责人本轮未表态，**按现状（仅新游戏可选）执行**，不擅自加功能。
- `last_safe_spot_id`：**字段已预留、本轮不实现**。代码里目前没有“安全点”概念，硬造一个契约字段会挖坑。**安全点系统未立项**；最小解除需先定义安全点判定（哪些区域算安全、敌人距离阈值、进出条件），并由负责人同意后再立任务，避免擅改 14 键存档契约。
- 旧档人工处理（备份/删除）仍由玩家在系统层完成；T042 不隔离、不静默覆盖。
