## 1. 目标

1. **固定食物点**：容量 3、每 180 s 恢复 1 Unit、一次交互 **1.5 s**、1 Unit 恢复 **Hunger 35**。
2. **饮水点**：**无限**（不扣 units）、一次交互 **2 s**、恢复 **Thirst 40**。
3. **区分物种食物**：食物点带 `food_type`（`SpeciesConfig.FoodType.MEAT=0` / `SEED=1`），
   交互者必须 `SpeciesConfig.can_eat(food_type)` 为真，否则 `deny_reason = &"food_type"`。
   **一个食物点只能补给允许它的物种**（策划第 157 行）。
4. **成功一次发放收益**：扣 1 Unit 与恢复指标在**同一个方法里**完成；恢复量**夹紧到物种上限**（策划/Parameters「成功后全值夹紧」）。
5. **取消 / 打断无收益**：取消只调 `cancel_interaction()`，**不扣 units、不给收益**（策划第 159 行）。
6. **耗尽不可继续领取**：`units <= 0` → `deny_reason = &"empty"`，且不进入候选。
7. **提交前复检**：距离、视线、物种允许、资源余量、**受伤/死亡状态**都要在提交那一刻再判一次（`TechnicalDesign` §4）。
8. **受伤中断**：交互进行中掉血 → 自动取消（`reason = &"hurt"`）；死亡 → `&"died"`。
9. **按世界时间恢复**：`next_refill_at` 用绝对世界时间；一次调用要**结算所有经过的恢复周期**并夹紧容量，
   **不能只恢复一次**；暂停（世界时间不前进）时不恢复，读档/重生不刷新（策划第 241 行）。
10. **失效**：`expire_at > 0` 且世界时间到期 → units 归 0（捕获食物 300 s；本任务只提供机制与断言，生成属 T021）。
11. **`to_record()`** 产出 `ResourceRecord` 形状的字典（供 T037 存档）。

## 4. 决策（D1~D9）

- **D1 数值归资源点，不进 `SpeciesConfig`**：`nutrition`（35 / 40）、`interaction_duration`（1.5 / 2.0）、
  `capacity`（3）、`refill_interval`（180 s）都是**资源属性**；`Parameters.md` 第 75/77 行没有按物种分列 → 先用共同值。
- **D2 水点用 `infinite = true`**：`query` 不看 `units`、`commit` 不扣 units；`capacity` / `refill_interval` 对水点无意义（留默认）。
- **D3 提交前复检放 `InteractionDetector`**：提交前重跑一次候选集，目标不在其中就
  `success = false`、`reason = &"out_of_range"` / `&"occluded"` / `&"empty"` / `&"food_type"` / `&"dead"`（取当时的 `last_deny_reason()`），
  且**不调用目标**。这是"查询及提交时都检查"的落地位置，避免每个资源点自己重算距离。
- **D4 收益原子化**：`commit_interaction()` 内先判后做（扣 Unit → `restore_*`），中途不改其它状态；
  任一步失败则**不扣不发**并返回 `success=false` + 原因。
- **D5 幂等双保险**：事务表在 `InteractionDetector`（T016）与 `Interactable`（基类）各一份，同 `transaction_id` 第二次都不会再结算。
- **D6 恢复用绝对时间点**：`advance_to(world_time)` 里 `while next_refill_at > 0 and world_time >= next_refill_at: units += 1; next_refill_at += refill_interval`；
  满容量时 `next_refill_at = 0`（不再排期），从"再次未满"那一刻重新起算。暂停时世界时间不前 → 自动不恢复。
- **D7 受伤中断由身体做**：`AnimalBody` 记 `_last_health`，`survival.changed` 里 health 下降且正在交互 → `release_interact(&"hurt")`；
  `died` → `&"died"`。**不在 `ResourcePoint` 里读交互者的血**（资源点不该知道身体细节）。
- **D8 `expire_at`**：`> 0` 且到期 → `units = 0`；`query` 返回 `&"expired"`。生成与赋值属 T021（300 s）。
- **D9 视觉只做占位**：正式美术属 P6；脚本按 `kind` 设占位盒尺寸与颜色（食物灰绿、水蓝），便于将来视觉判读。

## 5. 接口（本任务新增）

```gdscript
# scripts/world/resource_point.gd
class_name ResourcePoint extends Interactable

const KIND_FOOD := &"food"
const KIND_WATER := &"water"

@export var kind: StringName = KIND_FOOD
@export var food_type: int = 0            # SpeciesConfig.FoodType（水点忽略）
@export var units: int = 3
@export var capacity: int = 3
@export var refill_interval: float = 180.0
@export var next_refill_at: float = 0.0   # 0 = 不排期（满容量或水点）
@export var expire_at: float = 0.0        # 0 = 不失效
@export var nutrition: float = 35.0       # 食物 → Hunger；水 → Thirst
@export var infinite: bool = false        # 水点 = true
@export var region_id: StringName = &"Courtyard"

signal consumed(transaction_id: String, interactor: Node, units_left: int)
signal refilled(units: int, world_time: float)
signal expired(world_time: float)

func advance_to(world_time: float) -> void   # 结算所有经过的恢复周期 + 失效判定
func is_empty() -> bool
func is_expired(world_time: float) -> bool
func to_record() -> Dictionary               # ResourceRecord 形状
func fill() -> void                          # 调试/初始化：units = capacity
```

## 6. 断言（`tests/run_t017_food_water.gd`，目标 ≈110 条）

- **A 参数与接口**：`ResourcePoint` 继承 `Interactable` 且在 layer 3；食物默认 1.5 s / 35 / capacity 3 / refill 180；
  水点（`infinite=true`）2.0 s / 40；`to_record()` 含 `ResourceRecord` 全部字段。
- **B 物种区分**：SEED 食物点 → 猫 `deny_reason = food_type`、鼠可吃；MEAT 食物点 → 鼠被拒、猫可吃；水点两者都可。
- **C 收益一次**：鼠吃 SEED（hunger 50）→ hunger 85、units 3 → 2、`consumed` 信号一次。
- **D 夹紧**：hunger 90 吃 35 → 100（不超上限）。
- **E 耗尽**：`units = 1` → 吃一次后 `units = 0`、`deny_reason = empty`、不再进候选。
- **F 取消无收益**：1.5 s 交互进行到 0.5 s 松开 → hunger 不变、units 不变、`cancel_interaction` 被调一次。
- **G 时长走世界时间**：1.4 s 未提交、1.6 s 提交一次；暂停（`time_advancing = false`）期间不提交。
- **H 受伤中断**：交互中 `apply_damage()` → 自动取消（`reason = hurt`）、units 与 hunger 都不变。
- **I 水点无限**：连喝 3 次 Thirst 均 +40（夹紧 100）、units 不变；血量不变。
- **J 恢复周期**：units 0 → 推进 180 s 得 1；**一次推进 540 s 得 3（不是 1）**；满容量后 `next_refill_at = 0`；
  再消耗 1 后重新排期。
- **K 失效**：`expire_at = t + 10`，推进 11 s → units 0、`deny_reason = expired`、`expired` 信号一次。
- **L 提交前复检**：交互中把目标 `enabled = false` / 移出范围 → 提交失败、**无收益**、原因可读。
- **M 集成**：真实 `animal_body.tscn` + `resource_point.tscn` 实例化；HUD 出现资源行、`MOV|` 出现 `food=`/`water=`；
  正式场景（`main.tscn` / `l_courtyard.tscn`）仍 0 调试节点；全量回归不退化。

  （T016 的合成时间用例里目标不动、不被禁用，应当天然有效）；若确实冲突，把复检降级为"仅当目标 `enabled` 变化或距离超出"时才判失败，并在证据里写明取舍。
- 若水点 `infinite` 与 `units` 语义打架：统一为"`infinite = true` 时 `units` 只读、不参与 `query`"，不动基类。
- 任一失败最多两次有依据的修复，之后按 `AGENTS.md` 记 blocked 并给最小解除方法。
