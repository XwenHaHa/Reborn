### 2.4 `--check-only` 的真实性验证（重要）

这不是个"永远返回 0"的空检查——它**抓到了我真实写出的语法错误**：

```
SCRIPT ERROR: Parse Error: Expected closing ")" after call arguments.
    at: GDScript::reload (res://main.gd:76)
ERROR: Failed to load script "res://main.gd" with error "Parse error".
CHECK_EXIT=1
```

错误原因是把 Python 风格推导式写进了 GDScript（`"|".join(c.name for c in ...)`）。改成
`"|".join(body.get_children().map(func(c: Node) -> String: return c.name))` 后退出码变 0。

**结论**：`--check-only` 是可信的静态门——可用来在运行前拦截语法错误，退出码可判定。

### 2.5 一次挂起与规避

修复语法错误前的那次 `--check-only` + 无头运行组合中，**运行命令挂起超过 180 s 被超时终止**。原因是脚本加载失败导致 `_ready()` 未执行，`get_tree().quit()` 从未被调用，进程不退出。

**规避**：无头运行一律加 `--quit-after <N>` 作为硬上限（本次用 300 帧）。**这条必须写进后续所有 Godot 运行命令**，否则一次脚本错误就会挂死自动化。
