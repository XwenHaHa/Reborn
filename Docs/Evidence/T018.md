- **D1 位置/不吃输入**：全屏 `Control` + 左下 `VBoxContainer`（`alignment = 2`），`mouse_filter = IGNORE`（实测值 2）。
- **D2 文本形式**：`Label` 文本（未做血条控件）。

- **D4 警告措辞**：`饥饿` / `缺水` / `饥饿 + 缺水`（中文，无英文键名）。
- **D5 交互提示**：`eat → 进食`、`drink → 饮水`；进行中带百分比；无目标时整行隐藏。
- **D6 信号驱动**：伤害/恢复/警告/目标切换/交互开始·提交·取消全部走信号；`_process()` **唯一**读取的是交互进度（连续量）。

## 6. 本任务踩到的坑（写进 `Docs/Commands.md` §2.14）

1. **`Control.mouse_filter` 默认是 STOP（0）**：HUD 全屏控件会把鼠标事件全吃掉 → 显式设 `IGNORE(2)` 并断言。
2. **带类型的 `Node` 参数遇到"已 `queue_free()` 的目标"会直接报错**：
   `Invalid type in function '_target_id_of' … (previously freed) is not a subclass of the expected argument class`。
   修法：检测器里所有可能收到目标的参数改成**无类型**（`Variant`）并在内部先 `is_instance_valid()`；
   `is_interacting()` 也要 `is_instance_valid(_active_target)`（失效目标不算"进行中"）。
3. **HUD 进度必须用真实世界时间**：用合成 `tick()` 会让 HUD 显示 `0%`（身体的每物理帧 `tick()` 把时间拉回，T016 同一个坑）。
   测试改成真实推进 0.15 s → 进度 0.417。
4. **"状态不变"的断言要在同一帧内比**：跨帧对比会因为饥渴按时间下降而失败（实测 `hunger 99.98`）。
5. **窗口模式捕获要用后台执行 + 轮询日志**：直接前台跑可能一直不返回（`--quit-after` 是**帧数**，写大了等于没上限）；
   本次用 `Start-Process` + 90 s 轮询拿到 `CAP|t018|done`。图先落 `user://`，需复制到 `Art/Probes/`。
