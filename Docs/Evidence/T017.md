## 4. 决策落地（对 `Docs/Tasks/T017.md` §4）

- **D1 数值归资源点**：`nutrition`（35/40）、`interaction_duration`（1.5/2.0）、`capacity`（3）、`refill_interval`（180）都在 `ResourcePoint`
  且由 `kind` 的 setter 套默认值；`SpeciesConfig` 没有新增字段。
- **D2 水点 `infinite = true`**：`query` 不看 `units`、`commit` 不扣；实测连喝 3 次余量仍 0/无限。
- **D3 提交前复检**：`InteractionDetector._recheck_target()`——禁用 → `disabled`、移出 3 m → `range`，两次都**没有调用目标**（`commit_count()` 仍 0、指标与余量不变）。
- **D4 收益原子化**：`ResourcePoint.commit_interaction()` 里"扣 Unit → `restore_*`"连续完成；失败分支提前 return，不扣不发。
- **D5 幂等双保险**：`InteractionDetector` 与 `Interactable` 各有一张事务表（T016 已验；T017 的 M 段走真实场景仍只结算一次）。
- **D6 恢复用绝对时间点**：`advance_to()` 里 `while` 结算所有经过周期；满容量 `next_refill_at = 0`；**消耗后不排期**，
  由下一次 `advance_to()` 统一排期（避免两个时间源）。
- **D7 受伤中断由身体做**：`AnimalBody._on_survival_changed`（health 下降才算受伤）与 `_on_survival_died`。
- **D8 `expire_at`**：到期 → `units = 0` 且只发一次 `expired`；生成捕获食物属 T021。
- **D9 占位视觉**：脚本按 `kind` 建 BoxMesh + 颜色（食物灰绿 / 水蓝），正式美术属 P6。

## 5. 本任务踩到的坑（写进 `Docs/Commands.md` §2.13）

1. **GDScript 的 lambda 按值捕获局部变量**：`var n := 0` 然后 `signal.connect(func(...): n += 1)` —— 信号确实发了，但外面读到的 `n` **永远是 0**。
   计数必须放进数组（`var c := [0]` → `c[0] += 1`）或字典。实测前两次断言 `C_consumed_signal_once`、`K_expired_signal_once` 都是 0。
2. **`kind` 的 setter 会重置同类型默认数值**：`ResourcePoint` 里改 `kind` 会套用时长/恢复量/容量/间隔，
   所以**场景/测试里覆盖数值必须写在 `kind` 之后**（`_configure_resource()` 里明确按这个顺序设置）。
3. **`_ready()` 用真实世界时间排期，会和用假时间的测试打架**：`advance_to(2000)` 会一次补掉十几个周期。
   加 `@export var auto_advance: bool`（运行期 true、假时间测试 false）+ 测试把 `next_refill_at` 归 0 后显式推进。
4. **`ResourceRecord` 形状要在实现时就固定**：`to_record()` 的十个字段被 A 段逐条断言，避免 T037 存档时才发现字段名不一致。
5. 继承 `Interactable` 时要显式 `super()`（`_init` / `_ready` / `deny_reason_for` / `cancel_interaction` 都覆盖了）。
