## 3. 关键实现

**D1 双门控**（`Parameters.md` 的两句话都满足，`AnimalBody`）：

```gdscript
func _update_sprint_latch() -> void:
	if not want_sprint or is_crouching or survival == null or species_config == null:
		_sprint_active = false
		return
	if _sprint_active:
		_sprint_active = survival.has_any_stamina()      # 继续：> 0
	else:
		_sprint_active = survival.has_min_stamina()      # 开始：≥ sprint_min_stamina(5)
```
`current_speed()` 里顺手刷新一次，所以 HUD/测试"直接读档位"也拿到正确结果；`is_sprinting()` 是唯一读口。

**D2 消耗用世界时间差**（不读 physics `delta`）：

```gdscript
		var dt_sim: float = survival.tick_to(world_time_now())
		if dt_sim > 0.0 and is_sprinting():
			survival.spend_stamina(species_config.sprint_stamina_per_sec * dt_sim)
```
`spend_stamina()` 每次调用会把"距上次消耗"清零 → **冲刺期间自然不回复**（与 `RegenDelay` 语义一致）。

**D3 跌落只看垂直速度**（`AnimalBody._track_fall()`）：腾空期间记录 `max(|velocity.y|)`，**落地那一帧**结算一次并清零；
伤害 = `(v − fall_safe_vertical_speed) × fall_damage_scale`，上限 `max_health`（=100，与 `Parameters.md` "最大100"同口径）。

**D4 危机扣血复用伤害通道**（`SurvivalController._apply_crisis_damage()`）：原因 `starvation/dehydration/exhaustion`
三选一，扣血走 `apply_damage()` → 写 `last_damage_reason`、归零只发一次 `died`，不另开改血路径。

## 6. 过程中修掉的 5 个问题（全部因实测）

| 现象 | 根因 | 处理 |
|---|---|---|
| `@export var sprint_stamina_per_sec` 重复声明 | 它在 "Survival" 组里**早就存在**，我在新组里又加了一份 | 删掉新增的重复声明（保留原字段） |
| 体力用 `spend_stamina(94)` "设成 6" 但断言拿到 0 | **`spend_stamina` 是扣减不是赋值**（4 − 94 → 夹到 0） | 该处改成直接赋值 `state.stamina = 6.0` 并注明"距上次消耗 <1 s 不会自动恢复" |
| 体力设成 4/0/20 后测试里"体力自己涨回来"（门控/恢复用例全错） | 直接改 `state.stamina` **没有重置 `_time_since_spend`**；初值是 `INF` → 下一次 0.2 s 结算立刻开始恢复 | 测试改用 `spend_stamina(...)`（真实游戏里体力只会被"消耗"减少）把延迟对齐；`RegenDelay` 用例把等待窗口压到 0.6 s |
| 体力 0 的"耗尽仍可行走"位移比 walk 期望小 ~14% | 期望值没算**加速段**（从静止到 walk 速度需要 `v/max_acceleration` 秒） | 期望 = `walk_speed×t − 0.5·walk_speed²/max_acceleration`，实测 0.963 vs 0.930 ✓ |
| 调试 HUD 缺 `warn=` 标记 | 断言先写、实现后到 | HUD 的 survival 行加 `warn=` / `crisis=`（只读 `SurvivalController` 的布尔量） |
