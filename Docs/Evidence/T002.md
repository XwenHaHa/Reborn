### 2.1 关键设计决定

- **地面**：`BoxMesh`/`BoxShape3D` 尺寸 `Vector3(10, 0.2, 10)` = 1000×1000 cm，厚 20 cm（顶面 y=0.1）。
- **PlayerStart**：`Marker3D` 在 `(0, 1.5, 0)`。
- **Player**：`CharacterBody3D`，`collision_layer=2`、`collision_mask=1`（只与 `world_static` 碰撞）。
- **胶囊**：`radius=0.16`、`height=0.48` —— 对应 `Parameters.md` 的 Cat 半径 16 / 半高 24 cm。
  （`CapsuleShape3D.height` 是**含两端半球的总高** = 2×半高）
- **速度**：`walk=1.80`、`sprint=4.50`、`crouch=0.90` m/s；`jump_velocity=3.20` m/s；`acceleration=10.0` m/s²
  —— 全部由 `Parameters.md` 的厘米值 ÷100 得到。
- **碰撞层**：`1=world_static`、`2=animal`、`3=interactable`、`4=safe_spot`（在 `project.godot` 集中定义）。
- **渲染**：`forward_plus`，关闭 MSAA。**T600 4GB 下是否吃力尚未实测**（P1 起测），此处不宣称性能。

## 6. 过程中发现并修正的真实缺陷

### 6.1 断言在节点进入场景树之前执行

**现象**：初次运行出现大量 `ERROR: Condition "!is_inside_tree()" is true`，
`player.global_position` 读回 `0.000`，`get_world_3d()` 返回 `null`。

**根因**：在 `_initialize()` 里 `add_child(lab)` 之后**同一帧内**就断言，
节点尚未进入场景树，`get_global_transform()` 无效。

**修正**：改为等待条件成立（见 6.2）。修正后 `player_at_start_m` 读回精确 `0.0000`。

### 6.2 固定帧数等待导致间歇性失败

**现象**：改用"等 2 帧"后，**第 2 次运行出现 1 次失败**（`SUMMARY|checks=16|failures=1`），
随后连续 6 次、15 次复现均未再出现。

**处理**：没有当作偶发放过。根因判断为**依赖固定帧数**——首次运行需生成 `.godot` 缓存有额外开销。

**修正**：引入条件轮询

```gdscript
func _await_condition(predicate: Callable, max_steps: int) -> bool:
	for i in max_steps:
		if predicate.call():
			return true
		await physics_frame
	return predicate.call()
```

落地检查改为"轮询 `is_on_floor()` 直到成立，上限 600 物理帧"，不再赌帧数。

**复验**：5 次冷启动 + 5 次热运行 = **10/10 通过，结果完全一致**。断言数从 16 增至 18。
**未能复现原始失败**，因此这里如实记录：修正依据是根因分析（时序依赖）而非复现，10/10 稳定是修正后的实测结果。
