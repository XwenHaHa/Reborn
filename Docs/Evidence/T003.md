## 2. Git LFS 配置

### 2.1 初始化（仅本仓库，不污染全局）

```powershell
& git lfs install --local
# → Updated Git hooks. / Git LFS initialized.   EXIT=0
```

**验证未改全局配置**：

| 作用域 | `filter.lfs.clean` |
|---|---|
| global | （空） |
| local | `git-lfs clean -- %f` |

局部过滤器全部就位：`clean` / `smudge` / `process` / `required=true`。

### 2.2 `.gitattributes`

分三段：

1. **走 LFS 的二进制**：`*.blend`、`*.glb`、`*.gltf`、`*.fbx`、`*.obj`、`*.dae`、
   贴图（`png/jpg/jpeg/webp/tga/bmp/exr/hdr/ktx2`）、音频（`wav/ogg/mp3/flac`）、
   字体（`ttf/otf/woff/woff2`）、视频（`mp4/webm`）
2. **明确保持纯文本**（**不走 LFS，必须可 diff**）：`*.gd`、`*.tscn`、`*.tres`、`*.godot`、
   `*.import`、`*.cfg`、`*.md`、`*.json`，统一 `eol=lf`
3. 语言统计归属

第 2 段既是对 Godot 纯文本资产特性的记录，**也是保险**：误把 `.tscn`/`.tres` 交给 LFS
会破坏 diff 与合并能力，那是本次引擎迁移的核心收益之一。

### 2.3 LFS 对真实资产生效（实证）

用现有 PNG 资产 `Art/Probes/vision_probe_red_blue.png`（112 B）验证：

```powershell
& git lfs migrate import --include="*.png" --yes
# → Rewriting commits: 100% (1/1), done.   EXIT=0
```

**三重验证**：

1. **追踪清单**
   ```
   $ git lfs ls-files
   83f20a60df - Art/Probes/vision_probe_red_blue.png
   ```
2. **仓库里存的是指针而不是实体**
   ```
   $ git show HEAD:Art/Probes/vision_probe_red_blue.png
   version https://git-lfs.github.com/spec/v1
   oid sha256:83f20a60df6384d38b71f39824dcb661c3239eb861ac3bd328e6bc80ecb81365
   size 112
   ```
3. **LFS 缓存里存的是真 PNG**
   ```
   LFS 对象长度: 112 bytes
   前 8 字节: 89 50 4e 47 0d 0a 1a 0a   ← PNG 魔数
   实际 SHA256 与文件名一致: True
   ```

### 2.4 过程中遇到并修正的问题

`git lfs migrate import` 完成后，**工作区文件变成了 128 字节的指针文本**而非实体 PNG
（`git show` 是指针、但 working tree 也是指针 → smudge 未执行）。

**排查**：先怀疑数据损坏，逐层核对后确认**LFS 对象本身完全正确**（魔数 + SHA256 均匹配），
问题只在工作区实体化。

**修正**：`git lfs checkout` → `Checking out LFS objects: 100% (1/1), 112 B, done.` EXIT=0

**复验**：工作区 112 字节、魔数 `89 50 4e 47`、SHA256 = `83f20a60...`（与期望一致），
`git status` 干净。

> **教训**：LFS 操作后必须独立校验**工作区实体**，不能只看 `git lfs ls-files` 有输出。

### 2.5 历史重写与推送

`migrate import` 重写了包含该文件的提交。推送前**先确认远端没有别人的提交**：

```
$ git log --oneline origin/main --not main
(空 — 远端无独有提交，force push 安全)
```

远端两个提交作者均为 `XwenHaHa <929716663@qq.com>`（本人）。

```powershell
& git -c http.proxy=http://127.0.0.1:7897 push --force-with-lease origin main
# → Uploading LFS objects: 100% (1/1), 112 B, done.
#   67c0806..b7767ca  main -> main          EXIT=0
```

用 `--force-with-lease` 而非 `--force`：远端若被他人更新过会拒绝推送。

## 6. 已知限制

- **未做断电/中途失败注入测试**：`.gitattributes` 与 LFS 只是版本管理，**不宣称任何断电场景零丢失**。存档层的双槽与故障注入属 T038/T039。
- **LFS 只对一个 112 B 文件验证过**：尚未用**大文件**（如 `.blend`、贴图）实测上传/下载行为。T005 引入真实资产时应复验一次。
- **未配置 LFS 的 GitHub 存储配额检查**：公开仓库的 LFS 有带宽/存储限制，未核查。
- **`.gitattributes` 的 `*.exe` 规则**：`.gitignore` 忽略 `*.exe`，因此 Godot 导出的可执行文件默认不入库；T007 需交付时应用 `git add -f` 或改用 Release 附件。**这是有意选择**（发布二进制不进源码仓库）。
- 文本 `eol=lf` 规则会导致 Windows 上出现 `LF will be replaced by CRLF` 警告，属正常。仓库内统一 LF，工作区在检出时为 CRLF。
