## 6. 复测暴露的两个既有缺陷（都不是本轮引入）

### 发现① **鼠洞当前不是安全区**（重要，直接削弱 P3 的"同一地点对鼠=安全"）
- 数据：鼠进洞到 `hole_gap 0.13~0.26 m`（判定 ≤0.30 通过）后，`cat_min_to_hole 0.75~0.80 m`，
  两者水平距离 ≈ **0.5~0.7 m** < 攻击距离 `0.65 + 0.05` → 猫在洞外**能咬到洞里的鼠**，`hp 100 → 0`。
- **与冲刺无关**：把 `chase_sprint_enabled` 关掉（默认）仍复现 3/3。
- 这正好回答 T026 记的"**洞里能否被打中 = 未测（预期打不到）**"：**能被打中**。
- 影响：鼠的"往洞里跑"不是安全策略，只是延迟死亡 → P3 阶段门的"不同用途"实际只剩"位置差异"，没有"安全性"。
- 需要决策（三选一或组合）：① 洞内目标免疫/不可选；② 攻击的遮挡/可达复核对"洞内"更严（例如要求攻击者与目标的连线不穿过洞口平面）；
  ③ 让洞更深/洞内位置距洞心更远（改关卡几何，属 T030+）。

### 发现② **冲刺会把 AI 冲出无护栏平台，且掉落后没有处理**
- T023 的合成夹具 `split_platform`（两块平台 + 沟）里，开冲刺后猫**直冲下沟**：
  `MEASURE|F_stuck|pos=(0.0,-210.5419,-4.707025)|y=-210.54|on_floor=false|state=explore|failures=0`（8 s 掉 210 m）。
- 真实关卡 `l_courtyard` 是平地、无悬崖 → 当前不触发；但一旦 T030+ 加地形高差就会踩到。
- 处置：T023 该段**显式关冲刺**（本段验证"路径失败语义"），并新增声明断言 `F_sprint_off_for_path_semantics`；
  "AI 掉落后怎么办（重置/寻回/放弃）"作为待办交后续任务。

## 7. 为什么把开关默认关掉

- 打开后走查 3/3 都是"鼠被发现 → 被追上 → 咬死"（`hp 100→0`），但**根因是发现①（洞里也不安全）**，不是冲刺本身；
- 若在①未解决前默认打开，等于**用参数掩盖设计缺口**，且会把 T028 已验收的体验（W4 存活）直接打红；
- 平衡（猫该多凶、鼠该多脆）**属于产品规则**，按 `AGENTS.md` 需负责人同意后再改默认值。
- 因此本轮交付的是：**能力 + 参数 + 定量数据 + 明确推荐值（`3.0 m`）**，开关由负责人决定；
  回滚/调整只需改 `chase_sprint_enabled` 一个布尔或 `chase_sprint_min_gap` 一个数值，**不用改代码**。
