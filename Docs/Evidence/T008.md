### 0.1 过程中踩到并解决的一个引擎行为（值得记住）

抽出新类后，探针立刻报：

```
SCRIPT ERROR: Parse Error: Identifier "StepClimb" not declared in the current scope.
```

原因：`class_name` 的全局类注册在 `.godot/global_script_class_cache.cfg`，**新增 `class_name` 脚本后，
无头运行前必须先让引擎扫描一次**。处理：跑一次 `--headless --import`，缓存里出现 `&"StepClimb"` 后即正常。
→ 已记入 `Docs/Commands.md`（"新增 class_name 后先 import"）。

## 2. 数据真源与 `Parameters.md` 的一致性（**唯一真源**）

配置由测试**逐字段**与 `Parameters.md`（cm→m）核对，全部通过：

```
CONFIG|Cat|radius=0.160|half_height=0.240|total_height=0.480|max_step=0.120|jump=3.20
CONFIG|Mouse|radius=0.060|half_height=0.090|total_height=0.180|max_step=0.030|jump=0.00
```

- 断言覆盖 19 个浮点字段 + `species_id` + 食物类型 + 3 个能力布尔 + `capsule_height = 2×half_height`
  + `can_eat(自己食物)=true` / `can_eat(另一种)=false` + `validate_config()` 为空。两个 ID 还必须互不相同。
- 说明：`CapsuleShape3D.height` 是**含两端半球的总高**，所以猫 0.48 / 鼠 0.18（不是 0.24 / 0.09）。

## 4. **配置驱动的物理台阶实测**（T008 的核心验收）

每个物种各两个用例，全部走 `AnimalBody` + 其配置驱动的 `StepClimb`（全新世界，避免互相污染）：

```
STEP|Cat|   capsule_radius=0.160|capsule_height=0.480|step=0.120        |climbed=0.1203|max_x=2.017|reached=true
STEP|Cat|                                            |step=0.200（超限）|climbed=0.0000|max_x=-0.160|reached=false
STEP|Mouse| capsule_radius=0.060|capsule_height=0.180|step=0.030        |climbed=0.0290|max_x=2.017|reached=true
STEP|Mouse|                                          |step=0.120（超限）|climbed=0.0000|max_x=-0.060|reached=false
```

| 用例 | 期望 | 实测 |
|---|---|---|
| 猫上 12 cm（= `config.max_step_height`） | 上去 | 抬升 **0.1203 m**、水平到达 x=2.017 ✓ |
| 猫 20 cm | 上不去 | 抬升 0、被挡在 x=−0.160（台阶面）✓ |
| 鼠上 3 cm（= `config.max_step_height`） | 上去 | 抬升 **0.0290 m**、到达 x=2.017 ✓ |
| 鼠 12 cm | 上不去 | 抬升 0、被挡在 x=−0.060 ✓ |

**这就是 P1 要的"尺度差异实际成立"**：同一套代码、同一套组件，仅靠配置值就得到不同可达性。
