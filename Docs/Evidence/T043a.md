## 2. 时钟接缝

- 单一接缝：`scripts/core/game_clock.gd`（`extends RefCounted` + static；消费者 `const GameClock := preload(...)`，不用 `class_name`，避免 `--headless --script` 全局类缓存未刷新）。
- API：`now_ms()` / `is_fake()` / `use_fake(start_ms)` / `advance_ms(ms)` / `use_real()`。
- 生产实现：`Time.get_ticks_msec()`；`WorldDirector._process`、`hud.gd` Toast 到期、`save_manager.gd` 节流全部只读 `GameClock.now_ms()`。
- 世界时间注入范式（测试侧）：`GameClock.use_fake()` → `time_advancing` 保持 true → 每物理帧 `world_director.set_world_time(w + 1/60)` → `await physics_frame`。世界时间与物理帧严格锁步。
- 生产代码零测试分支：`_process` 只按 `now_ms()` 差推进；`time_advancing` 是既有暂停门闩语义；没有 `if is_fake()` 改写游戏逻辑的分支。

## 3. 批处理守卫

`Tools/t040_headless_batch.ps1`：每套 RED 判据（任一命中）：

1. 非零退出；
2. 无 `SUMMARY`/`RESULT` 或不可解析；
3. `checks <= 0`；
4. `fails < 0`；
5. `fails != 0`；
6. `RESULT|FAIL` 与 `failures=0` 矛盾；
7. 输出含 `SCRIPT ERROR`。

并账覆盖**全部**套件（含 RED），RED 行格式：`GUARD|<suite>|RED|cause=<reason>|exit=<code>|checks=<n>|fails=<n>`；整体非零退出。

### 5.1 t020 969 秒的三段结论（2026-11-06 复核）

**结论：不该这么慢。969.1 s = 904 s 连接待机 + 约 65 s 正常运行，与改造无关。**

| 假设 | 证据 | 判定 |
|---|---|---|
| ① 改后引入长等待/自旋 | t020 全文无 `create_timer`/`OS.*`/`Time.*`/`sleep`/`frames_drawn`；所有等待循环都有硬上限：`_run_seconds` 帧数 = `round(s*60)`（≤1200）、`_advance_frames(n)`、`_await_nav_ready` 240 帧且每 20 帧最多重烤 5 次；`_physics_step` 先 `set_world_time(+1/60)` 再 `await physics_frame`，不存在"等注入时间但没人推进" | **排除** |
| ② 机器挂起 | 系统日志 `Kernel-Power 506` 12:28:12「系统正在进入连接待机状态 原因: Lid」→ `507` 12:43:16「退出连接待机 原因: Input Mouse」= **904 s**。t020 run1 起止约 12:28:0x–12:44:0x；`969.146 − 904 = 65.1 s`，与正常耗时（run2 61.7 / run3 47.5 / 复跑 66.8、75.8 / 改前 58.7）同量级。同期 `Application 1002` 只是 SearchApp 挂起，与 Godot 无关；run1 其余 21 套耗时均正常（run1 合计 1560.0 s，扣除 904 s 待机 = 656.0 s，对比 run2 611.6 / run3 590.2） | **成立** |
| ③ 本来就是慢套 | 改前 7b6279a 工作树同一套 = **58.7 s**（164 checks/1 fail，旧测试的时间敏感缺陷）；改后 47.5/61.7/66.8/75.8 s。t020 世界时间累计约 60 s（F/G 段 15 s + 20 s 等），是全批偏慢套件之一，但不因改造变慢 | 部分成立，**不构成回归** |

### 5.3 t036 第二轮 `G4_world_time_reset` 红色与修复

- 现象：run2 `71/1`，`actual=0.564`（阈值 `<=0.2`）。
- 根因：t036 未接假时钟，`_advance_frames()` 走 `process_frame`，`world_time` 由 `_process` 的真实帧间隔累加；run2 那两帧恰好耗时 564 ms → 归零后立刻漂移。
- 修复：`_initialize()` 加 `GameClock.use_fake()`；世界时间只由 `_advance_world_ms()` / `set_world_time()` 显式推进。
- 验证：单套 ×5 全绿 72/0（5.2/6.2/7.2/7.2/7.2 s）。**整批 ×3 待重跑**。
