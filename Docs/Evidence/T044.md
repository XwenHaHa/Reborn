## 3. 推导

| 量 | 公式 | 结果 |
|---|---|---|
| 1080p / 720p 基线比 | 6.695 / 3.751 | **×1.78** |
| 每件猫（720p） | (3.892 − 3.762) / 31 | **0.0042 ms** |
| 每件猫（1080p） | (7.076 − 6.844) / 24 | **0.0097 ms** |
| 每件鼠（720p） | (3.809 − 3.757) / 60 | **0.00087 ms** |
| 每件巨石（720p） | (4.409 − 3.582) / 56 | **0.0148 ms** |
| 每件草丛（720p） | (3.945 − 3.760) / 24 | **0.0077 ms** |
| 每 draw call（720p） | 猫 4 draw/件 → 0.0042 / 4 | ≈**0.001 ms** |
| 每万渲染三角（角色，720p） | 0.0042 / (4,036/10,000) | ≈**0.010 ms** |

判定：
1. **几何不是瓶颈**：32 只猫（prim +128,536，≈13 万渲染三角）只多 **0.130 ms**；64 块巨石（prim +1,080,000）多 **0.827 ms**。同一场景下，**屏幕覆盖率（填充/着色）与 draw call** 才是主导项（巨石几乎不加 draw 却比猫贵 3.5×/件，因为它占屏更久）。
2. **分辨率主导**：×1.78。任何预算不写档位就没有意义，因此验收基线定 720p、余量档定 1080p。
3. **骨骼有固定开销**：鼠（3,602 tris）每件 0.00087 ms，与三角数不成比例，说明按件计的成本主要来自 4 个 draw call + 皮肤准备。
4. **同口径警示**：`prim_peak` 是引擎计数，包含阴影/双面等 pass 的重复计数（巨石 ≈15,000 prim/件，而 ART03 记录资产本身 7,500 tris）→ **该列只用于同口径比较，不作为面数断言**。

## 4. 预算（已写入 `Docs/ART_ASSET_SPEC.md` §2.4）

| 层 | 阈值 |
|---|---|
| 目标 | 60 fps = 16.67 ms，渲染 ≤ **11.67 ms（70%）** |
| 场景总增量 | **≤ +2.0 ms @1080p 或 ≤ +40 draw call**（先到者为准；1080p 余量 4.97 ms 的 40%） |
| 角色单件 | ≤ 40k tris / ≤ 2 材质槽 / ≤ 4 draw；**同屏 ≤ 12 只**（≈0.12 ms @1080p） |
| 鼠单件 | ≤ 20k tris / ≤ 2 槽 / ≤ 4 draw |
| 环境单件 | ≤ 15k tris / ≤ 2 槽 / ≤ 2 draw；占屏 >15% 的大件按 0.009 ms/万渲染三角 @720p 复核 |
| 静态装饰 | 必须共享材质、优先 MultiMesh/合批；每多 1 draw ≈ 0.001 ms @720p |
| 贴图 | ≤ 2048²、材质槽 ≤ 2（沿用既有契约，本轮未测带宽） |

与 v1.0 固定面数表的关系：15k–40k（猫）/5k–20k（鼠）/3k–15k（洞口）等**全部落在实测余量内**，降级为**结构建议**，不再是硬上限；**仍不允许为面数牺牲关键结构**（洞净空 0.24×0.30、耳/吻/爪轮廓）。

## 8. 边界与未验证

1. **只测渲染**，不含 AI/物理/寻路；真实帧预算还需叠加逻辑（22 套批处理只证明功能，不测帧时）。
2. 单机单 GPU（T600 4 GB，低端笔记本）；**未测 4K、未测 1440p、未测垂直同步/无边框窗口**，也未测多 NPC 同屏 + AI 同时运行的组合。
3. `prim_peak` 含 pass 重复计数，**不能**当成"资产三角数"。
4. 预算的 70% 渲染占比与 +2.0 ms 增量是**本任务定的工程判断**，不是策划/负责人给的硬指标——若后续定 30 fps 或 144 Hz 目标，本表需重跑（探针已入库，一条命令可重测）。
5. 清单补齐的是**当前包内**资产；`references/_downloads/` 里未采纳的候选仍只在 manifest 候选区（未进包）。
