probe(T009): 台阶 MaxStepHeight 能力达成 6/6

从"未达成"推进到"达成"。共定位并修复三个真实 bug，最后的根因是
"探测前移量不足"。

最终结果（5 次运行，每次 6 条目 6 OK 0 MISMATCH，签名唯一）：
  Cat_3cm_should_pass      OK
  Cat_12cm_should_pass     OK   (实测抬升 0.120，与阈值精确吻合)
  Cat_20cm_should_block    OK
  Mouse_3cm_should_pass    OK
  Mouse_12cm_should_block  OK
  Mouse_20cm_should_block  OK

三个 bug：
1. 逐帧棘轮：胶囊圆底贴棱角每帧抬一点点，增益序列
   0.0921 -> 0.0337 -> ... -> 0.0012，每帧都小于阈值，累积爬上
   19.8cm。改为以"当前落脚面"为基准算总抬升。
2. _base_y 恒为 INF：基准更新条件含 velocity<0.05，但该分支会先清零
   速度再被 move_and_slide 覆写。改为只用 is_on_floor()。
3. 探测前移量不足（关键）：前移量只有一帧位移约 1.67cm，而胶囊半径
   16cm，底心根本没越过台阶面，下探永远撞在台阶顶棱上：
     normal=(-0.868, 0.497) 夹角 60 度 > floor_max_angle 45 度
     -> 判定为墙面不可站立 -> 拒绝
   实测把抬高量加到 0.29 也没用，证明问题不在抬高量。

修复（三处，缺一不可）：
- 抬高量与阈值解耦：probe_raise = max_step*2 + 0.05
  (胶囊圆底贴棱时底心比台阶顶还低，要抬过台阶高度本身)
- 前移量与帧位移解耦：probe_forward = max(RADIUS_SAFE=0.20, 帧位移)
- 保留可站立面判据：要求 n.y >= cos(45 度)，防"踩棱"

设计要点：抬高量与前移量只是探测参数，不承担阈值把关；
阈值只由最终 total_gain 校验决定，故两者可宽裕取值而不影响正确性。

独立发现（重要）：裸 move_and_slide 的行为取决于 胶囊半径/台阶高度 之比。
  猫(16cm) 能滚过 3cm，过不了 12cm
  鼠(6cm)  连 3cm 都滚不过
=> 鼠的 3cm 阈值不能依赖引擎默认行为，这是必须自实现的直接原因。
