## 3. 过程中发现并写清的三个环境/夹具事实（都不是游戏缺陷）

1. **`--script` 下 `_read_input()` 每帧用 Input 覆盖 `want_pounce` / `want_interact`**
   ⇒ 手写意图的夹具必须先 `player_controlled=false`（T021/T022 同口径）；交互要走检测器入口
   `interaction.press_interact()`（`want_interact` 在非玩家控制时不消费）。
2. **`--script` 里引擎不设 `current_scene`**，而 `MainEntry._ready` 的**读档门**（T037 D9 的"正式运行"判定）
   要求 `current_scene == self` ⇒ 夹具按 `_ready` 的**同一顺序**补跑
   `_load_saved_game()` → `apply_saved_snapshot(snap, false)` → 再走**玩家侧入口** `continue_game()`。
   断言的是生产代码路径（读档 + 继续门），不是自造状态。
3. **读档位置回退是设计行为**：本套件把玩家放到 `(2.00, 21.00)` 存档，存档文件里写的确实是 `(2.00, 21.00)`；
   读回却是 `(0.71, −0.71)`，`last_position_resolution.reason = **nearest_nav**`
   —— 该点不在**鼠**的导航层上，T040 把它吸附到最近导航点。**这是 T040 的安全回退，不是缺陷**；
   精确位置往返属 T037/T040 的契约（本套件只断言"有限且在场地内"）。
