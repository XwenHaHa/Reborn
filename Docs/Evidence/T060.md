## 3. 修的这一个：昼夜光照**限频**

### 3.1 为什么它会贵

原 `_process` 只要世界时间变了就 `apply_now()`，而世界时间**每帧都在变** ⇒ 每帧都写
`DirectionalLight3D`（旋转/能量/颜色）+ `Environment`（环境光能量/来源/颜色）+ `Sky` 材质的 `energy_multiplier`
≈ 8 个属性，**每帧触发渲染服务重推环境资源**。

### 3.2 改法（`scripts/systems/day_night_director.gd`）

- 新增 `MIN_APPLY_INTERVAL = 0.25`（世界秒，≈4 Hz）与 `_last_applied_world_time`；
- 自动路径加门：距上次真正写入不足 0.25 s 就不重推；**显式 `apply_now()` 不受限制**；
- `bind_level()` 重置基准，**时间跳变（读档 / 休息快进 / 反向调时间）差值必然 ≥ 0.25 s ⇒ 一定重推**；
- 语义不变：采样仍是 `world_time` 的**纯函数**，只是"多久写一次"变了；一天 1200 s 在 4 Hz 下最多晚 0.25 s（1/4800 天）。

### 3.3 复测（修后，同机位/同帧数）

| 变体 | 修前 720p | 修后 720p | 修前 1080p | 修后 1080p |
|---|---|---|---|---|
| `all` | 5.249 / p95 5.940 | **4.524 / 5.132**（重复 4.552 / 5.152） | 8.368 / 8.671 | **7.870 / 8.506**（首次采样 8.396，含 1 帧 155 ms 的管线编译尖峰） |
| `no_daynight` | 4.415 / 4.564 | 4.433 / 4.550 | 7.703 / 7.858 | 7.643 / 7.764 |
| **昼夜项差值** | **0.83 ms** | **0.09–0.12 ms** | 0.67 ms | 0.23 ms |

⇒ 720p 整帧 **5.249 → 4.52 ms（−14%，≈190 → 221 fps）**；1080p p50 **8.410 → 7.657 ms（−9%，≈119 → 131 fps）**；
昼夜这一项的相对代价从 0.8 ms 级降到 0.1 ms 级。

## 6. 过程中修正的错误（如实记录）

1. **一次多行替换把 `day_night_director.gd` 改出重复行**（同一行被加了两次、`return sample` 丢失）：
   读到 diff 里出现重复立即发现问题，改为**整文件重写**并用断言（28/28）验证。教训：**多操作编辑不要用相互重叠的行号区间**。
2. **判据依赖真实帧 delta**（`B1_small_step_no_apply` 假红：headless 帧 delta 不稳，额外帧时间把"小步"补过阈值）：
   夹具改为先 `time_advancing = false`，让**只有 `set_world_time()` 能移动时间**，变体间完全确定。**是夹具错，不是生产缺陷**。
3. **1080p 首次采样出现 155 ms 单帧**：是切分辨率后管线/着色器重编译的一次性尖峰；
   所以两分辨率都按"平均 + p95 + 最大值"报，并用重复采样（`all` 各测两次）交叉验证。
