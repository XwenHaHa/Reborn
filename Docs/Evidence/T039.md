状态：**done**（2026-11-04）。存档格式、T038 队列语义、状态机与 `last_safe_spot_id` 均未改动。
规格：[T039.md](../Tasks/T039.md) §1–§9。

## 1. 口径与边界

- 读档来源只有主档与 `.bak`；`.tmp/.old/.bak.tmp` 是写入中间态，**永不载入**。
- 损坏源一律**改名隔离**（`*.corrupt-<unix>`，同名追加 `-1/-2…`），**不删除**。
- 双坏：两份都隔离 → `status=corrupt` + 精确文案「存档损坏，已隔离；未载入」→ 读档零写入；
  `MainEntry` 阻断本会话开新局（选物种被拒、`save_now` 返回 `blocked`、退出不保存）。
  恢复路径为**重启**（隔离后主路径为空 → `none` 新局）；会话内“确认开始新游戏”留给 T041。
- 主档缺失 + `.bak` 损坏 → 隔离 `.bak` 并返回 `corrupt`（不再静默 `none`）。
- 测试钩子 `write_delay_phase/write_delay_ms` 与 `CaptureRun -KillOnMarker` **仅测试**，生产默认空/0/关闭。

## 2. 四类损坏场景结论表（玩家看到什么 / 文件变成什么样）

| 场景 | 读档结果 | 玩家看到 | 文件最终状态 |
|---|---|---|---|
| `.tmp` 半截 + 主档完好 | `ok`（内容/`revision` 来自主档） | 正常进入（菜单/读档），无提示 | 主档字节不变；`.tmp` 保留到下次保存；下次保存成功并清理 `.tmp` |

| 只有陈旧 `.tmp`，无主档/备份 | `none` | 正常新局菜单 | 不拿 tmp 冒充存档；下次保存创建新主档并清理 `.tmp` |
| 主档损坏 + `.bak` 好 | `recovered_backup` | 「主存档损坏，已从备份恢复」 | 主档 → `.corrupt-*`（原坏内容保留）；`.bak` 不动；载入备份 `revision` |
| 主档缺失 + `.bak` 好 | `recovered_backup` | 「主存档缺失，已从备份恢复」 | `.bak` 不动；无主档 |
| 主档缺失 + `.bak` 损坏 | `corrupt` | 「存档损坏，已隔离；未载入」 | 坏 `.bak` → `.bak.corrupt-*`；无主档 |
| 主档 + `.bak` 都损坏 | `corrupt` | 菜单保留并显示「存档损坏，已隔离；未载入」；选物种被拒 | **两份都隔离**、原路径为空、坏内容完整保留；**零写入**、无新档 |

写入失败（`tmp_open`/`disk_write`/`rename`）：`write_failed`，主档与 `.bak` 字节不变、无 `.tmp/.old`；
`bak_copy`：`ok` + warning「存档已保存（备份更新失败）」，主档前进、旧 `.bak` 保留。
连续失败与失败后退出均不升级：两份旧档仍可解析，`active_writes=0`、队列为空。

## 9. 实现要点

- `save_manager.gd`：
  - `last_quarantine: Array[String]`；`_quarantine_file(path)` 通用隔离（唯一后缀、失败保留原文件）。
  - `load_game()` 主档缺失时**完整走** `_recover_missing_main()`（不再把 `corrupt` 降级成 `none`）。
  - `_recover_from_backup()` 在 `.bak` 解析失败/结构损坏时隔离 `.bak`，统一 `_corrupt_result()`。
  - `_test_pause(phase)` 仅在 `write_delay_phase == phase && write_delay_ms > 0` 时打印标记并 `OS.delay_msec`；
    四个时点：`before_tmp`、`tmp_mid`（store+flush 后、close 前）、`rename_gap`（main→old 后、tmp→main 前）、
    `bak_rotate`（`.bak.tmp` 复制后、轮换前）。
- `main_entry.gd`：`_load_blocked`（`_load_status=="corrupt"`）；`is_load_blocked()`；
  `select_species()` 阻断；`save_now()` 返回 `blocked`；`_exit_tree()` 阻断时跳过退出保存。
- `CaptureRun.ps1`：新增 `-KillOnMarker/-KillGraceMs/-KillExitCode`；`.winmon.log` 增
  `kill_marker_seen/terminated/killed/kill_at_ms`；默认关闭，既有取证零影响。
  监视器用 `FileShare.ReadWrite` 只读打开子进程 stdout 日志（普通 `ReadAllText` 会被写句柄拒绝）。
