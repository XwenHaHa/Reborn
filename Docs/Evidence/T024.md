## 6. 过程中改掉的问题（都记在这里，不藏）

1. **测试夹具自相矛盾 3 处（写套件时的设计错误，不是实现缺陷）**：
   - C/D 段用 8 m 宽的实心墙制造遮挡，但那堵墙**同时挡住猫的去路** → 猫顶着墙 → 1 s/3 次/`WAIT` 的失败链（≈4.3 s）会**早于** 5 s 搜索超时 → 永远看不到 `search_timeout`，`arrived` 也永远不会发生。判据改成"保持看不见（把猎物搬到视野外）+ 撤掉遮挡墙，让猫真的走到快照点/洞口"。
   - F 段原本把"隐藏的猎物"瞬移到猫正前方 6.5 m / 9.0 m —— 那两个位置**仍在视锥与视距内** → 会按 C7"重新发现"转 `CHASE`，快照类断言必然不成立。改成搬到视野外（身后 25 m / 14 m），并**加前置断言**"猎物确实看不见"。
   - B6 段连续换位用了 `40°/80°/120°`：**120° 超出 60° 半角** → 变成"看不见 → 搜索"。改成 `-30°/0°/+30°`。
2. **`AnimalBody.ai_enabled` 不是"暂停开关"**：`_sync_ai()` 在关掉时 `queue_free()` 掉 AI 实例，再打开时**重建一个新实例**。
   本会话想在 H2 临时"停 AI 摆位"，结果旧引用失效（`Nonexistent function … in base 'Nil'`）并**崩溃**（`0xC0000005`）。
   夹具改成"**重建一对新猫/鼠**"（新猫 `patrol_enabled=false`，摆位后显式 `look_at`）。
   → 结论：**测试里不要用 `ai_enabled` 做临时暂停**；要停就换掉/重建身体。
3. **瞬时 `state_reason()` 会被同一帧内的后续步骤覆盖**：`lost_sight` → 同帧被 `_step_search` 写成 `moving_to_last_seen`；
   `reacquired` → 同帧被 `_step_chase` 写成 `chasing`。**触发原因**改用 `state_changed` 的**转移账**断言（T023 E 段同口径），
   并保留 `C1_transition_lost_sight` 一条显式断言证明"确实发生过"。
4. **窗口运行时 `pounce` 是鼠标左键**（`project.godot`）：捕获日志里 `pounces=1` 是**一次真实点击**造成的，不是 AI 扑击
   （AI 路径不调 `start_pounce()`；套件 B8 断言 `pounce_count == 0`）。同一场追逐的 `escapes=1` 也证明**猎物活着**（没被捕获）。
   → 记入 §7：窗口运行会受到真实输入事件干扰，`--headless` 套件不会。

## 7. 未验证 / 限制（不得当成已通过）

1. **真实按键输入**（WASD/Space/Shift/Ctrl、鼠标左键扑击）仍未做人工试玩 → T028/T063 的外部体验验收不受本任务影响（仍 NOT-RUN）。
2. **多洞口优先级**（搜索时若有多个鼠洞标记该等哪个）→ 本任务只做"最近且 ≤ `hole_search_radius` 的那一个"；细化属 T026/T027。
3. **"洞口不可达"的几何/导航验证**属 T026（本任务假设 T012 的猫层导航已经保证猫进不去洞；断言 E4 只保证"停在洞外 ≥ 半径"）。
4. `escape_count` 落 `LifeRecord` / `encounter_id` 持久化 → P4（T030+）；本任务只有 AI 侧账本 + 信号。
5. **`APPROACH → CHASE` 的判据是"跳变 > 0.5 m"**（`chase_trigger_move`，实现默认值）：连续低速奔跑（鼠 1.5 m/s → 每帧 0.025 m）**不会**切 `CHASE`，
   而是留在 `APPROACH` 继续重设目的地 —— 行为等价（两者都是"追到 0.65 m 停住"），只有 `state` 名与 `reason` 不同。
   真实追击链的更细切换（体力/扑击时机）属 T025，值待负责人并入正式起测值。
6. 视觉只有 **2 张静态图**（追击中 / 搜索到点），没有连续视频；"追击的连续性"靠套件数值断言（B3/B6 三次再收敛）承担。
