## 4. 决策落地（对 `Docs/Tasks/T016.md` §4）

- **D1 只查 area、不动身体 mask**：`intersect_shape` + `collide_with_areas=true`、`collision_mask = 1 << 2`，`exclude` 掉身体 RID。
  **实测有效**：Area3D 目标能被查到（T009/T010 的 `collision_mask == world_static` 断言仍全绿）。
- **D2 原点 = 眼睛**：`_eye_position()` 优先用 `AnimalBody.eye_position()`（相机全局位置），无相机时"中心 + 半高"。
- **D3 3D 距离**：`B_cat_vertical_counts` 实测覆盖（0.98 水平 + 0.50 竖直 = 1.10 > 1.00 → 不可用）。
- **D4 边界含等号**：用 ±2% 余量验证两侧（0.98/1.02、0.44/0.47）。
- **D5 排序确定性**：`priority` 降序 → 距离升序 → ID 字典序（`D_tie_break_by_id`、`D_order_independent` 双向验证）。
- **D6 时长走世界时间**：`tick(world_time)` 只看传入时间；暂停（`time_advancing=false`）期间真实世界时间位移 0.0000、进度冻结。
- **D7 按住/松开**：`animal_body._update_interact_input()` 取按键沿 → `press_interact()` / `release_interact()`；立即式目标按下即提交。
- **D8 鸭子类型**：只 `has_method()`；`DuckTarget`（**不是** `Interactable` 子类）能选中并提交，缺方法的节点被跳过并计数。

## 5. 本任务踩到的坑（写进 `Docs/Commands.md` §2.12）

1. **`Area3D` 自带 native `priority`（float）**：`@export var priority: int` 直接冲突 → `Parse Error: Member "priority" redefined`。
   改成 `interaction_priority`，检测侧先读它、再退回 `priority`（给鸭子类型节点用）。
2. **`add_child()` 之后再设 `global_position` 会让物理体在原点存在一帧**：新加的 `StaticBody3D` 与身体/地面重叠 → 引擎把**身体**沿最短轴 depenetrate
   推开。实测：加一个 2 m 外、完全不可能碰到的墙，身体仍被推离 **0.1877 m**（`(0,0.240127,0)` → `(0,0.238788,0.187743)`），
   连带让交互距离从 0.90 变成 1.09 → 误判成 `range` 而不是 `occluded`。
   **修法：先设 `position` 再 `add_child()`**（夹具全部改过来）。**这个坑会污染任何"平地 + 生成物"的测试**，不只是交互。
3. **身体每物理帧会 `detect()`**：`target_changed` 事件数取决于"目标添加顺序 × 帧数"，不能硬断言"恰好 1 次"。
   断言改成"最后一次事件 = 当前目标"+"同目标不重复发"（计数前后不变）。
4. **别把合成 `tick()` 与真实帧混用**：`press_interact()` 后用假时间推进，再让真实物理帧喂时间，进度会**倒退**（`_last_world_time` 被拉回）。
   暂停断言改为"真实推进 0.2 s → 记录进度 → 关 `time_advancing` 推 0.3 s → 进度不变"。
5. `InteractionDetector` 的进度基准要可读（`interaction_start_time()`），否则断言只能用"身体当前时间"近似（差一帧就偏 0.03）。
