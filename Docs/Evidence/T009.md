## 4. 两条决策的落地与证据

### D1：`camera_offset_z` = 相对胶囊中心的**竖直（本地 +Y）**偏移
- 断言锁定：`camera_offset_axis == "y"`、`camera.position.y == 0.10`、`camera.position.x/z == 0`；
- **运行时旁证**：lab 场景换猫后，捕获工具的默认帧打印
  `CAP|active_camera=Camera3D` + `CAP|camera_global_pos=(0.0, 0.440195, 0.0)`，
  即眼点 = 猫站立中心 0.34 + 0.10 ✓（不是"挂在屁股后面"）；
- 蹲下时相机本地 y = `0.10 − 0.09 = 0.01`（断言 `crouch_camera_local_y_lowered`），
  世界眼高 0.260（= 0.250 + 0.01），相对胶囊顶始终低 0.14（`eye_below_capsule_top_invariant`）。

### D2：新增 `crouch_half_height`（`Parameters.md` 里原本没有）
- 猫 **0.15**（蹲高 0.30）/ 鼠 **0.06**（蹲高 0.12）；`validate_config()` 断言
  `0 < crouch_half_height < capsule_half_height`；两物种都通过。
- 试验世界的低顶净空取 **0.42 m**，夹在"猫蹲高 0.30"与"猫站高 0.48"之间
  —— 工具与测试**双方**都断言这个夹逼关系，谁改了几何都会失败。
- **仍待负责人确认**（§9）。

## 5. T009 查出的两个真实缺陷（都在 `scripts/characters/step_climb.gd`）

### 5.1 落点高度用"运动测试位移"，形状越小停得越早 → 鼠永远上不了自己的台阶
启用 T009 的重力（`AnimalBody._physics_process`）后，T008 的鼠 3 cm 用例**立刻回归失败**
（`step_mouse_on_max_step_reached = false`）。实测定位（`Art/Probes/*`，诊断脚本见下）：

| 物种（胶囊半径） | 下探探针"提前停下"的高度 | 于是 3 cm 台阶被算成 |
|---|---|---|
| 鼠（0.06） | **2.655 mm** | 3.256 cm |
| 猫（0.16） | 0.249 mm | 12.025 cm |

`params.margin` 取 0.001/0/−0.001/−0.005/−0.02 结果**完全相同**（说明不是 margin 的问题）。
鼠的 3.256 cm 超过了上界 `max_step + tolerance = 3.2 cm` → 台阶被拒 → 卡在台阶面。
旧的"通过"是**假通过**：当时身体没有重力、悬在地面上方 2 mm，`_base_y` 一直是 INF，
`base` 退化成起点 y，抬升量因此被少算。

**修复**：`_landing_y()` 改为用**接触点 + 法线**解出可站立面在胶囊轴线处的高度，
再换算身体中心高度（含斜面项 `r(1/n.y − 1)`）；非胶囊形体才退回旧的位移法。
修复后：鼠 3 cm 抬升 **0.0299**（真值 0.03）、猫 12 cm 抬升 **0.1199**，T008 回到 114/114。

### 5.2 斜坡被当成"无数级小台阶" → 猫沿坡"飞"上去再摔下来
T009 第一次跑斜坡：`gain=0.001 m`、`forward=6.653 m`、`on_floor_all=false`（2.5 s 走 6.65 m ≈ 2.66 m/s，
比 walk 1.8 还快）。逐帧探针（`Art/Probes/`）显示：每帧 `try_step_up` 成功一次，
把身体**前移 `radius_safe + 本帧位移 ≈ 0.23 m`**（该位移是"越台阶竖直面"用的校准量），
25° 坡每帧抬升 0.095 m < 阈值 0.122 m → 每帧都被接受 → 猫以 0.23 m/帧"上台阶"冲到坡顶越界摔下来。

**修复**：把"前方障碍"的判据从 `test_move()` 的布尔升级为运动测试结果，
**若真正阻挡本次运动的接触面是可站立面（`n·dir < 0` 且 `n.y ≥ cos45°`）就判定为斜坡，不做台阶处理**，
交给 `move_and_slide()` 顺坡走。
```gdscript
if n.dot(d) > -0.05: continue   # 脚下地面的接触（法线竖直、点积 0）必须排除，
                                # 否则猫再也上不了任何台阶（T008 会直接失败——实测踩到）
```
修复后斜坡：`gain=1.107 m`、`forward=3.837 m`、`airborne_frames=0`、`worst_stuck_frames=0`，
逐帧水平速度 1.478 m/s + 垂直 0.690 m/s（= 1.8·cos25° / 1.8·sin25°，与 `move_and_slide` 的斜面投影一致）。

> 两个缺陷都不是"调容差"能解决的：改的是**判据**，而且都有实测数据支撑。

### 5.3 已知未修的遗留（记录，不在 T009 范围）
台阶抬升成功时会**瞬移 `radius_safe`（0.2 m）水平距离**（`try_step_up` 里"越过台阶竖直面"的校准量）。
对单级台阶是"跳一下"的手感问题（不是穿透：位移方向是面朝方向的合法侧），
但在多级/窄台阶与真实关卡里会被玩家感觉到。**建议 T011/T013 处理**（改成只抬起 y、由 `move_and_slide` 推进）。

### 7.1 出图过程中踩到的两个坑（都已修，且**都不是靠"看图"发现的**）

**坑 1：视觉模型会漏"小而暗"的目标 → 改用客观差异法。**
第一版低顶第三人称用的是**俯视**机位，紫色板把蹲着的猫整个遮住；换平视机位后仍有一次模型答"板下是空的"。
**没有据此下结论**，改用不依赖语义判断的办法：同一机位拍"无猫 / 有猫蹲在板下"两张、逐像素求差：
```
DIFF|size=1280x720|sampled_changed=4593|bbox=(564,310)-(716,460)
```
→ 有 **152×150 px** 的区域确实因猫而变化（≈0.30 m 物体在 1.7 m、45° FOV 下的理论尺寸）；
把该区域裁出来单独提问，模型才给出「呈圆形/球状轮廓、深灰或深褐灰，很可能是蜷缩的身体；右上方有紫色矩形板」。

**坑 2（更隐蔽）：`await process_frame` 读到的可能是"上一帧"，换机位后两张图字节完全相同。**
`tp`/`fp` 两图**文件名不同、内容 MD5 相同**（`C1ECCAEF8C01` = `C1ECCAEF8C01`）暴露了它 ——
而日志里 `active=T009Camera` / `active=Camera3D` 明明已经切换。修法：读像素前等真正画完的一帧：
```gdscript
await RenderingServer.frame_post_draw
await RenderingServer.frame_post_draw
```
修完后三对图的 MD5 全部不同（`ramp` 5F2C56…/BE26E8…、`low_ceiling` C522F0…/BEF4A8…、`platform` 8DE19B…/BCDC4B…）。

> **教训（给后面的人）**：视觉证据的"文件存在 + 名字对"**不代表内容对**。
> 换机位/换视角后，用 **MD5 或像素差**确认两图真的不同，再拿去判读。
