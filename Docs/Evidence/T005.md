### 1.1 本体缺陷（已修）：导出 kwargs 探测方式错误

第一次运行 `PROBE|FATAL|export_format_kwarg_unsupported`：脚本用
`bpy.types.EXPORT_SCENE_OT_gltf.bl_rna.properties` 取算子参数，实测该 RNA **只有 14 个基础键**
（`bl_idname`/`bl_label`/`options`...），于是把 10 个真实 kwargs 全部误判为"不支持"。

诊断（`hasattr` + `get_rna_type()` 实测，未凭记忆）：

```
DIAG|cls_rna_key_count=14      ← bpy.types.EXPORT_SCENE_OT_gltf.bl_rna（不能用）
DIAG|op_rna_key_count=51       ← bpy.ops.export_scene.gltf.get_rna_type()（正确来源）
DIAG|prop|export_format|type=ENUM|items=GLB,GLTF_SEPARATE,GLTF_EMBEDDED|default=GLB
```

修正后 `unsupported=none`，导出真正执行。**教训**：算子参数签名要从 `get_rna_type()` 读，不要从基类 RNA 读。

### 2.1 轴向实测（**与文档原表格不符，已改正文档**）

Blender 位置 → Godot 位置（引擎读回的真实 `position`）：

| 对象 | Blender | 期望（实测映射 `(x,y,z)→(x,z,−y)`） | Godot 实际 |
|---|---|---|---|
| `Marker_Front`（Blender 前 = −Y） | `(0, −2, 0)` | `(0, 0, +2)` | `(0.000000, 0.000000, 2.000000)` |
| `Marker_Top`（Blender 上 = +Z） | `(0, 0, +2)` | `(0, +2, 0)` | `(0.000000, 2.000000, 0.000000)` |
| `Marker_Right`（Blender 右 = +X） | `(2, 0, 0)` | `(2, 0, 0)` | `(2.000000, 0.000000, 0.000000)` |

**结论**：`+Z`-up → `+Y`-up 正确；但 **Blender 的 −Y（前）映射到 Godot 的 +Z（身后）**，
即按"面朝 −Y"建的角色导入后会**背对** Godot 的相机前方。这是 glTF 的约定（模型正面朝 +Z）。
已在 `Docs/BlenderPipeline.md` 写明**本项目角色资产约定：在 Blender 里面朝 +Y**。
未做任何手工旋转（导出器负责转换）。

### 3.1 运行中碰撞（"素材与碰撞在运行中正确"）

### 3.2 本测试自身的一个真实缺陷（已修）

第一次运行 `landed_on_probe_top FAIL`、`step_up_height_m=2.7599`（等于瞬移高度 3.0−0.24）。
根因：`CharacterBody3D.is_on_floor()` 在**瞬移后**仍返回**上一帧**的状态，
`_fall_until_rest` 的 `if is_on_floor(): break` 立刻退出，玩家根本没下落。
修正：瞬移后先推进一帧（施加一帧重力 + `move_and_slide()`）并 `await physics_frame` 再判定。
修正后连跑 3 次全部稳定通过。
