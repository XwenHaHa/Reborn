## 3. 关键实现（两处决策落地）

**D1 时间源唯一**：`SurvivalController` 不读任何 `delta`，只接**世界时间**：

```gdscript
func tick_to(world_time: float) -> float:
	if is_nan(last_world_time):      # 第一次只对齐，不消耗（否则出生瞬间会按"从 0 到现在"扣一大批）
		last_world_time = world_time
		return 0.0
	var dt := world_time - last_world_time
	if dt <= 0.0:
		return 0.0                   # 时间没走（暂停）或时钟回退（读档）→ 不消耗、不回退数值
	last_world_time = world_time
	_accum += dt
	while _accum >= UPDATE_INTERVAL - 1e-9:   # 累计到 0.2 s 才结算
		_apply_interval(UPDATE_INTERVAL)      # 但用的是**累计到的实际时间**（D2）
		_accum -= UPDATE_INTERVAL
	return dt
```

`AnimalBody` 每物理帧 `survival.tick_to(world_time_now())`；`world_time_now()` 取 Autoload `WorldDirector`，
**只有在拿不到单例的环境里**才退回"按物理帧累计"的兜底时钟（两套时间源不会同时用，见代码注释）。

**暂停为什么自动成立**：世界时间由 `WorldDirector._process` 推进，而树暂停时 `_process` 不跑 →
`world_time` 不动 → `dt = 0` → 不消耗。显式门闩（`time_advancing = false`）走同一条路。

## 5. 实测数据（原样 `MEASURE|`）

```
MEASURE|world_director|node=WorldDirector:<Node#…>|paused_ok=true
MEASURE|consumption|Cat|elapsed=4.00|hunger=99.6800|thirst=99.7600|stamina=100.0000      # 损失 0.32=0.08×4 / 0.24=0.06×4
MEASURE|consumption|Mouse|elapsed=4.00|hunger=99.6000|thirst=99.6800|stamina=100.0000    # 损失 0.40=0.10×4 / 0.32=0.08×4
MEASURE|frame_rate|Cat|60s|30Hz=4.8000|60Hz=4.8000|144Hz=4.8000|spread=0.000000          # = 0.08×60
MEASURE|frame_rate|Mouse|60s|30Hz=6.0000|60Hz=6.0000|144Hz=6.0000|spread=0.000000        # = 0.10×60
MEASURE|pause|run=99.9360|paused=99.9360|resumed=99.8560                                 # 暂停期间完全不变
MEASURE|stamina|delay=1.00|regen=18.0|after_spend=70|after_delay+0.2=73.60|max=100.0
MEASURE|long_frame|dt5s_hunger=99.6000|rewind=0.000000|tiny_1s_hunger=99.9200            # 5 s 一次结算=0.40；时钟回退 0 消耗；1000 帧 1 s=0.08
MEASURE|integration|body|elapsed=2.001|consumed=0.1600|expected_max=0.1601               # 真实身体按世界时间掉饥饿
MEASURE|debug_hud_survival_line|survival: health=100.0 hunger=100.0 thirst=100.0 stamina=100.0  world_time=4.3
```

**说明（口径）**：
- C/D 两节的 `tick_to()` 序列**先对齐到 0**（第一次调用只对齐），所以"4 s / 60 s"的期望值能精确对上；
- 帧率无关的判据是双重的：**①** 三条步长两两差 ≤ `rate × 0.2`（一次结算间隔）；**②** 每条都落在
  `[(T−0.2)×rate, T×rate]` 内。本次实测三条**完全相等**，所以 spread = 0（比判据更严）；
- 暂停断言同时查了"**世界时间增量为 0**"与"**数值不变**"两件事，避免"数值恰好没变但其实时钟在走"的假通过。

## 6. 过程中修掉的问题（都因为实测）

| 现象 | 根因 | 处理 |
|---|---|---|
| C/D 两节消耗少了一个 0.2 s 结算 | `tick_to()` 第一次调用**只对齐**（防止出生瞬间按"从 0 到现在"扣一大批），测试却从 0.2 s 开始计 | 测试里先 `tick_to(0.0)` 对齐 → 期望值与实现语义一致 |
| E 小节**卡死**（靠 `--quit-after` 才退出） | 树暂停时 `world_time` **根本不走**，而我的辅助函数是"等世界时间前进 seconds 秒" → 死等 | 暂停段改为**固定帧数**等待 + 断言"世界时间增量为 0"；辅助函数加 `not paused` 安全阀与帧数上限 |
| 5 个脚本 check-only 报 `Identifier "SurvivalState" not declared` | 新增 `class_name` 后**全局类未注册** | 按 `Docs/Commands.md` §8 先跑一次 `--import`，再逐脚本 `--check-only`（全 0） |
