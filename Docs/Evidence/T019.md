## 4. 决策落地（对 `Docs/Tasks/T019.md` §4）

- **D1 AI 是组件**：`AnimalAI extends Node` 挂在身体下；身体只执行 `move_intent`（AI 不直接改位移）。
- **D2 世界时间**：所有计时用 `world_time_now()` 的差（`state_elapsed` / Alert 0.3 s / 失败窗 1 s / `WAIT` 1 s），暂停自然不推进。
- **D3 导航层反查**：`_resolve_nav_layer()` 扫 `NavigationRegion3D` 的 `metadata/species` → 实测得到鼠层 1，来源标记 `metadata`。
- **D4 共用交互规则**：NPC 到达后 `press_interact()` → 扣 Unit 与恢复 Hunger 全由 `ResourcePoint` 完成（AI 不碰 `units`/`survival`）。
- **D5 失败判据**：1 s 窗口内位移 < 0.05 m → 记失败（实测 `path_failures=4`）。
- **D6 重选与等待**：重选 3 次后进 `WAIT`（1 s）→ 回 `EXPLORE`（`G_recovers_after_wait` ✓）。
- **D7 警戒语义**：`alert_for()` → 停手停脚 + **取消交互**（`cancel_call_count` +1、units/hunger 不变）；不逃跑（属 T020）。
- **D8 状态值**：前 9 个值与 `TechnicalDesign` §1 一致，`WAIT` 追加为第 10 个。

## 5. 本任务踩到的坑（写进 `Docs/Commands.md` §2.15）

1. **AI 默认开着会让所有既有测试回退**：给 `mouse.tres` 加 `ai_script` 后，凡是生成鼠身体的测试（T010/T011/T012/T013b/T015/T017/T018）
   都被 AI 抢走 `move_intent` → **一次回归 57 条失败**（T010 17 / T011 4 / T012 5 / T013b 8 / T015 1 / T017 20 / T018 2）。
   修法：`AnimalBody.ai_enabled` **默认 false**，由生成 NPC 的一方显式打开（`_sync_ai()` 负责建/释放）。
2. **`NavigationAgent3D.navigation_layers` 是位掩码**：把层设成 `99` 仍**包含位 1**（鼠层）→ 依然可达，测不出"失败"。
   要用**与目标层没有交集**的值（如 `2`）。
3. **"没有路径"时必须清空 `move_intent`**：否则会残留上一帧的方向继续走，看起来像"不可达也能走通"（实测把 `WAIT` 路径整个掩盖了）。
4. **测试的 `until` 不能一开始就为真**：用 `state == forage` 当"已到达"会立刻命中（进入移动时就是 forage），
   要用 `state_reason() == "arrived"` 这种**只在真正到达时**成立的条件。
5. **"已锁定目标"与"选最近"是两件事**：一旦锁定就不应因出现更近的目标而抖动；测试要把两者分开断言
   （直接调 `find_food_target()` 验规则 + 验"不抖动" + 验"目标消失后切换"）。
6. `len` 之类的低级失误：改脚本时误删 `func can_jump()` 的签名行 → `check-only` 立刻抓到，按错误行号恢复即可（**别盲重试**）。
